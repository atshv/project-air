# P3-01 — Backend scaffold, PostgreSQL and local Compose

## Goal

`services/platform` and `services/auth` exist as Node/TypeScript ESM packages with configuration,
an HTTP skeleton, health endpoints and a migration runner; the Compose stack gains a pinned Kratos
service with its own database, and the slot setup creates the extra database and the restricted app
role.

**Why:** every backend task builds on this package layout, the configuration, the database
connection and the local service stack.

**Satisfies:** D9

## Scope

- New workspace packages `services/platform` (`@project-air/platform`) and `services/auth`
  (`@project-air/auth`), ESM TypeScript:
  - `package.json` scripts `build` (`tsc -p tsconfig.json`), `typecheck` (`tsc --noEmit`), `lint`
    (`eslint --max-warnings=0 .`), `test` (Node test runner), `start`; `tsconfig.json` extends
    `../../tsconfig.base.json`; no framework.
  - `src/config.ts` — parse environment once, fail fast on missing values: `DATABASE_URL`,
    `PORT`/`AUTH_PORT` from `.polier-slot`, auth secrets, `NODE_ENV`; never print secrets.
  - `src/http/` — a small `node:http` router (method + path, JSON body limit, `requestId`,
    error → JSON envelope), and a `GET /health` plus `GET /health/ready` (database ping) for both
    services; no business endpoints yet.
  - `src/db/pool.ts` (`pg` Pool) and `src/db/migrate.ts` (applies `infra/migrations/*.sql` in
    name order, records versions in `schema_migrations`, idempotent, fails on checksum change).
  - Tests with the Node test runner (`node --test`) covering the router, config validation and the
    migration runner against the slot database.
- Dependencies (owner-approved 2026-10-25): `pg` `8.23.1` (MIT) and `@types/pg` (dev) only; pin both
  in `docs/versions.md` with source URL, date and licence; `pnpm-lock.yaml` is updated by
  `pnpm install --frozen-lockfile` after `pnpm add` and committed.
- `infra/compose/compose.yaml`: add a pinned `kratos` service (image `oryd/kratos:v26.2.0`,
  Apache-2.0) with a health check and its own database `projectair_kratos` on the existing Postgres
  server; the full identity configuration arrives in P3-03. Keep the existing services untouched.
- `tools/dev/setup`: extend the per-slot bootstrap with the restricted `app_user` role (login, no
  `SUPERUSER`, no `BYPASSRLS`), the slot app database grants and the shared `projectair_kratos`
  database; `tools/dev/reset-db` resets the slot database and reruns migrations. Update the
  compose/README and `.env.example` names (names only, never values).
- `docs/versions.md` rows for `pg`, `@types/pg` and the Kratos image; `docs/gates/postgres.md`
  commands stay the source for `db-migrate`, `api-tests`, `rls-tests` (adjust it if a path differs).
- `.changes/P3-01-backend-scaffold.md` (area `platform`, kind `minor`).

## Specifications

- Node from `.nvmrc`/`engines` (>= 24.22.1); ESM only (`"type": "module"`); strict TypeScript.
- Tests run with `node --test test/*.mjs` and may import TypeScript sources directly (native type
  stripping in the pinned Node); no test framework.
- Compose is one shared stack per machine with fixed host ports outside the slot range; databases
  and the app role are per slot, the Kratos database is shared for local development only
  (documented limitation; tests do not depend on it).
- `DATABASE_URL` comes from `.polier-slot`/environment; migrations never create the database itself.
- Pin the Kratos image by tag and digest (`docker pull`, `docker inspect`), like the existing images.
- No secrets in the repo, logs or `.env.example` (names only); no `console.log` of connection
  strings.

## Pitfalls

- `board-check` scans `node_modules/`; run it before any `pnpm install` in the worktree.
- `pnpm add` changes the lockfile: install with `--frozen-lockfile` afterwards and commit the
  lockfile in this task.
- `/health/ready` must return 503 when the database is down, never a 200.
- The compose stack is shared by worktrees; do not stop or recreate services you did not start
  except through the documented compose commands, and never run destructive SQL against slot 0.

## Edge cases

- Missing environment variable → process exits 2 with a clear message, no stack trace with secrets.
- Database unreachable at start → readiness 503, health 200 for liveness.
- Migration runner on a database that already has all versions → no-op exit 0.
- `app_user` must not be able to bypass RLS (`rolbypassrls = false`, not superuser, not table owner).
