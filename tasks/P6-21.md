# P6-21 — Blocks on the web canvas with inline comfort (L18, L00 tools)

## Goal

Checklist, columns and table blocks can be created from the toolbar, are drawn with their content,
and are filled with the keyboard directly on the canvas (L18: `Enter` new entry, `Tab`/`Shift+Tab`
next/previous field, `Backspace` in an empty entry deletes it). Content is stored with
`updateBlockContent` through the one L05 save path; the block grows instead of scrolling. The
toolbar shows the demo's tool groups with correct icons and labels.

**Why:** owner decision 2026-10-29 (close the stage-7 gaps first). L18 is `open` because there is
no inline block creation in `apps/web`; the demo shows a checklist block and a spreadsheet card.

**Satisfies:** D12

## Scope

- `apps/web/` toolbar (L00): groups note │ zone, checklist, columns, table │ select, pan, each with
  its own ui-kit icon and messages label (fix the current reuse of the columns icon for connect and
  the select label for pan); tools without a feature yet (connect, image, pen) are not shown.
- `apps/web/` block creation by the L20 placement rule as one `createBlock` with empty content.
- `apps/web/` inline editing through the engine overlay (P4-23): the L18 key map, the 24 px colour
  field where the catalogue asks for it, focus handling; every committed edit is one
  `updateBlockContent` with its inverse (typing bursts grouped like the note editor), undo/redo per
  edit.
- Rendering: block content bound as text (checklist points with done state, columns with their
  items, table cells); block height follows the engine required height.
- Realtime: two clients editing different points of one block both keep their edit (P6-13 merge).
- Tests: pure tests for the key map and content edits; e2e: three points created with the keyboard
  only, an empty point deleted with `Backspace`, reload persistence, a second client sees the edit.
- `.changes/P6-21-<short-name>.md` (area `web`, kind `minor`).

## Out of scope

- Palette and timeline content, images, pen/ink, edges/connect, file and link tools (later stages).

## Acceptance

A1 WHEN a checklist block is created and three points are typed with the keyboard only, THEN they
are stored, survive a reload and an empty point is deleted with `Backspace` (the L18 acceptance).
A2 WHEN columns or table blocks are filled, THEN `Tab`/`Shift+Tab` move between fields, the block
grows with no inner scrollbar, and each edit is undoable.
A3 WHEN the task is done, THEN the toolbar shows only working tools with correct icons, and
`board-check`, `boundaries`, `unit`, `typecheck`, `design-check`, `language-check` and `e2e` exit 0
with records; the change entry exists.

## Specifications

- No second save path and no second inline input pattern (L18 "Do not").
- Item ids are UUIDv7 created on the client; order changes are content edits.
- A missing icon is an open question, never an invented one.

## Pitfalls

- Board shortcuts must not fire while an overlay field has focus (reuse the P6-05 guard).
- The overlay must follow pan and zoom; closing it on pan loses typing.
