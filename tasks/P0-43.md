# P0-43 — Live demo: pen tool and ink colours over the whole board

> Static design preview (`apps/web/preview/`). Owner note (2026-10-27): the live preview is not
> bound to the usual brief budgets.

## Goal

Owner request of 2026-10-28: the toolbar's colour icon and a freehand pen icon must work — "damit
kann man in verschiedenen farben auf leinwand und über alle zonen, notizen, fotos usw einzeichnen /
von hand schreiben".

1. **Pen tool.** A pen button (inline SVG line icon in ui-kit style, next to the palette button)
   enters drawing mode: a stroke follows the pointer as one smooth polyline, commits on pointerup and
   renders **above every board object** (zones, notes, photos, tables, checklists) in world
   coordinates, so it pans and zooms with the board. Drawing never moves/selects an object; Escape or
   another tool leaves the mode; the cursor is a crosshair.
2. **Ink colours.** The palette button opens a keyboard-operable popover with token swatches
   (`--tone-a` … `--tone-e` plus neutral `--fg`), the current one marked (`aria-pressed`). Choosing a
   colour applies it to the next stroke and the button's dot; strokes store the token name, so a
   theme switch recolours existing ink correctly. The popover closes on selection and Escape; labels in
   EN and DE; colour survives tool changes.
3. **History, status, locales, themes.** One stroke = one translated undo step (redo restores it);
   the status line reports pen/colour like the other tools; switching DE/EN or dark/light keeps
   strokes and colour.
4. **Docs and evidence.** README documents pen, colours and that ink is preview state (no data, cleared
   on reload); screenshots light/dark × EN/DE with writing over zone/note/photo and the open popover; a headless-Chrome log with strokes, colour change, undo/redo and theme switch.

**Why:** the owner wants to annotate over the board.

**Satisfies:** D3

## Specifications

- Ink is one SVG inside `[data-demo-world]` above the objects, `pointer-events: none` at rest; only
  pen mode captures drawing. No persistence, no network, cleared on reload.
- Stroke points are stored in **world coordinates** (inverse of the world transform at pointer time)
  so pan/zoom/theme/locale never move them; colour is a token name (`tone-a` … `tone-e`, `fg`)
  rendered as `stroke: var(--tone-x)`, never a raw colour.
- One history step per stroke with a translated label; existing history steps stay intact. All UI text
  from the locale files; toolbar buttons keep `aria-pressed`, names and focus ring; the popover uses
  token colours only.
- No raw colour/radius/spacing/shadow/motion outside token variables; no new dependency; no changed
  or deleted tests.

## Pitfalls

- World zoom is a CSS transform: convert pointer → world with the current rect/scale; test two zoom
  levels and after a pan.
- Ink must clip to the board surface, not overflow the page.
- `setupToolbar` currently only flips `aria-pressed`; add pen/palette behaviour without breaking the
  other buttons.
- A pointerup after tiny jitter is one stroke (or discarded); undo while the pen is active must not
  add a point.
- Light mode: all tones and the neutral stay visible on canvas and photos.
