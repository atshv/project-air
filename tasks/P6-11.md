# P6-10 — Canvas evidence, repo-wide checks and the web-app stage report

## Goal

Every remaining web canvas order (L00, L02, L04, L05, L06, L09, L12, L17, L18) has evidence
(screenshots and the e2e steps), design-check and language-check are green repo-wide (including the
demo/playground texts), a11y/touch basics are checked, and `docs/web-app.md` is the stage report with
exit-criteria status and open points; HANDOFF/STATUS updated.

**Why:** the stage exit criteria "every canvas work order done with evidence; design-check and
language-check green repo-wide" and the handoff to value/hardening.

**Satisfies:** D12

## Scope

- `reviews/evidence/` web canvas evidence: per **L00, L02, L04, L05, L06, L09, L12, L17, L18** one
  screenshot at 1440×900 and one at 390×844 where viewport-relevant (`P6-10-<entry>-<viewport>.png`),
  from a Playwright capture script (exclusive `e2e`) at a stable ready state, with a capture record
  (entry, viewport, commit, environment). Engine-owned parts cite the engine-core evidence.
- `docs/canvas-acceptance.md`: set the web-app entries (and the shared entries where the web part is
  now covered) to `fulfilled` with the evidence links, date and the responsible task; keep
  engine-only/hardening parts `open` where they genuinely remain (never mark a gap fulfilled).
- Repo-wide checks: run `design-check` and `language-check` on the whole repo and fix any remaining
  violation (playground/demo texts, preview, messages) in the smallest scoped change; run
  `board-check`, `boundaries`, `unit` as well. Record the gate evidence.
- A11y/touch basics: keyboard-only pass through login → boards → board → panel → save (documented
  steps + screenshot of focus), labels/roles audit of the new pages, focus-visible and contrast from
  tokens; tap-target sizes (36/28 px) noted, touch gestures (L15) stay in hardening with a note.
- `docs/web-app.md` stage report: architecture summary (SPA on SDK/engine/sync, SDK-owned CRDT
  document, cookie handshake, own editor, no paid-tier dependency), exit-criteria status, bundle
  size, limits, open points and the handoff to **value** (templates/library/search, import/export,
  AI, sharing) and **hardening** (M1, images, touch L15, a11y mirror, budget, real Kratos in CI,
  compaction/RLS, board bootstrap).
- Board bookkeeping: `board.stage` to 7, HANDOFF stage-7 block complete, STATUS generated;
  `.changes/P6-10-<short-name>.md` (area `web`, minor).

## Out of scope

- New product features, e2e-suite logic changes (P6-09), performance measurement (hardening), touch
  gestures (hardening), real Kratos in the automated gate (documented optional), templates/library/
  search (value), images (hardening).

A1 WHEN the evidence set is reviewed, THEN each web canvas order L00, L02, L04, L05, L06, L09, L12,
L17, L18 has a desktop and a mobile screenshot plus a capture record with the environment/commit, and
the orders that are engine-owned cite the engine evidence for the engine part.

## Specifications

- Deterministic evidence: seed from P6-09 fixtures, wait for ready + "Saved", record commit/env; no
  manual screenshots; capture under the exclusive `e2e` lock, artifacts ignored.
- Canvas status: `fulfilled` only when the catalogue acceptance is visibly proven; otherwise keep
  `open` with the exact remaining gap (e.g. touch part).
- Repo-wide design/language fixes stay minimal; never weaken the checkers or expected lists.
- A11y: real keyboard flow, role/name audit, visible focus, no colour-only signals; document gaps.
- Report in the engine-report style (numbers, remaining work, owner of each follow-up).
- Bookkeeping: `board.stage` to 7 and stage complete only with passing `e2e`, `design-check`,
  `language-check` records; render STATUS, update HANDOFF.

## Pitfalls

- Screenshots taken before fonts/engine first frame look broken; wait for the ready and saved states.
- A failed check must not be "fixed" by widening the expected-skip list — fix the violation.
- `language-check` scans the whole repo including docs/playground; historical evidence files with
  German demo text must not be edited as product code — scope the fix to source/messages.
- Canvas entries shared with engine-core (L02, L13, L18) need the engine evidence referenced, not a
  duplicate claim.
- Do not commit `test-results/`/`playwright-report/` or generated screenshots outside evidence.
- The board/stage bookkeeping must not mark stage 7 complete before all three exit gates have
  passing records.

## Gates

Run through `gate.py`; records under `reviews/evidence/`:

1. `board-check`: `python3 $POLIER/tools/check.py .` -> exit 0.
2. `boundaries`: `python3 $POLIER/tools/boundaries.py .` -> exit 0.
3. `unit`: `pnpm test --affected` -> exit 0.
4. `design-check`: `node tools/design-check/index.mjs .` -> exit 0.
5. `language-check`: `node tools/language-check/index.mjs .` -> exit 0.
6. `e2e`: `pnpm exec playwright test` (exclusive) -> exit 0.

## Limits

- **Scope:** `apps/web/`, `apps/web/messages/`, `docs/`, `.changes/`, `reviews/evidence/`.
- **Stop:** 2 rounds; blocked: `status: blocked` + reason.
