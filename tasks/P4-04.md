# P4-04 — Visual gate with reference images

## Goal

A dependency-free Node harness captures deterministic playground states at 1440×900 and 390×844,
compares them against committed reference images with a documented tolerance and writes a `visual`
gate record; `docs/gates/visual-diff.md` and `docs/quality.md` define the gate.

**Why:** the stage exit needs green reference images, and every drawing change in engine-core must
prove it did not regress the canvas.

**Satisfies:** D10

## Scope

- `packages/engine/test/visual/run-visual.mjs`: one Node script (builtins only) that
  - reads the web port from `.polier-slot`, copies the built playground, bridge, test-kit build and
    WASM into a temporary folder, starts and stops its own static server, launches Chrome for Testing
    with the same real-GPU flags and fail-closed renderer check as the perf harness;
  - emulates the viewports exactly through the DevTools protocol (1440×900 and 390×844, DPR 1),
    waits for the playground ready hook, pauses the render loop and captures the named scenes from
    `packages/test-kit` (sample board at rest, zoomed-in section, zoomed-out section, 10,000-object
    scene at rest);
  - decodes the PNG, compares it with the committed reference image, writes the diff PNG and JSON
    record on failure and reports differing pixels plus the worst channel delta;
  - supports `--update` to write baselines (an explicit review action, never a gate pass) and
    `--scene`/`--viewport` filters for local work.
- PNG encode/decode in Node: implement the minimum (zlib inflate/deflate from `node:zlib`, the five
  scanline filters, RGBA8) or decode in the browser; no new dependency.
- Reference images under `reviews/evidence/visual-baselines/`, named
  `<scene>-<viewport>-<backend>.png`; updates need a reviewer who saw both images.
- `docs/gates/visual-diff.md`: verify and refine the plan-committed `visual` section; mirror the
  viewport, scene and tolerance constants in the harness and commit the first baseline run and gate
  record.
- Deterministic camera states: prefer harness-driven input; if a pinned state is needed, a small
  read-only query hook (for example `?view=<name>`) in `apps/engine-playground/main.js` is allowed,
  documented in `docs/engine.md` and the gate log; never add a second camera path.
- `.changes/P4-04-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- WebGPU captures (P4-11 adds the backend switch), overlay scenes (P4-21), e2e or DOM assertions.
- Perf measurement (P4-03); real browser interaction tests.
- New dependencies (no Playwright, no pixel-match library).

## Acceptance

A1 WHEN the harness runs on a real-GPU browser, THEN it captures every named scene at both
viewports, compares against the committed baselines and exits 0 within tolerance; the JSON record
lists scene, viewport, backend, renderer and differing pixels.
A2 WHEN one pixel in a baseline changes, THEN the gate fails with a non-zero exit, writes a diff PNG
and names the scene and viewport; the failure is not swallowed as `infra`.
A3 WHEN the harness runs with `--update`, THEN it writes new baselines and reports that this was an
update, never a gate pass; the committed baselines are the ones the next gate compares against.
A4 WHEN the task is done, THEN `board-check` and `visual` exit 0 with records and
`docs/gates/visual-diff.md` matches the harness constants.

## Specifications

- Dependency-free: Node builtins, Chrome for Testing from the Playwright cache (`CHROME_PATH` wins),
  the DevTools protocol. Reuse the capture tool's pattern.
- Determinism first: fixed scenes from `packages/test-kit`, paused render loop, hidden or masked
  volatile HUD values, same Chrome version and flags, DPR 1, no animations.
- Tolerance defaults to 0 differing pixels. If antialiasing noise makes that impossible, document a
  per-channel delta and a pixel-count ratio in the gate and in `docs/gates/visual-diff.md`, and ask
  for review before committing the tolerance.
- Baselines are reviewed decisions, not a fix for a red gate. The harness never stops foreign
  processes, removes its temporary folder and records the Chrome binary and renderer string.
- If the sandbox refuses Chrome, record the exact error; never fabricate or reuse evidence.

## Pitfalls

- PNG decoding is the risky part; test with a known 2×2 image before wiring the diff. A wrong filter
  implementation silently compares garbage.
- Screenshots of a SwiftShader fallback look plausible but are not evidence; keep the fail-closed
  renderer check and classify software rendering as `infra`.
- A viewport mismatch (browser flags clamp window size) produces a false diff; set the metrics
  override through the DevTools protocol and assert the resulting screenshot size.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- No baseline for a scene: fail with the exact missing path; never auto-create unless `--update`.
- Scene not ready in time or Chrome not found: `infra` (exit 3), never a pass or a difference.
- Viewport smaller than the scene's fit: the scene must stay fully visible; choose the sample-board
  camera state accordingly.

## Gates

1. `board-check`: `python3 $POLIER/tools/check.py .` -> exit 0.
2. `visual`: `python3 $POLIER/tools/gate.py --task P4-04 --name visual --shell "node packages/engine/test/visual/run-visual.mjs"` -> exit 0, exclusive browser lock, JSON record written.
