# P6-22 — Demo-parity evidence, canvas status and the stage-7 close

## Goal

The web app's parity with the live demo is proven and documented: side-by-side screenshots of app
and demo for every shared behaviour, the e2e suite covers the new flows, `docs/canvas-acceptance.md`
moves L02, L03, L07, L08, L10, L14, L16, L18 and L20 to `fulfilled` where the web part is proven,
and `docs/web-app.md`, HANDOFF and STATUS state what remains, so the owner can close stage 7.

**Why:** owner decision 2026-10-29 (close the stage-7 gaps first): the stage exit criterion is
"every canvas work order done with evidence".

**Satisfies:** D12

## Scope

- `reviews/evidence/` captures: a Playwright capture script (exclusive `e2e`) for app vs demo at
  1440×900 and 390×844 — titles/previews at rest, drag with guides, zone dock preview, grouping
  ghost, emptied zone, zone name edit, checklist inline editing — with a capture record (commit,
  environment, entry).
- `docs/canvas-acceptance.md`: per entry the web status with evidence links; keep `open` with the
  exact gap where something is not proven (never an unproven `fulfilled`).
- `docs/web-app.md`: updated exit-criteria table, metrics (bundle, wasm size), a "Differences from
  the live demo" list (images, pen, edges/connect, light theme, palette/timeline) with the stage that
  owns each.
- HANDOFF stage-7 block and STATUS; `.changes/P6-22-<short-name>.md` (area `web`, minor).

## Out of scope

- New product behaviour (fix only what blocks evidence, in the smallest change, and record it);
  touch, images, performance budgets (hardening).

## Acceptance

A1 WHEN the evidence set is reviewed, THEN every shared behaviour has an app and a demo screenshot
at both viewports with a capture record, and differences are listed, not hidden.
A2 WHEN the repo-wide checks run, THEN `e2e`, `design-check`, `language-check`, `board-check` and
`boundaries` exit 0, and the catalogue reflects the real status per entry.
A3 WHEN the task is done, THEN `docs/web-app.md`, HANDOFF and STATUS are updated and the change
entry exists.
