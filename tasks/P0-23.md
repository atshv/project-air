# P0-23 — Visible connection anchors in the demo

## Goal

The live demo shows four visible connection anchors per note card (top, right, bottom, left side
midpoints); the connection edge snaps to the nearest anchor pair while cards are dragged.

**Why:** the owner wants to see where a card can connect and feel the edge snapping to those
points, not an invisible computed attachment.

**Satisfies:** D3

## Scope

- `apps/web/preview/`: add four anchor markers per demo card (positions: top/right/bottom/left
  midpoints, 6-px circles, decorative `aria-hidden`), rendered inside/at the card edge and moving
  with the card; style with tokens only (`--tone-d` for the anchors used by the edge, `--muted` or
  `--border-strong` for idle anchors; no raw colours, no new tokens).
- Change the edge computation from "nearest point on rectangle edge" to "nearest pair of the four
  anchors per card"; the edge connects the two chosen anchor centres; the chosen anchors are
  highlighted (`--tone-d`) while the edge uses them, others stay idle.
- Keep drag threshold, pointer capture, clamping, keyboard nudge (16 px), `Home` reset,
  `prefers-reduced-motion`, and the `--tone-d` 1.5-px edge style.
- Update `apps/web/preview/README.md`: four anchors per card, snapping rule, and the same-task
  update rule (demo + version meta line).
- Update the masthead meta line (P0-22 rule): `Last change: P0-23 — Visible connection anchors in
  the demo`.
- `.changes/P0-23-demo-anchors.md` (area `web`, kind `patch`, one English line).
- Refresh `reviews/evidence/P0-23-demo.png` (1440×900, anchors + edge visible); keep older demo
  screenshots untouched; manual log with serve/screenshot and the anchor-snap check.

## Out of scope

- Creating/removing connections by dragging from an anchor, multiple connections, corners or free
  edge points, engine or data.
- Changes outside `apps/web/preview/` and `.changes/`.

## Specifications

- **Anchor geometry:** derive from each card's rendered rectangle; anchors at `x = left + width/2`
  or `y = top + height/2`; keep them inside the card bounds (do not add page elements outside the
  demo surface).
- **Snap:** compute the distance between each of the 4×4 anchor pairs, pick the minimum, draw the
  line between the two anchor centres; no other attachment points.
- **Styling:** anchor diameter 6 px, `--tone-d` when used, idle `--muted` on a `--surface` ring or
  `--border-strong` outline; token-only.
- **Meta line:** update it in the same task (version from `CHANGELOG.md`, last change P0-23).
- **No JS dependencies, no build step; `preview.js` stays a plain module.**

## Pitfalls

- Do not let anchors change the card layout or capture pointer events meant for dragging.
- Do not regress the edge style (`--tone-d`, `--border-width-strong`) or the two-card/permanent
  demo rule.
- Do not forget the P0-22 meta line and the `.changes` entry.
- Keep findings deterministic and token-only; `design-check` must stay green.

## Edge cases

- Cards overlapping → anchors may coincide; pick the first minimal pair deterministically.
- Very small remaining distance → the line may be short; clamp to a minimum visible length.
- Keyboard movement updates anchors/edge exactly like pointer movement.
- Anchors must move with the card during drag without a one-frame lag (update in the same frame).
