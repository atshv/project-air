# P4-17 — Resize (L14)

## Goal

Selected objects show 8 px accent handles, resizing snaps to the 16 px grid (`Shift` free), the
per-type minimum sizes hold, and one gesture produces exactly one resize operation whose size survives
a reload/snapshot.

**Why:** L14 — sizes must be changed precisely, never below the type minima, and never with a second
write per gesture.

**Satisfies:** D10

## Scope

- `packages/engine/` resize interaction in the input/selection layer: when a selected object is
  selected, show eight 8 px `tokens::accent` handles (four corners + four edge midpoints) in the
  chrome pass (presentation-only, no command-buffer instances, no raw values); a press inside a
  handle starts a resize candidate (handle hit area 8 px screen px, cursors `nwse-resize`/
  `nesw-resize`/`ns-resize`/`ew-resize`); a press elsewhere keeps the existing click/drag/selection
  behaviour.
- `packages/engine/` resize gesture: from the press, compute the new size in world px from the
  pointer delta against the opposite edge/corner (that edge/corner stays anchored); snap the size to
  the `tokens::canvas_grid` 16 px grid unless `Shift`; clamp to the per-type minimum from the
  existing logic-layer minima (card 176×80, checklist 224×128, table 288×160, zone 256×192, columns
  368×192, timeline 320×160, palette 224×128) and for a zone to its member extent + `tokens::space_16`
  (P4-27); preview through the bridge geometry update without a document write; release commits
  exactly one `resize` gesture/operation with inverse through the P4-05 seam; `Escape`/`pointercancel`/
  lost capture restores the committed size with no operation.
- `packages/engine/` selection chrome: the 1 px `tokens::accent` frames stay; handles sit on the
  frame corners/edges and hide when the object is not selected or while it is dragged/resized
  elsewhere; handles follow the camera 1:1 and never scale with the object.
- `apps/engine-playground/`: resize demo on the sample and `?scene=layers` scenes (a selected card
  and zone, one gesture = one operation, `Shift` free, minimum clamp), a deterministic capture record
  + screenshots under `reviews/evidence/` (desktop 1440×900, mobile 390×844); every committed
  reference image stays 0-diff (handles appear only in selection state, the visual gate captures at
  rest).
- Tests: TypeScript suite for handle hit (8 px), corner/edge anchor math, 16 px snap and `Shift`
  free, per-type minimum clamp including the zone content minimum, one operation per gesture with
  exact inverse, cancel restore, snapshot round trip of the new size; `cpp-unit` regression.
  `.changes/P4-17-<short-name>.md` (area `engine`, kind `minor`); `docs/engine.md` documents the
  handles, anchor/snap rule, minima and the one-operation release.

## Out of scope

- Multi-object resize, aspect-ratio locking, auto-pan during resize (P4-18), arrangement changes for
  zones (P4-29 owns them), new visual baselines, contract/database changes, new dependencies,
  changed or deleted tests.

## Acceptance

A1 WHEN a handle of a selected object is dragged, THEN width and height are multiples of the 16 px
grid (free with `Shift`), the opposite edge/corner stays anchored, and the per-type minimum (plus the
zone content minimum) is never crossed.
A2 WHEN the resize is released, THEN exactly one `resize` operation with inverse is committed, the
size survives a snapshot round trip, and a cancelled resize restores the committed size without an
operation; unit tests cover each case.
A3 WHEN the task is done, THEN `board-check`, `boundaries` and `cpp-unit` exit 0 with records under
`reviews/evidence/`, the playground demonstrates the gesture with a capture record, and
`docs/engine.md` documents handles, anchor/snap rule, minima and the one-operation release.

## Specifications

- Values only from tokens: 8 px handle (`tokens::icon_card` is 16 px; the 8 px handle is the L14
  interaction value, documented as a named constant next to the existing 4 px/6 px/40 px
  interaction constants), `tokens::accent`, `tokens::canvas_grid` 16 px, `tokens::space_16` for the
  zone content inset; no raw colours.
- Snap and minima are computed in world px; the handle hit area is screen px (zoom-independent).
- One gesture = one operation (AD-1); no per-frame writes, preview is presentation only.
- The chrome pass never adds command-buffer instances; object counts and reference images stay
  unchanged.
- No new token, dependency or contract change; if a design value seems missing, record an open
  question instead of inventing a raw value.

## Pitfalls

- Anchoring the wrong edge makes the object jump on the first frame; test all four corners and edges.
- Snapping the anchor instead of the size moves the object; snap the resulting width/height and keep
  the anchor fixed.
- A zone minimum must consider its members (P4-27 helper), not only the 256×192 type minimum.
- Handles drawn in the object pass change instance counts and the visual gate; keep them in chrome.
- `Shift` free must still clamp at the minima; free does not mean unlimited.
