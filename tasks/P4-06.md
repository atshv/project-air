# P4-06 — Layers and draw order (L13)

## Goal

Drawing follows design rule §8: zones below blocks below note cards, the last moved object on top of
its layer, and the position stored through the contract's fractional `z`; Q15 is answered as clear
layers only and C++ tests plus a visual comparison confirm the order.

**Why:** overlaps must be predictable and stable before selection, dragging, resize and zones rely on
the draw order; L13 is the engine entry that fixes it. The fractional-z `reorder` operation is added
by P4-25 (contract 0.2.0), so this task depends on it.

**Satisfies:** D10

## Scope

- `packages/engine/` draw order: keep the documented layer order from `tokens.h` (`layer_zones`,
  `layer_blocks`, `layer_note_cards`) and the fractional `z` string as the within-layer key, then
  insertion order. Reserve the design-rule edge layer for later without drawing it. Make the
  "last moved or selected object on top of its layer" rule explicit in the document/render model:
  bringing an object to the front of its layer is exactly one contract `reorder` operation from
  P4-25 through the P4-05 seam, never a second write path.
- `apps/engine-playground/`: a deterministic overlapping demo state that shows a note card above a
  block and above a zone, a zone below its content, and one object brought to the front; a reload
  re-reads the stored `z` and shows the same order.
- Tests: extend the native suites — a note card always draws above blocks and zones regardless of
  `z`; within a layer, a greater `z` wins (lexicographic fractional key), equal `z` keeps insertion
  order; a front operation and its inverse restore the byte-identical command buffer; a reload from
  the stored state reproduces the order.
- `docs/engine.md`: correct the draw-order and layer-text if the implementation refines them.
- Visual evidence: a `visual` reference image for the overlapping scene, plus before/after images for
  the front/reload case under `reviews/evidence/`.
- `.changes/P4-06-<short-name>.md` (area `engine`, kind `minor`).

## Specifications

- Layers are design values: z-index numbers come only from `tokens.h` (AD-7), never from a local
  copy. The edge layer (3) is reserved and not drawn; chrome layers stay DOM (ADR-0009).
- "Last moved on top" means the object's `z` string moves ahead of its layer neighbours; it is stored
  through the contract operation, not as a separate front index.
- The visual comparison uses the P4-04 harness with a committed baseline; adding the scene is a
  reviewed baseline update, not an unreviewed overwrite.
- Q15 is binding: clear layers, no nudge; a collision nudge is out of scope until an owner decision.

## Pitfalls

- Sorting 50,000 objects per frame is not acceptable: reuse the precomputed draw-order permutation and
  invalidate it only on document change.
- A `z` string comparison must stay lexicographic on the contract's fractional index; parsing it as a
  float breaks beyond the precision range.
- Do not add a second "bring to front" path in the playground next to the operation seam.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- Equal `z` values: insertion order decides, and the order stays stable across reloads.
- Empty layer, all objects in one layer, and an object moved to the front of an empty layer.
- A reload with an outdated `z` (missing object) must not crash the playground.
