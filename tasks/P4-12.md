# P4-12 — WebGPU backend selection, capability and fallback

## Goal

The engine detects WebGPU adapter and device availability, selects the backend, falls back to WebGL2
without crashing when WebGPU is unavailable, exposes the active backend through the C ABI and the
bridge and reports the reason for a fallback. Unit tests cover the selection and fallback rules with
fakes.

**Why:** owner decision `Q19` — WebGL2 stays the measured default, WebGPU the second backend with a
fallback; P4-12 is the selection P4-13 switches and compares.

**Satisfies:** D10

## Scope

- `packages/engine/` capability probe: one module that asks the browser for
  `navigator.gpu.requestAdapter()` and `adapter.requestDevice()` with a bounded timeout, records the
  adapter identity (vendor/architecture/description), and returns a typed result
  (`webgpu` / `webgl2` / `fallback` with a reason). No crash and no leaked partial device when a step
  fails or is missing; the probe is injectable so native/Node tests can exercise every branch with
  fakes.
- `packages/engine/` selection and C ABI: a single entry point that takes a preferred backend
  (`auto` / `webgl2` / `webgpu`), runs the probe, creates the chosen renderer, and exposes
  `activeBackend()` plus `backendReason()` (a stable enum/string, never a raw exception) through the
  C ABI and the bridge. `auto` prefers WebGPU when the probe passes and falls back to WebGL2
  otherwise; an explicit `webgpu` request that fails falling back or failing cleanly must be defined
  and tested; the existing `engine_create`/WebGL2 default path keeps working byte-identically.
- `packages/engine/` bridge: `createEngine(canvas, options)` accepts `backend` and exposes the
  active backend and the fallback reason on the engine object; the HUD/playground switch is P4-13.
- `packages/engine/` native stubs for the probe/selection entry points (no browser API at compile
  time), keeping the native suites green; `wasm-smoke` covers the selection entry points and the
  "no WebGPU canvas" path.
- Tests: unit tests with injected fakes for every branch — `navigator.gpu` missing, adapter null,
  device request rejection, probe timeout, WebGPU renderer creation failure, explicit `webgpu`
  request with and without capability, `auto` preferring WebGPU and falling back; assert the
  reported reason, no crash, and that exactly one renderer is active. `.changes/P4-12-<short-name>.md`
  (area `engine`, kind `minor`); `docs/engine.md` documents capability detection, selection order,
  fallback rules and the reported reasons.

## Out of scope

- The playground `?backend=` switch, HUD backend naming and the two-backend visual comparison (P4-13);
  porting the glyph/chrome passes to WebGPU beyond what P4-11 built; changing the WebGL2 rendering;
  new dependencies; contract/database changes; changed or deleted tests.

## Acceptance

A1 WHEN WebGPU is available and `auto` or `webgpu` is requested, THEN the engine selects WebGPU and
reports it (with the adapter identity) through the C ABI and the bridge; WHEN it is unavailable or
fails, THEN the engine falls back to WebGL2 (or fails cleanly for an explicit request, as documented)
without crashing and reports the reason.
A2 WHEN the selection is exercised with fakes, THEN every branch (no `navigator.gpu`, no adapter,
device rejection, probe timeout, renderer creation failure, explicit vs auto) is covered by unit
tests, no partial renderer stays active and the WebGL2 path is unchanged.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `wasm-build`, `wasm-size`
and `typecheck` exit 0 with records under `reviews/evidence/`, the WASM stays within 300 KiB gzip,
and `docs/engine.md` documents detection, selection, fallback and reasons.

## Specifications

- Selection is one decision point: probe once per engine instance, create exactly one renderer,
  report one active backend and one reason string. No silent second attempt after a crash.
- Reasons are stable identifiers (for example `webgpu-unavailable`, `adapter-null`,
  `device-rejected`, `probe-timeout`, `renderer-create-failed`), never raw exception text; the
  bridge/HUD maps them, the playground naming is P4-13.
- Timeouts are bounded and short (a few hundred ms); a slow probe must not freeze the page.
- Native stubs keep the C++ suites and the wasm smoke green; no browser API at native compile time.
- No dependency; Emscripten 6.0.13/CMake 4.4.4 stay pinned; WASM stays within the size budget.

## Pitfalls

- A failed `requestDevice` after a successful adapter request must release the adapter/device
  resources and not leave a half-initialised renderer.
- `navigator.gpu` can exist with `requestAdapter()` returning null (no compatible adapter); both
  cases need distinct reasons.
- An explicit `webgpu` request that cannot be honoured must either fall back with a clearly reported
  reason or fail cleanly — never silently render WebGL2 while reporting WebGPU.
- Keep the WebGL2 default path byte-identical; its visual reference images are the regression proof.
- Adding the probe to the WASM/JS can change sizes; rerun `wasm-build`/`wasm-size`.
