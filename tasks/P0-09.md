# P0-09 — Pinned Polier for agents and CI

## Goal

Local sessions and CI use Polier at exactly the board's `generator_version` through
`tools/polier.sh`; the workflow uses the wrapper and every GitHub Action is pinned exactly and
recorded in `docs/versions.md`.

**Why:** gate records and guards must come from the same tool version everywhere; the CI workflow
(P0-08) still clones Polier inline and uses major-tag actions.

**Satisfies:** D2

## Scope

- `tools/polier.sh` (bash, executable):
  - `bash tools/polier.sh --check`: verify the checkout in `$POLIER` (required env var) is at the
    board's `generator_version` (read `board.json`), check `$POLIER/VERSION`, and when it is a git
    checkout also require the exact tag `v<version>`; print the version on success; on mismatch or
    missing checkout exit non-zero with a clear install hint. No network, no repo writes.
  - `bash tools/polier.sh --install [dir]`: clone/fetch the tag `v<version>` from
    `https://github.com/atshv/Polier.git` into `dir` (default `$HOME/.polier/<version>`), print the
    path; used by CI; never commits anything into this repository.
  - `bash tools/polier.sh --show`: print the resolved checkout and version.
- `.github/workflows/ci.yml`: replace the inline Polier clone with `tools/polier.sh --install
  "$RUNNER_TEMP/polier"`, then export `POLIER`; pin `actions/checkout`, `actions/setup-node` and
  `pnpm/action-setup` to exact versions or commit SHAs (not `@v4`); keep the step order and the
  board-check-before-install rule.
- `docs/versions.md`: one row per GitHub Action used (exact tag/SHA, source URL, date, approved by)
  so rule 1 holds; the local `rhysd/actionlint` Docker image is a local gate, not a workflow
  dependency (note it separately if useful).
- `AGENTS.md`: replace the "set `POLIER` to a checkout" line with `bash tools/polier.sh --check`
  after exporting `$POLIER`; keep the file at or below 400 words.

## Out of scope

- The real GitHub run (`ci-green`, remote), branch protection (P0-02), releases (P0-15/16/17).
- Changing Polier itself or committing a Polier checkout into this repository.

## Acceptance

A1 WHEN `bash tools/polier.sh --check` runs with `POLIER` pointing at the pinned v1.0.0 checkout,
THEN it exits 0 and prints the version; with a missing or mismatched checkout it exits non-zero with
a clear message.
A2 WHEN the workflow is read, THEN it obtains Polier through `tools/polier.sh --install` and every
`uses:` action is pinned exactly (no `@v4`/`@latest`); actionlint exits 0; every action appears in
`docs/versions.md` with source and date.
A3 WHEN the `polier-version`, `ci-local` and `board-check` gates run through `gate.py`, THEN all
exit 0 with committed records; `AGENTS.md` stays ≤ 400 words; `check.py` exits 0 (before any
`pnpm install`).

## Specifications

- **Version source:** `board.json` → `generator_version` (`1.0.0` today); tag `v<version>`; never
  hard-code a second version in the script or workflow.
- **Exact action pins:** use the current stable release tags or commit SHAs of
  `actions/checkout`, `actions/setup-node`, `pnpm/action-setup`; record the exact string in
  `docs/versions.md` with the upstream URL and date.
- **Local proof:** `POLIER` is set to the pinned checkout; the `polier-version` gate runs
  `bash tools/polier.sh --check`; the `ci-local` gate re-runs actionlint on the workflow.
- **No secrets, no network in `--check`, no host installs.**

## Pitfalls

- `--check` must work when the checkout is a detached tag or a branch; prefer
  `git describe --tags --exact-match` and fall back to `VERSION` only with a warning.
- Do not commit or copy the Polier checkout into this repository.
- Keep the workflow step order: board-check before install.
- Do not introduce `@latest` or floating tags for actions.
- `AGENTS.md` is close to its word limit; trim existing wording if needed.

## Edge cases

- `POLIER` unset → clear error naming the variable and `--install`.
- Checkout without `.git` (exported tarball) → compare `VERSION`, skip the tag check with a warning.
- A different tag of the same version → exit non-zero (exact tag required).
- CI has no cached Polier → `--install` clones the tag; local can reuse an existing checkout.

## Gates

1. `polier-version`: `bash tools/polier.sh --check` → exit 0, version equals `generator_version`.
2. `ci-local`: `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:latest` → exit 0.
3. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0 (before `pnpm install`).

## Limits

- **Scope:** only `tools/polier.sh`, `.github/workflows/ci.yml`, `docs/versions.md`, `AGENTS.md`;
  gate records under reviews/evidence are always allowed.
- **Stop:** 2 rounds; when blocked, `status: blocked` + reason.
