# P2-03 — WebGL2 renderer, TS bridge and engine playground

## Goal

The WASM build renders 50,000 rectangles via WebGL2 instanced draws in `apps/engine-playground`
behind the thin TypeScript bridge `createEngine(canvas, options)`, and the artifacts stay within the
300 KiB gzip budget.

**Why:** this is the visible spike artifact and the target of the performance gate; engine-core
later replaces the sketch with the full renderer.

**Satisfies:** D8

## Scope

- `packages/engine/` C++ renderer (`render_gl`):
  - one static quad, per-instance attributes (screen-space rect + tone colour) from the P2-02
    command buffer; one instanced `drawArraysInstanced` per frame;
  - vertex/fragment shaders as C++ string literals, no external shader files;
  - resize and device-pixel-ratio handling, canvas clear with the token colour;
  - small `EMSCRIPTEN_KEEPALIVE` C API: `engine_create`, `engine_resize`, `engine_set_camera`,
    `engine_load_rectangles`, `engine_render_frame`, `engine_last_error`.
- TypeScript bridge `packages/engine/src/bridge/engine.ts` (package `@project-air/engine`):
  `createEngine(canvas, options)` returns a typed handle (load rectangles, set camera, render);
  `package.json` scripts `build`/`typecheck`/`lint`, `tsconfig.json` extends the root base; no new
  dependencies (root TypeScript/ESLint only).
- `apps/engine-playground/`: static page loading the built bridge + Emscripten `engine.js` with a
  deterministic 50,000-rectangle demo, an fps counter and a "spike — not the engine" label; no
  external fonts/CDNs/images; visual values from `packages/ui-kit/tokens.css` (`var(--…)`); served
  over HTTP (WASM cannot load from `file://`).
- Size tool `packages/engine/tools/wasm-size.mjs` (Node builtins): gzip size of
  `build-wasm/engine.wasm` must be ≤ 307200 bytes (300 KiB), exit 0 with the size printed.
- `.changes/P2-03-webgl2-playground.md` (area `engine`, kind `minor`).
- Evidence: a playground screenshot (1440×900) and a serve/curl log; the stage showcase is P2-05.

caption, an fps counter. English UI text only; design tokens only.

## Pitfalls

- WASM and the Emscripten `.js` loader must be served over HTTP with the correct MIME types; a
  `file://` check will fail by design.
- Headless Chromium may render WebGL with SwiftShader; screenshots for P2-03 are allowed that way,
  but perf numbers belong to P2-04 on the recorded hardware.
- Do not add a bundler or framework; the bridge is compiled with `tsc`, the page uses ES modules.
- `design-check` rejects raw colours, off-grid spacing and unknown numeric z-index.
- `board-check` before any `pnpm` command.
- Keep `engine.wasm` under budget: no debug symbols, `-O3`, `--closure 1` only if verified, and
  check the size gate after every change.

## Edge cases

- Canvas resize and device-pixel-ratio changes during the demo.
- 0 and 50,000 rectangles; reload starts the demo cleanly.
- Missing WASM file → a short error line, no unhandled rejection.
- Bridge called before the WASM runtime is ready → clear error, never a silent no-op.

## Gates

1. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0 (before any install).
2. `boundaries`: `python3 $POLIER/tools/boundaries.py .` → exit 0.
3. `cpp-unit`: `ctest --test-dir packages/engine/build --output-on-failure` → exit 0.
4. `wasm-build`: `emcmake cmake -S packages/engine -B packages/engine/build-wasm
   -DCMAKE_BUILD_TYPE=Release && cmake --build packages/engine/build-wasm --parallel` → exit 0.
5. `wasm-size`: `node packages/engine/tools/wasm-size.mjs` → exit 0, gzip ≤ 307200 bytes.
6. `design-check`: `node tools/design-check/index.mjs .` → exit 0.
