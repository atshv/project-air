# P4-01 — Engine document: stable ids, incremental mutations, hit testing and spatial queries

## Goal

The engine document keeps contract board objects with stable ids, applies add/move/resize/remove
mutations without reloading the whole document, and answers hit tests and visible-bounds queries in
layer and `z` order; native C++ tests cover ordering, mutation and rejection cases.

**Why:** every gesture, overlay and measurement in engine-core needs one mutable working copy with
object identity and hit testing (AD-1, AD-2). The spike can only load rectangles wholesale, so the
first engine-core task provides the document API the later tasks build on.

**Satisfies:** D10

## Scope

- `packages/engine/` C++ core:
  - `doc`: stable `ObjectId` (monotonically assigned, never reused) per object, a live/removed flag,
    and incremental `addObject`, `updateGeometry`, `updateZ`, `removeObject` mutations that keep
    capacity reserved and increment the version; the draw-order permutation and its inverse stay
    valid across mutations.
  - `spatial`: point and bounds queries that return candidates in document order without allocating
    per query; the index still rebuilds only on version change and stays bound to document identity.
  - hit testing on the command-buffer level: given a screen point, return the topmost live object in
    draw order, or the empty result; reject non-finite points and a zero-size viewport.
  - C ABI additions for add, update geometry, update `z`, remove, hit test (returns index or -1) and
    the visible instance count; the existing `loadRectangles` stays for compatibility.
- TypeScript bridge `packages/engine/src/bridge/engine.ts`: typed methods for the new calls, keeping
  the existing `createEngine(canvas, options)` handle and error mapping.
- `docs/engine.md`: document the object identity, the mutation API and the new C exports.
- Tests: identity stability, mutation/version/draw-order correctness, hit-test precedence with equal
  `z`, removal, capacity and non-finite rejection, and a byte-identical command buffer after a move
  plus its inverse; keep the existing 2 suites green.
- `.changes/P4-01-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Gestures, pointer input, selection state, snapping, resize handles, text, DOM overlays.
- Renderer or command-buffer layout changes beyond what mutation needs; WebGPU; contract schema
  changes; playground UI (P4-02); new dependencies or changed tests.

## Acceptance

A1 WHEN a hit test runs at a point covered by several objects, THEN it returns the topmost object of
the highest layer, then greatest `z`, then latest insertion order, and a point without objects
returns the empty result; native tests cover this.
A2 WHEN objects are added, moved, resized, re-`z`ed and removed, THEN draw order, version, spatial
index and command buffer follow without a reload, and applying a mutation plus its inverse restores
a byte-identical command buffer; native tests cover this.
A3 WHEN one object is removed, THEN every other object keeps its id, geometry and draw-order rank;
ids are never reused, and non-finite geometry or a full document is rejected with a `Status` that
leaves the document unchanged.
A4 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `wasm-build`, `wasm-size`
and `typecheck` exit 0 with records committed, and `docs/engine.md` matches the code.

## Specifications

- The 24-byte instance layout and the deterministic draw order are load-bearing (ADR-0006): keep
  both; a changed layout needs an ADR and every dependant in the same task.
- Identity lives in the engine and is independent of contract UUID strings; the bridge owns the
  contract-id mapping and may expose it later. Never hash or parse contract ids inside the C++ core.
- Mutations validate like the existing camera and document APIs: non-finite input, overflow and
  unknown ids return a `Status` and leave state untouched; never throw across the C ABI.
- Removed slots may be reused by later inserts, ids never are; draw order depends only on layer,
  `z` and insertion order.
- Keep the native suite fast (< 2 s); the WASM build must stay inside the size budget.

## Pitfalls

- Rebuilding the whole spatial index per mutation is O(n); measure before choosing, and never
  rebuild on camera moves (the camera does not change the document).
- `drawOrderRank` is reused by the renderer; stale caches after removal produce ghost draws.
- No per-object JS calls or JS-side hit testing: one call per query.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- Empty document: hit test returns empty, instance count 0, no division by zero.
- Hit test exactly on an edge or corner: one deterministic rule, tested.
- Removing the last object keeps the document usable and the reserved capacity.
