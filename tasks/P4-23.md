# P4-23 — DOM overlay for field editing and inline comfort (L18)

## Goal

An overlay host positions DOM field editing over the canvas from the camera transform, routes focus
and pointer events into fields without starting a drag, and implements the inline comfort rules —
`Enter` creates the next entry below with focus, `Tab`/`Shift+Tab` move to the next/previous field,
`Backspace` in an empty entry deletes it and focuses the previous — for list, column and table
entries; the colour control is a 24 px field. The playground demonstrates it with plain fields until
`packages/editor` lands; none of it is a second save path.

**Why:** L18 and blueprint P4-08: the canvas needs a field layer before the web app can reuse it, and
inline editing must never fight the drag policy of L03.

**Satisfies:** D10

## Scope

- `packages/engine/` overlay host under `src/bridge/` (for example `overlay.ts`): a DOM layer above
  the canvas anchoring registered fields to a world rectangle through the camera (pan, zoom, DPR),
  keeping them 1:1 while the camera changes, hiding fields whose object leaves the viewport and
  staying transparent outside its fields. It owns focus management (open, close, next/previous,
  restore); fields stop pointer propagation so the P4-14 input layer never drags from them, and
  scrollable fields keep their wheel handling.
- `packages/engine/` inline keyboard policy as a pure function over a field list and a key event:
  `Enter` inserts a new entry directly below the focused one and focuses it, `Tab`/`Shift+Tab` move
  focus to the next/previous field with the documented wrap/clamp rule, `Backspace` in an empty entry
  removes it and focuses the previous, every other key stays with the field. The policy emits intents
  only — it never persists content (L05's single autosave is out of scope).
- `packages/engine/` colour field: a 24 px token-sized colour control replacing an oversized native
  colour button, keyboard-reachable.
- `apps/engine-playground/`: an inline-editing demo (for example `?edit=inline`) with checklist,
  column and table entries as plain DOM fields anchored over the layers scene; keyboard-only
  creation, tabbing and `Backspace` work in memory; a deterministic capture record under
  `reviews/evidence/` proves anchored fields and the focused entry. No board content is written.
- Tests: TypeScript suite for anchor math (world→screen at pan/zoom/DPR, off-screen hide), focus
  order/wrap, `Enter`/`Tab`/`Shift+Tab`/`Backspace` outcomes, empty vs non-empty `Backspace`, pointer
  events not reaching the drag layer, the 24 px colour field and that the policy writes nothing.
  `cpp-unit` regression; `.changes/P4-23-<short-name>.md` (area `engine`, kind `minor`);
  `docs/engine.md` documents the overlay host, anchoring and routing.

## Out of scope

- Rich text, the note editor, real persistence or autosave (L05, `packages/editor`), the side panel,
  the web app's translation setup, new tokens, new dependencies, contract changes, changed or
  deleted tests, new visual baselines.

## Acceptance

A1 WHEN a field is open and the camera pans or zooms, THEN the field stays anchored to its world
rectangle through the camera transform, hides when its object leaves the viewport, and focusing or
clicking a field starts no drag; unit tests cover anchor math, hide and drag suppression.
A2 WHEN `Enter`, `Tab`, `Shift+Tab` or `Backspace` is pressed in an inline entry, THEN a new entry is
created below and focused, focus moves to the next/previous field, and `Backspace` in an empty entry
deletes it and focuses the previous; the colour field is 24 px; unit tests cover each case and prove
the policy writes nothing.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `unit` and `design-check`
exit 0 with records under `reviews/evidence/`, the playground demonstrates keyboard-only inline
editing with anchored plain fields, and `docs/engine.md` documents the overlay host and routing.

## Specifications

- Values only from tokens: 24 px colour field, 40 px header, 120/180 ms transitions, 4 px series
  spacing; no raw values (design-check).
- The overlay is presentation and input only: no board content, operation payload, document state or
  second save path.
- Fields never start a drag and keep their wheel handling; `Esc` closes only the editing field.
- Anchoring is world px through the camera; a stale camera or disposed engine closes the overlay.
- No new dependency; DOM APIs only (no framework).

## Pitfalls

- Rebuilding the overlay per frame loses focus; reposition existing nodes only.
- A field swallowing `Tab` breaks keyboard exit; follow the wrap/clamp rule and test both ends.
- `Backspace` in a non-empty entry must not delete it — only an empty entry is removed.
- The visual gate captures no overlay: keep the demo off the default scene and add no baseline.
- Rebuild bridge and WASM before the capture; run `board-check` before any `pnpm` command.
