# P4-29 — Zone parity with the live demo I: arrangement and release preview (L08)

> Owner decision (2026-10-27): "The engine must work the way the live demo shows it." Reference:
> `apps/web/preview/` (README "Zone interaction"/"Zone name", `preview.js` zone section), read-only;
> the engine port is `packages/engine/`, the demo code is never imported.

## Goal

Zone members are auto-arranged stacked or side by side like the live demo (sizes + 16 px padding +
12 px gap below the 40 px header; orientation from size-normalised offsets with 1.25 dominance and a
half-item hold; order from the centre with a 12 px band). A drag shows the release preview — dashed
landing slot, the other member making room, the frame shrinking around the member that stays
(ghost/emptying frames are P4-30) — entering at pointer over the frame or 25 % coverage, staying
with a 24 px catch margin, placement against drag-start positions, one committed operation per
release, and a calm 300 ms `cubic-bezier(0.2, 0, 0, 1)` settle without overshoot (instant under
reduced motion).

**Why:** the demo must behave like the design preview, not a second implementation.

**Satisfies:** D10

## Scope

- `packages/engine/` arrangement core (pure, native-testable): member layout from sizes with
  `tokens::space_16`/`space_12` below the `tokens::header_height` band; orientation, dominance, hold
  and 12 px order band; an arrangement that does not fit falls back to the other orientation without
  changing the stored request. The release writes the arranged positions as one operation.
- `packages/engine/` preview state machine: from drag-start positions compute dock / reorder /
  orientation change / detach / free; show the landing slot, the other member glides aside, the
  frame shrinks around the staying member; 25 % enter and 24 px catch hysteresis; nothing commits
  before release; `Escape`, `pointercancel` and lost capture restore the committed layout.
- `packages/engine/` one release = one operation with inverse: dock, reorder, orientation change and
  detach commit exactly once (no per-member write); positions are world px, snapped to the 16 px grid
  where the live demo snaps them; a fallback orientation never changes the stored request.
- `packages/engine/` motion: 1:1 drag with the existing lift (scale 1 → 1.02, stronger shadow, top of
  its layer); 300 ms `cubic-bezier(0.2, 0, 0, 1)` settles, no overshoot; FLIP-style frame resize so
  the layout never stretches; reduced motion applies end states instantly.
- `apps/engine-playground/`: zone-parity demo on the layers scene (arrangement, landing slot,
  room-making, shrink-on-out, one-operation release), deterministic capture record and side-by-side
  screenshots against the live demo under `reviews/evidence/` at 1440×900 and 390×844.
- `packages/engine/test/visual/run-visual.mjs` + `docs/gates/visual-diff.md`: a deterministic
  zone-parity scene with reviewed baselines; the reference set and Baseline history are extended in
  this task and every existing image stays 0-diff.
- Tests: dominance/hold, order band, fit fallback, enter/stay hysteresis, shrink-on-out, one
  operation per release with exact inverse, cancel restore, reduced motion.
  `.changes/P4-29-<short-name>.md` (area `engine`, kind `minor`); `docs/engine.md` documents
  arrangement, preview states, thresholds and motion; `docs/adr/ADR-0010-zone-containers.md` records
  the approved auto-arranged-members amendment.

## Specifications

- Values only from tokens: 16 px padding, 12 px gap, 40 px header, 300 ms settle, 1.25 dominance,
  25 % coverage, 24 px catch margin, 12 px order band; no raw values (design-check).
- One gesture = one operation (AD-1); previews are presentation state and never write the document.
- Positions are world px; thresholds are screen px converted with the camera zoom.
- The stored request never changes because of a viewport fallback.
- `visual` is exclusive: never run it next to another browser gate.

## Pitfalls

- An orientation change without the position write leaves a half-arranged zone; the release carries
  the arranged positions.
- A preview that commits early makes the cancel path lie; test the byte-identical snapshot.
- Resizing `width`/`height` stretches the header; keep the FLIP scale.
- New baselines only through the reviewed `--update` path.
