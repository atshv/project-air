# P1-07 — Contract overview in the preview

> **Size:** target 500–800 words. UI task: numbers in the UI specification are binding.

## Goal

The permanent design preview gets a **Contract overview** section that shows the shared language
visibly: contract version `0.1.0`, the schema families and files, the operation vocabulary, the
sync message types, the API error codes and the fixture/codegen proof. The existing live two-note
demo stays at the top and keeps working.

**Why:** the owner wants a visible intermediate state during the contract stage (demo cadence,
`docs/quality.md`), and every later stage (engine, backend, realtime) relies on this contract.

**Satisfies:** D3

## Scope

- `apps/web/preview/index.html` — new section **“Contract 0.1.0 — the shared language”** directly
  after the interactive demo surface, before the colour section, plus the refreshed masthead
  meta line. Static markup is allowed; no build step, no fetch, no framework.
  Content (all values read from `packages/contracts/` in this task, never guessed):
  - contract version `0.1.0`; `$id` base `https://project-air.dev/contracts/0.1.0/` (placeholder
    until Q1); logical release, git tag only in the remote phase (ADR-0002/ADR-0003);
  - schema families table: board-content (10 schema files), sync protocol (client→server and
    server→client message lists + counts), API resources/error codes (resource envelopes and the
    seven fixed codes) — each with path (`schemas/…`) and fixture corpus (`fixtures/`,
    `fixtures-sync/`, `fixtures-api/`, `fixtures-gate/`);
  - the 19 operation types of `schemas/operation.schema.json` as a visible token/word list, with
    the one-inverse rule (AD-1);
  - fixture proof: 77 parity fixtures (32 valid / 45 invalid) read identically by TS and C++,
    generated `generated/types.ts` and `generated/contract.h`, the `codegen` rule, and why
    `fixtures-gate/` holds the two Polier gate specimens;
  - one short line stating the cadence rule: the section is updated in the same task as every
    contract or preview change; links to `docs/contracts.md` and
    `docs/adr/ADR-0005-contract.md` (relative paths, plain text links).
- `apps/web/preview/index.html` masthead meta line (`data-preview-*`): keep
  `Version 0.0.1`/`unreleased` from `CHANGELOG.md`; set last change to
  `P1-07 — Contract overview in the preview` and the date/time to the modification time of
  `.changes/P1-07-contract-overview.md` (format `YYYY-MM-DD HH:MM (Europe/Zurich)`). Write the
  change entry first, then stamp its mtime.
- `apps/web/preview/preview.css` — styles for the section, tokens only (`var(--…)`), no raw
  colours, no off-grid spacing, no new tokens, no new z-index values.
- `apps/web/preview/README.md` — document the section, the cadence rule and the new screenshots.
- `.changes/P1-07-contract-overview.md` (area `contracts`, kind `minor`) — required code change
  entry; it is also the masthead “last change” source.
- Screenshots + log in `reviews/evidence/` (see UI evidence below). The existing demo stays
  unchanged; the refreshed screenshots show the new masthead.

## UI specification

The preview is a documentation page; the section follows the existing documentation blocks
(bordered surfaces, calm typography, no accent fill).

| Element | Property | Value | Token |
| --- | --- | --- | --- |
| Section surface | background | card/surface colour | `var(--surface)` or `var(--card)` |
| Section block | border | 1 px resting border | `var(--border-width)`, `var(--border)` |
| Section block | radius | medium radius | `var(--radius-md)` |
| Section block | padding | 24 px | `var(--space-24)` |
| Between blocks | gap | 16 px | `var(--space-16)` |
| Section heading | size | 22 px | `var(--text-22)` |
| Body text | size | 13 px / 15 px | `var(--text-13)`, `var(--text-15)` |
| Table labels | size, tracking | 11 px, label tracking | `var(--text-11)`, `var(--tracking-label)` |
| Table row divider | border | 1 px | `var(--border-width)`, `var(--border)` |
| Code/path text | font | mono stack? | reuse existing token only; otherwise use `var(--font-sans)` |
| Chips (operations) | radius, padding | pill, 4×8 px | `var(--radius-pill)`, `var(--space-4)`, `var(--space-8)` |

**States:** the section is static documentation — hover/focus/pressed/disabled are `n/a`; links
use the existing preview link style with a visible focus outline.

**Do not:** add raw colours or `rgb()`/`hsl()`; add tokens; use spacing outside 4/8/12/16/24/32/48;
animate; add images, icon files, external fonts or CDNs; use German text; break the demo; change
existing sections beyond the masthead meta line.

**UI evidence:** serve the repository root on the slot's web port from `.polier-slot` (read it,
never hard-code), capture `reviews/evidence/P1-07-desktop.png` (1440×900, top with masthead and
demo), `reviews/evidence/P1-07-mobile.png` (390×844, top) and
`reviews/evidence/P1-07-contract.png` (contract section at 1440 width, window tall enough) with
the local Chromium headless shell; write `reviews/evidence/P1-07-preview.log` with the exact
serve/curl/screenshot commands, the HTTP status and the screenshot sizes. Only start and stop the
server yourself.

## Pitfalls

- `board-check` scans `node_modules/`; run it before any `pnpm` command (the preview needs no
  install).
- `design-check` rejects raw colours, off-grid spacing and unknown numeric z-index; the section
  must use `var(--…)` only.
- The changelog entry decides the masthead “last change”; write it before stamping the time.
- Counts must match the contract exactly: 19 operation types, 77 parity fixtures (32/45), 7 error
  codes, and the actual message/resource counts from the schemas. Prefer a short data object over
  duplicated strings.
- No fetch/build: the page is served as static files and must also render from `file://`.
- Do not edit `CHANGELOG.md`, `STATUS.md` or `board.json`.
