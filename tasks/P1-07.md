# P1-07 — Contract overview in the preview

> **Size:** target 500–800 words. UI task: numbers in the UI specification are binding.

## Goal

The preview gets a **Contract overview** section: version `0.1.0`, schema families and files,
operation vocabulary, sync message types, API error codes and the fixture/codegen proof; the
two-note demo stays at the top.

**Why:** the owner wants a visible intermediate state during the contract stage (demo cadence,
`docs/quality.md`).

**Satisfies:** D3

## Scope

- `apps/web/preview/index.html` — new section **“Contract 0.1.0 — the shared language”** after the
  demo surface, before the colour section, plus the refreshed masthead. Static markup only: no
  build step, fetch or framework. All values read from `packages/contracts/` in this task:
  - version `0.1.0`, `$id` base `https://project-air.dev/contracts/0.1.0/` (placeholder until Q1),
    logical release with the git tag deferred to the remote phase (ADR-0002/ADR-0003);
  - schema families with paths and fixture corpora: board-content (10 files, `fixtures/`), sync
    (`schemas/sync/`, `fixtures-sync/`), API (`schemas/api/`, `fixtures-api/`), plus why
    `fixtures-gate/` exists;
  - the 19 operation types with the one-inverse rule (AD-1), the 6+6 sync message types and the
    seven fixed error codes with their `errors.<camelCase>` message keys;
  - fixture proof: 77 parity fixtures (32 valid / 45 invalid) read identically by TS and C++,
    `generated/types.ts` + `generated/contract.h`, the `codegen` rule;
  - the cadence line; links to `docs/contracts.md` and the contract ADR.
- `apps/web/preview/index.html` masthead (`data-preview-*`): version stays `0.0.1`/`unreleased`
  from `CHANGELOG.md`; last change becomes `P1-07 — Contract overview in the preview`, date/time =
  modification time of the change entry (`YYYY-MM-DD HH:MM (Europe/Zurich)`). Write the entry
  first, then stamp its mtime.
- `apps/web/preview/preview.css` — section styles, tokens only (`var(--…)`); no raw colours, no
  off-grid spacing, no new tokens or z-index values.
- `apps/web/preview/README.md` — section, cadence rule, screenshots.
- `.changes/P1-07-contract-overview.md` (area `contracts`, kind `minor`) — required code-change
  entry and masthead “last change” source.
- Screenshots and log under `reviews/evidence/` (see UI evidence). The demo stays unchanged; the
  refreshed screenshots show the new masthead.

## Out of scope

- Changing `packages/contracts/`, demo behaviour, extra pages, live data, a build step, new
  dependencies, German UI text.

## UI specification

Documentation section in the existing preview block style (bordered surfaces, calm typography,
no accent fill).

| Element | Property | Value | Token |
| --- | --- | --- | --- |
| Section block | background | card/surface colour | `var(--surface)` or `var(--card)` |
| Section block | border, radius | 1 px, medium | `var(--border-width)`, `var(--border)`, `var(--radius-md)` |
| Section block | padding | 24 px | `var(--space-24)` |
| Between blocks | gap | 16 px | `var(--space-16)` |
| Section heading | size | 22 px | `var(--text-22)` |
| Body text | size | 15 px / 13 px | `var(--text-15)`, `var(--text-13)` |
| Table labels | size, tracking | 11 px, label tracking | `var(--text-11)`, `var(--tracking-label)` |
| Chips (operations) | radius, padding | pill, 4×8 px | `var(--radius-pill)`, `var(--space-4)`, `var(--space-8)` |

**States:** static documentation — hover/focus/pressed/disabled `n/a`; links keep the preview link
style with a visible focus outline.

**Do not:** raw colours or `rgb()`/`hsl()`; new tokens; spacing outside 4/8/12/16/24/32/48;
animation; images, icon files, external fonts or CDNs; German text; breaking the demo.

**UI evidence:** serve the repo root on the slot's web port from `.polier-slot` (never hard-code
it); capture `reviews/evidence/P1-07-desktop.png` (1440×900, top), `P1-07-mobile.png` (390×844,
top) and `P1-07-contract.png` (contract section, 1440 wide) with the local Chromium headless
shell; write `P1-07-preview.log` with the exact serve/curl/screenshot commands, HTTP status and
screenshot sizes. Start and stop only your own server.

## Pitfalls

- `board-check` scans `node_modules/`; run it before any `pnpm` command (the preview needs no
  install).
- `design-check` rejects raw colours, off-grid spacing and unknown numeric z-index.
- The change entry decides the masthead “last change”; write it before the stamp.
- Counts must match exactly: 19 operation types, 77 parity fixtures (32/45), 7 error codes and the
  real message/resource counts. Prefer one short data object over duplicated text.
- No fetch/build: static files must also render from `file://`.
- Do not edit `CHANGELOG.md`, `STATUS.md` or `board.json`.

2. `design-check`: `node tools/design-check/index.mjs .` → exit 0.
