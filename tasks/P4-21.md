# P4-21 — Undo/redo (L11)

## Goal

The P4-05 session history of 20 `{do, undo}` operations backs `Cmd/Ctrl+Z` and `Shift+Cmd/Ctrl+Z`,
shows an "Undo: …" hint for 3 s at the bottom centre, never consumes shortcuts inside a field and
issues exactly one counter-operation per undo.

**Why:** L11 — a wrong move must be undoable, one press exactly one step, and the hint must use the
design rule §9 bottom-centre slot.

**Satisfies:** D10

## Scope

- `packages/engine/` keyboard wiring for the existing history (P4-05): `Cmd/Ctrl+Z` calls
  `history.undo()`, `Shift+Cmd/Ctrl+Z` calls `history.redo()`; each call applies exactly one stored
  inverse/operation through the document port and seam (never a second write path), redo is cleared
  by a new operation (history behaviour), the depth stays 20, and a fresh session starts empty. The
  key handler yields when a field/editable element has focus (the browser's own undo wins) and when
  another overlay consumed the key.
- `packages/engine/` hint as DOM chrome (ADR-0009): after a successful undo, show the history label
  ("Undo: …", playground demo-text convention; product text later from translation files) in the
  design rule §9 bottom-centre slot for 3 s, `tokens::muted`/panel styling, no layout shift, no
  toast queue; no hint when the history is empty or for redo unless documented.
- `apps/engine-playground/`: demo on the layers scene (move, delete, undo, redo; a 20-step series; a
  field focused so the shortcut is left to the field), deterministic capture record + screenshots
  under `reviews/evidence/` (desktop 1440×900, mobile 390×844); no reference image changes.
- Tests: integration tests with the real history/port seam (one inverse per undo, redo re-applies,
  new operation clears redo, depth 20, empty history no-op), key-routing tests (field focus leaves
  `Cmd/Ctrl+Z` alone; `Shift` variant; other overlays' priority), hint timing (3 s, bottom centre,
  label), `cpp-unit` regression. `.changes/P4-21-<short-name>.md` (area `engine`, kind `minor`);
  `docs/engine.md` documents the shortcut map, field rule, one-counter-operation guarantee and the
  hint slot.

## Specifications

- One undo = exactly one stored inverse; one redo = exactly one stored operation; never a second
  counter-request and never a direct document write (AD-1).
- Field focus wins: the browser's own undo/redo is untouched inside `input`/`textarea`/`select`/
  `[contenteditable]`/`[data-field]`.
- Hint: bottom centre per design rule §9, 3 s, `tokens::muted`; no layout shift, no animation on the
  page content, reduced motion still shows/hides without motion.
- The history is per session (not persisted); the hint reads `describe()`; labels stay in code until
  the translation files own product UI text.
- No new token, dependency or contract change; a missing value becomes an open question.

## Pitfalls

- Applying the inverse and pushing it back onto the stack creates a loop; let `history.undo()` own
  the transition.
- Handling the shortcut twice (input layer and a page listener) undoes two steps; keep one owner.
- A field inside the overlay must keep its browser undo — test with a focused input.
- A new operation after undo must clear redo; the history already does, verify it through the UI.
- The hint must not reuse the context-menu slot; use the documented bottom-centre place.
