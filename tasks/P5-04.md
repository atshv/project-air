# P5-04 — SDK board-sync client and the one autosave path (L05 realtime half)

## Goal

`packages/sdk` becomes the client board library: it owns the client `BoardDoc`, speaks the 0.3.0
sync protocol over an injected WebSocket (`connect`/`joinBoard`, operation batches, remote
updates/snapshots, ack/`serverSeq`, reconnect from a state vector) and provides the one L05 autosave
path for its realtime half — 400 ms debounce, immediate flush on blur/panel close/navigation/tab
hidden/pagehide, sequence numbers against stale responses, an offline queue and saving/saved/error
events.

**Why:** ADR-0012 places the client document and the sync boundary in the SDK; every later client
(web app, e2e and load harnesses) needs one typed path with one autosave behaviour (L05
cross-section rule 3).

**Satisfies:** D11

## Scope

- `packages/sdk/` sync client: `createBoardSync(options)` owning one `BoardDoc`, taking an injected
  WebSocket-like connection (tests use a fake), performing `hello`/`welcome` and `joinBoard`
  (snapshot + catch-up from its state vector), sending local operations as one `operationBatch` with
  per-connection sequence numbers, applying remote batches/snapshots through `BoardDoc`, tracking
  `serverSeq`/acks, exposing state events, and reconnecting with bounded backoff and a
  `resyncRequest`; `close()`/`leaveBoard()` are idempotent.
- `packages/sdk/` the one autosave path: a 400 ms debounced writer with immediate flush on blur,
  panel close, navigation, `visibilitychange` hidden and `pagehide`; monotonic request sequence
  numbers so a delayed older response never overwrites a newer value; an ordered offline queue that
  flushes on reconnect; `saving` → `saved` → `error` events with `retry()`; no second save path and
  no board-content persistence in the SDK.
- `packages/sdk/` errors and safety: typed contract error codes, session token supplied by the
  caller, no token or payload logging, bounded queue with a clear error when exceeded, board-switch
  isolation (one document per board, no cross-board leakage).
- Tests: fake paired connections and an injected clock for handshake, join/catch-up, batch send, ack
  ordering, stale-response rejection, queue ordering/flush, reconnect resync, duplicate suppression,
  the five flush triggers and status transitions; one real-service integration path where practical. `.changes/P5-04-<short-name>.md` (area `sync`, kind
  `minor`); `docs/realtime.md` documents the client boundary and the autosave contract;
  `docs/adr/ADR-0012-sdk-client-document.md` gets the consequences refined if needed.

## Out of scope

- Presence payloads/UI (P5-05), restart/compaction proofs (P5-06), load (P5-08), web UI, panel or
  editor components (web-app stage), contract changes, new dependencies beyond the approved Yjs
  (through `packages/crdt`), a second transport.

## Acceptance

A1 WHEN the SDK joins a board, THEN it performs the 0.3.0 handshake, installs the snapshot and
catch-up, sends local operations as one batch, applies remote updates/snapshots through `BoardDoc`,
tracks `serverSeq` and reconnects from its state vector after a connection drop.
A2 WHEN autosave runs, THEN exactly one save is flushed 400 ms after the last keystroke or
immediately on blur, panel close, navigation, tab hidden and pagehide; sequence numbers prevent an
older response from overwriting a newer value; offline operations queue and flush in order; and
saving/saved/error events fire with `retry()`.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit` and `typecheck` exit 0 with
records, the SDK exports/types are documented, `docs/realtime.md` documents the client and autosave
contract, and no new dependency beyond Yjs (through `packages/crdt`) is added.

## Specifications

- `packages/sdk` may import `packages/contracts` and `packages/crdt` (`boundaries` gate, ADR-0012);
  it stays DOM-free apart from the injected WebSocket-like connection.
- One autosave path only (L05 cross-section rule 3); the SDK owns the timer, the queue and the status
  events, and no second writer exists beside it.
- Deterministic tests: injected clock and fake connections; no sleeps, no real timers, no network.
- The contract is the wire format: every message is validated before sending/receiving; unknown
  messages fail with a typed error.
- Sequence numbers: monotonic per save path, strictly ordered flushes; a late response with an older
  sequence is ignored and never applied.
- Reconnect is bounded (documented backoff, capped attempts), sends `resyncRequest` from the
  document state vector and never re-sends an already-acknowledged batch.
- No tokens, payloads or board content in logs; no secret in the repo or bundle.

## Pitfalls

- A debounce timer that is not cleared on flush sends the same edit twice; test the five triggers.
- Applying an older ack/response after a newer local value silently loses data — the sequence check
  is the core L05 requirement.
- Duplicate sends after reconnect are not harmless: dedupe by client sequence/operation id.
- A snapshot + catch-up gap (snapshot at `serverSeq` N, updates from N) must be installed atomically;
  do not apply updates before the snapshot.
- Board switching must not leak the previous document or queue.
- Session expiry surfaces as a typed error/status, not an endless reconnect loop.
