# P1-01 — Board content data model as JSON Schema

## Goal

`packages/contracts` contains the board-content data model as JSON Schema 2020-12 with valid and
invalid fixtures: account, workspace, board, note, card placement, zone, block, edge, parent
relationship, fractional index, minimum sizes and timestamps.

**Why:** the engine, backend and web app must agree on one versioned model before they exchange
anything (AD-3, AD-4); this is the first contract (version `0.1.0`).

**Satisfies:** D7 (planned in the contract stage)

## Scope

- `packages/contracts/`: package manifest (`package.json`, workspace package, no runtime
  dependencies), `schemas/` with the JSON Schema files, `fixtures/` with at least one valid and one
  invalid example per schema, a small `index.mjs` exporting the schema paths, and Node-builtin unit
  tests (`node:test`) that parse every schema/fixture and check the fixture metadata and required
  fields.
- Model (minimum, extend only from the blueprint §5.1):
  - account, workspace, board (owner, timestamps, title, visibility);
  - note (one note exists once, `AD-4`), card placement (board, note reference, x/y/size/z/fraction),
    zone (contains cards), block types (checklist, palette, columns, timeline, table), edge/connection
    between two cards;
  - parent relationship (board → zone → card → child), fractional index as a string, minimum sizes
    for every object type (note 176×80, checklist 224×128, table 288×160, zone 256×192, columns
    368×192, timeline 320×160, palette 224×128), ids and timestamps.
- Versioning: the contract carries version `0.1.0`; schemas use `$id` with that version and a
  `$schema` of JSON Schema 2020-12.
- `.changes/P1-01-board-model.md` (area `contracts`, kind `minor`, one English line).
- Update `packages/contracts/README.md` and `ARCHITECTURE.md` (schema map, fixtures, commands).

## Out of scope

- Operations/undo (P1-02), codegen (P1-03), sync protocol (P1-04), API errors (P1-05), prose/ADR
  (P1-06), engine or backend code.
- New third-party dependencies; a JSON Schema validator library is not allowed in this task.

## Acceptance

A1 WHEN the schemas are read, THEN every entity and relation from the minimum model exists with a
`$id` including `0.1.0`, JSON Schema 2020-12, required fields, enums for fixed values and numeric
minimum sizes for the object types.
A2 WHEN `fixtures/` is read, THEN every schema has at least one valid and one invalid fixture, each
fixture names its schema and validity, and the invalid one violates a documented rule.
A3 WHEN `pnpm --filter ./packages/contracts test` runs, THEN every schema/fixture parses, the
fixture/schema mapping is complete, required top-level fields are present in valid fixtures, and the
tests pass; the `unit` gate record is committed.
A4 WHEN `python3 $POLIER/tools/check.py .` runs, THEN it exits 0 (before `pnpm install`).

## Specifications

- **No dependencies:** tests use `node:test`/`node:assert`; the package has no `dependencies` or
  `devDependencies` (root tooling is enough).
- **Schema layout:** one file per entity under `packages/contracts/schemas/`, referenced with
  `$ref` from a root `board.schema.json` where useful; ids stable and versioned.
- **Fixture metadata:** a wrapper per fixture file: `{ "schema": "...", "valid": true|false,
  "reason": "...", "data": { ... } }`; invalid fixtures name the violated rule.
- **Test scope:** structural (schema JSON parses, `$id`/version, required fields, fixture mapping,
  minimum size values, enums); a full JSON Schema validator is not required in this task.
- **Commands:** report the exact `unit` command for `docs/quality.md`.
- **No engine or server code, no generated TypeScript in this task.**

## Pitfalls

- Do not implement operations or codegen here; keep the data model only.
- A note exists once (`AD-4`); cards reference notes, they never embed note content.
- Use strings for ids and fractional indexes; validate minimum sizes as numbers.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm install`.
- The root lockfile must stay consistent; if pnpm changes it, commit the change.

## Edge cases

- A card without a zone (board-level card) is valid; a zone inside a zone is not part of v1.
- An edge between a card and a zone is invalid in v1 (cards only).
- Unknown block type → invalid; every block type has its own minimum size.
- Timestamps are ISO-8601 strings with timezone.
