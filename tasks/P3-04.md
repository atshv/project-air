# P3-04 — Platform API routes and api-tests

## Goal

The platform API serves workspace, board, note and card envelopes from the contract with
owner/editor/reader permission checks and the shared error envelope, and every route has an
allow-and-deny API test.

**Why:** the stage exit needs a tested allow/deny API surface; the SDK and the realtime service
build on these routes.

**Satisfies:** D9

## Scope

- `services/platform/` routes (envelopes exactly as in `packages/contracts/schemas/api/`):
  - `/v1/workspaces` — list (paginated `items` + `nextCursor`), create, get, update, delete.
  - `/v1/workspaces/:workspaceId/boards` and `/v1/boards/:boardId` — list/create/get/update/delete.
  - `/v1/workspaces/:workspaceId/notes` and `/v1/notes/:noteId` — list/create/get/update/delete.
  - `/v1/boards/:boardId/cards` and `/v1/cards/:cardId` — list/create/get/update/delete.
  - Requests carry `requestId` (client value echoed), list responses carry `items` and
    `nextCursor` (null on the last page, limit 1–100), writes return the resource envelope.
  - Permission matrix: read = any member; create/update/delete boards, notes and cards =
    owner/editor; workspace update = owner/editor; workspace delete and member changes = owner;
    non-member → `NOT_FOUND` (do not reveal existence).
  - Every request opens a transaction, sets `app.account_id` via `SET LOCAL` and runs queries as
    `app_user` (AD-5 second line); session comes from `services/auth` (test mode in tests).
  - Error envelope `{code, messageKey, details?, requestId}` with the contract codes; validation
    details are field paths, never user text.
- `services/platform/test/api/*.test.mjs` — `api-tests`: boot both services in-process on ephemeral
  ports against the slot database (reset + migrations in `before`), create accounts/workspaces via
  the auth test mode, and assert for **every** route an allow case and a deny case (wrong role,
  foreign workspace, missing session, invalid payload). Tests must close pools and servers.
- `.changes/P3-04-platform-api.md` (area `platform`, kind `minor`).

## Out of scope

- SDK and the full RLS suite (P3-05), media/files, realtime, comments, templates, pagination beyond
  the simple cursor, rate limiting implementation (only the error code mapping), UI.

## Acceptance

A1 WHEN the routes are read, THEN every resource from the P1-05 API contract has list/get/create/
update/delete endpoints with the contract envelopes, `requestId` and cursor pagination.
A2 WHEN the permission matrix is exercised, THEN owner/editor/reader/non-member behave exactly as
specified and workspace existence is not leaked to non-members.
A3 WHEN `node --test services/platform/test/api/*.test.mjs` runs, THEN every route has at least one
allow and one deny case and all tests pass.
A4 WHEN `board-check`, `boundaries`, `unit` and `api-tests` run, THEN all exit 0 with records
committed.

## Specifications

- Validate requests against the contract limits (title/name lengths from ADR-0004, page size
  1–100) with explicit checks; no validation library, no new dependency.
- Cursor pagination: order by `(created_at, id)`, cursor encodes the last seen pair (opaque
  base64url), stable for inserts during pagination.
- Notes are created once and shared across cards (AD-4); a card references the note, never embeds
  it. Card creation requires the note to belong to the same workspace.
- Errors: `AUTH_REQUIRED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404, `VALIDATION` 400, `CONFLICT` 409,
  `RATE_LIMITED` 429, `INTERNAL` 500 — with the `errors.<camelCase>` keys from P1-05.
- Tests must be deterministic and isolated: each test creates its own accounts/workspaces; the
  suite resets the slot database once, then migrates; pools closed in `after()`.
- No service-to-service DB access: the platform uses its own pool; auth is an HTTP call only.

## Pitfalls

- Forgetting `SET LOCAL app.account_id` inside the transaction returns zero rows silently — assert
  allow cases, not just deny cases.
- `POSTGRES_USER` (superuser) bypasses RLS: the API must connect as `app_user`.
- A foreign workspace must look like a 404, not a 403 (no existence leak).
- Close the in-process servers and pools, or `node --test` hangs.
- `board-check` before any `pnpm` command; tests are exclusive on the `db` resource.

## Edge cases

- Empty lists → `items: []`, `nextCursor: null`; last page → `nextCursor: null`.
- Invalid limit (0, 101, non-int) → `VALIDATION`; unknown ids → `NOT_FOUND`.
- Workspace without owner row (corrupt state) → `INTERNAL`, not a crash.
- A card whose note is in another workspace → `VALIDATION` (or `NOT_FOUND`), never created.
- Duplicate workspace name in the same account is allowed (no unique name), no hidden constraint.
