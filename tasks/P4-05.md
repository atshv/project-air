# P4-05 — Gesture-to-operation seam and undo history core

## Goal

The engine package gains a typed gesture-to-operation layer: every content gesture produces exactly
one contract operation with its inverse, and a per-session history records up to 20 `{do, undo}`
pairs; unit tests prove one gesture equals one operation and that a counter-operation restores the
previous state.

**Why:** AD-1 and canvas cross-section rule 2 require reversibility from the first write. Every
interaction task (drag, snap, resize, multi-select, keyboard, zones) produces its operations through
this seam instead of inventing a second write or save path.

**Satisfies:** D10

## Scope

- `packages/engine/src/logic/` (TS logic layer, UI -> logic -> data):
  - `operations.ts`: build contract operations from gesture results — move (single object and group
    as one operation), resize, create, delete, z-order and selection-independent content changes.
    Use the generated contract types (`packages/contracts/generated/types.ts`) and the
    `operation` schema; each builder returns `{ operation, inverse }` where the inverse is a contract
    operation too.
  - `document-port.ts`: the narrow data port the logic calls (add/update/remove object, update z)
    with a pure in-memory fake for tests and the bridge adapter for the browser.
  - `history.ts`: a session history with depth 20, `push(operation, inverse)`, `undo()`, `redo()`,
    redo cleared on a new operation, and a `describe()` label for the undo hint.
  - `gestures.ts`: the typed gesture-result union (drag single, drag group, resize, create, delete,
    keyboard nudge series) so input code never calls the document directly.
- `packages/engine/package.json`: add the `test` script (`node --test test/*.test.mjs`) and keep
  `build`/`typecheck`/`lint` green; `tsconfig.json` covers the new folder.
- `packages/engine/test/operations.test.mjs` (or `.ts` compiled): one gesture = one operation;
  inverse restores byte-identical engine state; undo/redo depth and redo-clear semantics; group move
  is one operation; rejection of invalid or unknown ids; no network and no DOM in the logic layer.
- `packages/engine/ARCHITECTURE.md` and `docs/engine.md`: document the three TS layers and the rule
  that gestures go through `history` — no direct document writes.
- `.changes/P4-05-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Pointer/keyboard input handling, selection state, snapping, rendering, the playground UI.
- Applying operations to a server or CRDT; server-side sync is realtime.
- Selection/undo of another client's operations (realtime); zone membership operations (P4-23/24).
- New dependencies; changed or deleted existing tests.

## Acceptance

A1 WHEN a gesture result is converted, THEN it yields exactly one contract operation with a valid
inverse, and a group move is one operation (not one per object); unit tests assert the operation
shape against the generated types.
A2 WHEN an operation is applied and then its inverse, THEN the engine working copy is byte-identical
to before (via the fake port and a native round-trip check); undo does the inverse and redo re-applies
the operation.
A3 WHEN the history holds more than 20 entries, THEN the oldest is dropped, a new operation clears
the redo branch, and `describe()` returns the hint label for the last undoable operation.
A4 WHEN the task is done, THEN `board-check`, `boundaries`, `typecheck` and `unit` exit 0 with
records committed, and the architecture docs state the layer rule.

## Specifications

- The logic layer is pure TypeScript: no DOM, no `fetch`, no engine module import at module scope.
  The document port is injected; tests use a deterministic fake.
- Operation builders respect the contract's field names and limits; never invent a parallel
  operation shape. Where the contract lacks a field the gesture needs, write an open question
  instead of extending the schema in this task.
- One gesture = one operation: a keyboard-nudge series is batched into one operation (later task
  provides the timer), a group drag is one move operation; never emit per-object operations.
- The history stores operations, not engine indices; applying uses stable object ids from P4-01.
- `describe()` labels come from a small, English-key lookup in the logic layer (UI text later comes
  from translation files; no user-visible string is rendered in this task).

## Pitfalls

- Do not let the logic layer call the WASM module directly; that would make it untestable in Node and
  break the layer rule.
- The existing bridge has no test script; adding one must not change the published exports.
- Exact-optional-property and noUncheckedIndexedAccess are on: the code must typecheck with the
  strict base config.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- Empty gesture result: no operation, no history entry.
- Removing an object that is already gone: rejected, no history entry.
- A move to the current position: decide one rule (no-op) and test it.
- Undo while the history is empty: no-op, no error.
