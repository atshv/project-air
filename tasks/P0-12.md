# P0-12 — Design tokens and icons in ui-kit

## Goal

`packages/ui-kit/tokens.json` is the single source of visual values and generates CSS custom
properties and a C++ header; the toolbar icons are SVG files; no new dependency.

**Why:** AD-7 — one source of visual values for web and engine; P0-13 (`design-check`) and the
engine build on this.

**Satisfies:** D3

## Scope

- `packages/ui-kit/tokens.json`: every token the design law uses — colours, spacing, sizes,
  radii, typography, motion, shadows, layers and person tones. Take the names from
  `docs/design-rules.md` and the values from blueprint section 21.1 (first) and
  `reference/src/app/globals.css` (for tokens the blueprint summary does not spell out). No value
  may be invented.
- A self-contained code generator (Node.js ESM, Node builtins only) that reads `tokens.json` and
  writes: (a) CSS custom properties (`:root { --…: …; }`) and (b) a C++ header with the same
  values as typed constants. Commit the generated files under `packages/ui-kit/` and make
  regeneration deterministic (no timestamps, stable ordering, `\n` endings).
- `packages/ui-kit/layers.ts`: the layer order as typed data, generated from the same tokens (the
  design law's `z-index` rule names this file).
- `packages/ui-kit/icons/*.svg`: one SVG per toolbar icon from
  `reference/src/ui/canvas/toolbar-icons.tsx` — `note`, `source`, `image`, `file`, `zone`,
  `checklist`, `palette`, `columns`, `timeline`, `table`; 24×24 grid, stroke 1.6, round caps and
  joins, `currentColor`, no fills, no inline style.
- `packages/ui-kit/package.json` with `lint`, `typecheck`, `test`, `build` and `codegen` scripts
  (workspace package; no new dependencies; unit tests with the Node builtin `node:test`).
  Update the root `pnpm-lock.yaml` for the new workspace package.
- Unit tests: token groups present and values in the expected form; generated CSS and C++ header
  match the committed files; `layers.ts` order matches the tokens; icons are valid SVG with
  `currentColor`, 24 viewBox, no fill; no raw colour value outside `tokens.json` (except the
  generated outputs, which are derived).
- Update `packages/ui-kit/README.md` and `packages/ui-kit/ARCHITECTURE.md` (outputs, commands).

## Out of scope

- `tools/design-check/` (P0-13), web/engine components, CSS beyond the generated tokens file,
  fonts or third-party icon sets.

## Acceptance

A1 WHEN `tokens.json` is compared with `docs/design-rules.md` and blueprint 21.1, THEN every token
group and value is present, names match the design law, and no value is invented or missing.
A2 WHEN `codegen` is run twice, THEN the second run leaves the tree clean (deterministic) and the
generated CSS and C++ header contain every token with the same values.
A3 WHEN `packages/ui-kit/icons/` is read, THEN it contains exactly the ten toolbar icons above as
SVG files with a 24 viewBox, stroke 1.6, round caps/joins and `currentColor`.
A4 WHEN `pnpm --filter ./packages/ui-kit test`, `pnpm --filter ./packages/ui-kit typecheck` and
`pnpm --filter ./packages/ui-kit lint` run, THEN each exits 0, the `tokens-codegen` gate exits 0,
and `python3 $POLIER/tools/check.py .` exits 0 (run it before `pnpm install`); records are
committed.

## Specifications

- **Token naming:** CSS custom properties carry the `--` prefix; the key in `tokens.json` is the
  same name without it (as stated in `docs/design-rules.md` §2).
- **Generated files:** document their exact paths in the package `README.md`; they are committed,
  so the `tokens-codegen` gate can prove "regenerate, then `git diff --exit-code`".
- **C++ header:** `#pragma once`, constants (or a struct of `constexpr` values), no engine code.
- **Icons:** paths copied from the reference component, converted to standalone SVG files; the
  visual shape must not change; the reference's icon component is not imported or copied as code.
- **No new dependencies**; Node builtins (`node:fs`, `node:path`, `node:test`, `node:assert`).
- **Gate commands:** report the exact `tokens-codegen` and `unit` commands you used; the lead
  updates `docs/quality.md`.

## Pitfalls

- The 400-word package `ARCHITECTURE.md` budget stays enforced; expand it only within the budget.
- `check.py` scans `node_modules/`; run `board-check` before `pnpm install` or after removing it.
- Generated files must not drift: run `codegen` twice and check `git diff`.
- Do not add a formatter, SVG optimizer or schema library — integrate with the existing ESLint,
  TypeScript and Node test setup only.
- The reference belongs to an earlier prototype: copy values and icon geometry, never its names,
  imports, CSS classes or vendor references into the new files.

## Edge cases

- A design-law token missing from blueprint 21.1 and the reference CSS → keep it out and record an
  `open_question`; do not invent a value.
- A reference icon whose JSX uses a shared wrapper or props → expand it to a plain SVG with the
  same geometry (24 grid, stroke 1.6, round).
- Icons and tokens are the only deliverables; no UI component may be built here.

3. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0.
