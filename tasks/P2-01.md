# P2-01 — Engine toolchain and native + WASM build scaffold

> **Size:** 400–900 words. First task of the engine-spike stage.

## Goal

`packages/engine` builds a minimal C++20 engine target natively and to WebAssembly with the pinned
CMake/Emscripten toolchain, its unit suite is registered with CTest and green, and the project gate
commands and versions are documented.

**Why:** every later engine task and the stage exit gates `cpp-unit` and `wasm-build` build on this
toolchain; the contract codegen and the ui-kit token header must be consumable from C++.

**Satisfies:** D8

## Scope

- Toolchain (owner approved 2026-10-25: pinned installs are free, no paid tier):
  - `brew install cmake emscripten`; at planning time Homebrew resolves **CMake 4.4.4 (BSD-3-Clause)**
    and **Emscripten 6.0.13 (Apache-2.0 / LLVM exception / MIT or NCSA)**. Verify the actually
    installed versions (`cmake --version`, `emcc --version`), pin them in `docs/versions.md` with
    exact version, source URL, date and licence, and never use `latest`.
  - Add the Emscripten `emcc`/`em++` to the session `PATH` (`$(brew --prefix emscripten)/bin` or the
    formula bin); CI keeps its own pinned install later.
- `packages/engine/CMakeLists.txt`: C++20, library target `air_engine`, test executable
  `engine_unit_tests` registered with `enable_testing()`/CTest, include paths for
  `packages/contracts/generated/` and `packages/ui-kit/` (generated `contract.h`/`tokens.h`), flags
  `-Wall -Wextra -Wpedantic -Werror`, no third-party libraries.
- Minimal sources so the build is real: `include/engine/engine.h` + `src/engine.cpp` exposing
  `air_engine_version()` and a compile-time check that the generated contract header is included and
  `kContractVersion` is `0.1.0`; one native unit test (`test/engine_test.cpp`) asserting the version,
  the contract version and C++20 (`__cplusplus >= 202002L`).
- Emscripten target: the same library builds with `emcmake` to `build-wasm/engine.wasm` +
  `build-wasm/engine.js` (exported `air_engine_version`, no DOM or GL yet).
- Gates documented: replace the `[VERIFY: …]` rows in `docs/gates/cpp-cmake.md` and
  `docs/gates/wasm-emscripten.md` with the exact project commands and artifact paths; keep
  `docs/quality.md` gate rows in sync if a command changes. Update the package README/ARCHITECTURE
  command sections.
- `.changes/P2-01-engine-toolchain.md` (area `engine`, kind `minor`).
- `pnpm-lock.yaml` only if a workspace manifest changes (the engine gains no npm dependency).

## Specifications

- Node/TypeScript toolchain stays as pinned (`docs/versions.md`); the engine adds no npm dependency.
- Build directories (`packages/engine/build/`, `build-wasm/`) are ignored by the existing
  `.gitignore` (`build/`, `build-*/`) and are never committed.
- C++ standard is C++20 everywhere; no exceptions for debugging builds.
- The native and WASM builds use the same `CMakeLists.txt`; the toolchain differences live in the
  Emscripten toolchain file or in documented `if(EMSCRIPTEN)` branches.
- `docs/gates/*.md` keep the catalogue shape (table + pitfalls), now with concrete project commands.
- One commit `<ID>: <title>`, `.changes` entry, no push.

## Pitfalls

- `emcc` is not on the default `PATH` after a Homebrew install; the gate command must work from a
  clean shell or document the `PATH` line.
- Emscripten flag names change between majors; only use flags verified with the installed version.
- `board-check` scans `node_modules/`; run it before any `pnpm` command.
- A stale `build/` hides changes; configure into a fresh directory when in doubt.
- Never commit `build/`, `build-wasm/`, `.cache` or absolute `CMakeCache.txt` paths.
- Do not change `packages/contracts` or `packages/ui-kit`; only include their generated headers.

## Edge cases

- No `emcc` available → `wasm-build` fails with a clear message, never silently skips.
- Generated headers missing (fresh checkout without codegen) → run the existing contract/ui-kit
  codegen first and document it, do not copy generated files into the engine.
- Apple clang warning-as-error differences between native and Emscripten builds → fix the code, not
  the flags.

## Gates

1. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0 (before any install).
2. `cpp-unit`: `cmake -S packages/engine -B packages/engine/build -DCMAKE_BUILD_TYPE=Debug && cmake
   --build packages/engine/build --parallel && ctest --test-dir packages/engine/build
   --output-on-failure` → exit 0, "100% tests passed".
3. `wasm-build`: `emcmake cmake -S packages/engine -B packages/engine/build-wasm
   -DCMAKE_BUILD_TYPE=Release && cmake --build packages/engine/build-wasm --parallel` → exit 0,
   `engine.wasm` + `engine.js` written.

Also run `boundaries` (`python3 $POLIER/tools/boundaries.py .`) as a check (not a board gate of
this task) and keep it at exit 0.
