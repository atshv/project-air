# P0-07 — Local services compose

## Goal

PostgreSQL, S3-compatible object storage and a mail catcher start locally with one command, shared
by all worktrees, with one database and one bucket per slot created later by `tools/dev/setup`.

**Why:** backend, auth and media tasks need these services; P0-06 (per-slot setup) creates slot
databases and buckets inside them.

**Satisfies:** D2

## Scope

- `infra/compose/` with one compose file defining three services: PostgreSQL, S3-compatible storage,
  mail catcher (SMTP + web inbox).
- Images pinned to exact versions (tag plus digest where available), each listed in
  `docs/versions.md` by the lead after review (the task reports them in its result).
- Fixed host ports for these shared services, documented in `infra/compose/README.md`, outside the
  slot range (slots use 4000–4999).
- Health checks for all three services.
- `infra/compose/README.md`: start, stop, reset of local data (owner data in slot 0 is never reset by
  scripts), which ports are used.
- `.env.example` names (no values) if the services need credentials; local values in `.env`
  (gitignored).

## Out of scope

- Creating slot databases and buckets (P0-06), migrations (stage backend-core), deployment
  infrastructure (P0-15 and later).

## Acceptance

A1 WHEN the documented start command runs, THEN all three services report healthy within 60 s.
A2 WHEN the compose configuration is validated, THEN it lists exactly the three services with pinned
image versions and health checks.
A3 WHEN `infra/compose/README.md` is read, THEN it names the start, stop and reset commands, the host
ports, and states that no script resets slot 0 data.

## Specifications

- **Package:** `infra` — writes only `infra/compose/` (and `.env.example` names, reported to the lead
  if outside scope).
- **Image choice:** propose the S3-compatible storage and the mail catcher image with licence and
  version source before writing; open-source licences only.
- **Gate command:** the compose CLI's configuration validation; report the exact command for
  `docs/quality.md`.

## Pitfalls

- Container tooling may not be installed in the agent environment; if so, report it as
  `open_questions` and stop instead of installing software.
- Do not bind service ports inside the slot range 4000–4999.

## Edge cases

- Port already in use on the owner's machine → document an override variable, never stop the other
  process.

## Gates

1. `compose-config`: compose configuration validation command (set in this task) → exit 0, three
   services listed.

## Limits

- **Scope:** only `infra/compose/`.
- **Stop:** 2 rounds; when blocked, `status: blocked` + reason.
