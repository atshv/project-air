# P0-20 — Live connection demo in the preview

## Goal

The design preview shows two note cards connected by an edge; both cards can be dragged with
mouse, touch or keyboard and the connection follows live, so the owner can feel the interaction
before the engine exists.

**Why:** the owner wants to feel the board interaction early ("build, show, continue"), not only
look at static sections.

**Satisfies:** D3

## Scope

- `apps/web/preview/`: add a clearly labelled interactive demo section (or extend the sample board
  section) with:
  - two note cards connected by one edge (SVG line/path) in a dot-grid demo area;
  - pointer dragging (`pointerdown`/`pointermove`/`pointerup`, `setPointerCapture`) for both
    cards, whole card as drag handle, 4-px drag threshold, `grabbing` cursor and the selected
    card state (1.5-px `--accent` border + `--accent-soft` ring);
  - the edge recomputed continuously while dragging (anchor at the nearest rectangle edges), with
    small endpoint dots; 1.5-px `--border-strong` stroke; the edge stays below the cards;
  - keyboard nudge: cards focusable, arrow keys move 16 px (the canvas grid), `Home` resets;
  - positions constrained to the demo area, no scrolling/jumping; works at 1440×900 and 390×844;
  - label "interactive demo — not the engine; no data, no server".
- `apps/web/preview/preview.js` (or extend the existing one) with no dependencies; update
  `index.html`, `preview.css`, `README.md` (how the demo works, its limits).
- Only token values (`var(--…)`); no raw colours; no inline colour values; dot grid via tokens.
- `.changes/P0-20-live-preview-demo.md` (area `web`, kind `patch`, one English line).
- Manual evidence `reviews/evidence/P0-20-preview.log`: serve on the slot web port, `curl` 200,
  and a screenshot `reviews/evidence/P0-20-demo.png` (1440×900) showing both cards and the edge;
  note how the drag was verified (headless screenshot of the initial state plus a short manual
  description of the pointer logic).

## Out of scope

- Real engine, persistence, CRDT, multiple boards, adding/removing objects, pan/zoom, snapping,
  selection of multiple cards, server or data.
- Changes outside `apps/web/preview/` and `.changes/`.

## Acceptance

A1 WHEN the demo is opened, THEN two note cards and one connecting edge are visible; dragging a
card moves it and the edge follows without gaps; the other card stays put.
A2 WHEN the page is used at 390×844 or with keyboard only, THEN the cards stay inside the demo

A3 WHEN `python3 $POLIER/tools/check.py .`, `node tools/config`-free design rules and the

## Specifications

- **No framework, no dependency, no build step**; plain DOM/SVG and `preview.js`.
- **Coordinate system:** cards positioned absolutely inside the demo container; keep a min/max
  clamp so a card cannot leave the area.
- **Drag:** whole card is the handle; threshold 4 px before moving; `pointercapture`; ignore
  drags that start on a future control.
- **Edge:** recompute endpoints from the two card rectangles (nearest sides), update the SVG
  attributes each frame (no layout thrash beyond transform/position); endpoint dots 3 px.
- **States:** focusable cards with visible focus ring, drag state, selected state; respect
  `prefers-reduced-motion` (no transitions for movement).
- **Tokens only:** dot grid, colours, radii, shadows via `var(--…)`; no new tokens.
- **Serve/screenshot:** read the web port from `.polier-slot`; `python3 -m http.server`; headless
  Chromium from `~/Library/Caches/ms-playwright/...` like P0-19; no hard-coded 4000–4999.
- **Change entry:** required because `apps/` code changes; use the P0-14 gate.

## Pitfalls

- Do not attach the drag to the whole page; only the demo cards.
- Do not move cards on a simple click (< 4 px) — that would feel broken.
- Do not let the edge draw above cards; it belongs below in the layer order.
- Keep the static sections intact; the demo is an addition, clearly labelled.
- `check.py` scans `node_modules/`; run `board-check` before any install.

## Edge cases

- Pointer leaves the window mid-drag → capture keeps the drag until `pointerup`/`pointercancel`.
- Two cards overlap → the edge may be short; keep it valid (no negative length).
- Small screens: stacked layout, demo area height grows; no horizontal overflow.
- Keyboard: focus must not scroll the page; `Home` returns both cards to start positions.
