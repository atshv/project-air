# P6-01 — Web app scaffold: React + Vite SPA, layout, i18n and base components

## Goal

`apps/web` becomes a React 19 + Vite SPA on the slot web port: router with start/login/boards/board/
settings routes, layout and navigation, ui-kit tokens/layers/icons, base components (button, icon
button, menu, dialog), the i18n loader over `apps/web/messages` (en/de parity, persisted language
with `<html lang>`), and pinned dependencies with licence/source in `docs/versions.md` (ADR-0013:
no paid-tier libraries, the editor stays our own code).

**Why:** every later web task builds on one shell, one design-token source and one message catalog;
ADR-0013 fixes the stack (owner-approved).

**Satisfies:** D12

## Scope

- `apps/web/` project skeleton: `package.json` with `dev`, `build`, `preview`, `typecheck`, `lint`,
  `test`; Vite config reading the slot (`web` port 4100, preview/e2e 4101 — never hardcode 3000);
  `tsconfig` extending the workspace base; eslint flat config as in the other packages;
  `index.html`; `src/main.tsx`, `src/App.tsx`.
- `apps/web/` router and layout: routes `/` (start), `/login`, `/boards`, `/boards/:id`, `/settings`;
  a top bar with the product name, language switch, account area (session hook is P6-02, so it may
  render the unauthenticated state), a nav to boards/settings, and keyboard/focus basics. Routes for
  later tasks (`/login`, `/boards`, `/boards/:id`) render an honest "not connected yet" state that
  P6-02…P6-04 replace — no fake data.
- `apps/web/` design system integration: import `packages/ui-kit/tokens.css`; colours/spacing/radius/
  z-index only via tokens and `layers.ts` (no raw hex, no z-index outside layers); icons from
  `packages/ui-kit/icons`; base components `Button`, `IconButton`, `Menu`, `Dialog` with
  `aria-label`/`data-label` from message files, focus trap for Dialog, 36/28 px sizes per
  `docs/design-rules.md`.
- `apps/web/` i18n: one loader over `apps/web/messages/{en,de}.json` (matching keys, German as
  default, English switch, persisted choice, `<html lang>` updated); add the shell/start/settings
  keys in en and de (the existing `canvas`/`note`/`panel`/`errors` keys stay); `language-check`
  must stay green (no literal visible text in code).
- Dependencies (owner-approved stack, ADR-0013): react, react-dom, react-router, vite,
  `@vitejs/plugin-react`, `@types/react`, `@types/react-dom` — exact versions pinned in
  `apps/web/package.json`, `pnpm-lock.yaml` and `docs/versions.md` with licence, source URL and date
  (npm registry); **no** rich-text library, no paid-tier package, no SSR framework.
- `docs/versions.md`: a web row group with each new dependency; `.changes/P6-01-<short-name>.md`
  (`pnpm run change -- web minor "<summary>"`).

## Out of scope

- Login/registration pages and session logic (P6-02), board list (P6-03), the board page/engine
  (P6-04+), the editor (P6-06), realtime UI (P6-07), e2e (P6-08), SSR/Next.js (deferred),
  templates/library/search (value stage).

## Specifications

- The app is client-rendered (ADR-0013); no server code in `apps/web`; data access comes later only
  through `packages/sdk` (P6-02/P6-03).
- Imports only per `packages[].may_import` for `apps/web` (`contracts`, `ui-kit`, `editor`, `engine`,
  `sdk`) — the `boundaries` gate is authoritative.
- Tooling consistency: TypeScript strict, ESM, scripts mirror the other packages; tests use
  `node --test` for pure logic (i18n loader, language persistence, route helpers) — DOM tests would
  need extra dependencies, so the shell behaviour is covered by P6-08's e2e.
- Pin versions from the registry at task time (npm URL + date in `docs/versions.md`); no `latest`.
- Keep the preview (`apps/web/preview/`) untouched; the app is the product, the preview is the
  design reference.

## Pitfalls

- Raw colour, off-grid spacing or a z-index outside `layers.ts` fails `design-check`; use tokens.
- Hardcoded ports break parallel sessions — read `.polier-slot` (the dev loop writes it) and allow an
  env override for e2e.
- A React/Vite version mismatch with the Node toolchain fails the build; run `pnpm install` and
  `pnpm build` after pinning.
- `language-check` scans `*.md` and code for German literals; all new text goes into `en.json` and
  `de.json` with the same keys.
- Do not commit `dist/` or `node_modules`; the app's build output stays ignored.
- A "later route" stub must be an explicit empty state from messages — no lorem ipsum and no unfinished-marker text.
