# P4-19 — Placement of new objects (L20)

## Goal

New objects appear at the centre of the view on the 16 px grid, cascade 32 px right and down while the
spot is taken (at most 10 attempts) and never land outside the visible area; a unit suite covers the
placement function and five consecutive "add note" actions give five visible, non-overlapping cards.

**Why:** L20 — a new object must be visible and usable where the person is looking, never stacked
invisibly on top of another.

**Satisfies:** D10

## Scope

- `packages/engine/` placement function (pure, unit-tested): input = visible world bounds, grid
  (`tokens::canvas_grid` 16 px), the existing visible objects and the new object's size; output = a
  world position on the 16 px grid, starting at the view centre (snapped), cascading
  `tokens::space_32` right and down while the candidate overlaps an existing visible object, at most
  ten attempts; the result is always inside the visible world bounds (clamped on the grid, never
  outside), deterministic, no clock/random, and independent of zoom except through the visible
  bounds. If ten attempts are taken, the tenth candidate is returned (documented); a candidate only
  counts an overlap against visible objects of the same board.
- `packages/engine/` create path: the placement feeds the existing create gesture/operation builders
  (card, block, zone) through the P4-05 seam, so a new object is one create operation with inverse at
  the computed position; no separate position write.
- `apps/engine-playground/`: an "add note" action (button/`n` key) that creates a card at the
  computed position through the seam; five consecutive actions produce five visible, non-overlapping
  cards; a deterministic capture record under `reviews/evidence/` records positions, attempt counts
  and the operation ids (desktop 1440×900, mobile 390×844); every committed reference image stays
  0-diff (no visual gate scene is added).
- Tests: unit suite for centre/grid start, cascade offset 32 px right and down, attempt cap of ten,
  overlap avoidance against visible objects only, clamping into the visible area, determinism with
  different zoom levels, and the five-add integration giving five non-overlapping positions;
  `cpp-unit` regression. `.changes/P4-19-<short-name>.md` (area `engine`, kind `minor`);
  `docs/engine.md` documents the placement rule and the create path.

## Specifications

- Values only from tokens: 16 px grid, 32 px cascade, visible bounds from the camera/viewport; no raw
  values.
- The placement is a pure function of its inputs: same view, objects and size → same position.
- The visible area is the camera's world bounds; a position must never be outside it, and the
  candidate must keep the object's full size inside (clamp, then snap to the grid).
- Ten attempts maximum, documented; no unbounded search and no random offset.
- One create = one operation with inverse (AD-1); the create builders fill board id and timestamps.
- No new token, dependency or contract change; a missing value becomes an open question.

## Pitfalls

- Clamping after snapping can land off grid; clamp to the visible bounds, then snap inward.
- Counting invisible objects as occupied places new cards nowhere; only visible objects block.
- A cascade that grows without bound must stop at ten attempts.
- Zoom changes the visible world bounds; the result must still be on the grid.
- The fifth add must not land on the fourth: test the integration, not only the pure function.
