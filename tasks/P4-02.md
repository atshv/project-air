# P4-02 — Engine playground: interactive sample board and stage shell

## Goal

The playground shows a deterministic sample board of 500 cards, 50 zones and blocks with pan and
zoom, an object and FPS HUD, and a shared scene fixture for the perf and visual harnesses;
ADR-0009 records the canvas text and overlay strategy.

**Why:** engine-core needs one visible, reproducible board surface for demonstration, measurement
and reference images; the perf gate, the visual gate and the stage showcase all reuse it.

**Satisfies:** D10

## Scope

- `packages/test-kit/`: first real package content — `package.json` (`@project-air/test-kit`,
  private, scripts `build`, `typecheck`, `lint`, `test`), `tsconfig.json` extending the root base,
  and `src/scenes.ts` with deterministic builders: the sample board (500 note cards, 50 zones with
  contained blocks, tone variety, world bounds) and a stress scene (N objects, default 10,000). A
  seeded PRNG keeps every run identical; scenes are plain engine rectangles with ids, geometry, tone
  and layer plus metadata. A `node --test` suite proves determinism and the 500/50/10,000 counts.
- `apps/engine-playground/`: load a scene by query (`?scene=sample`, `?scene=stress`), draw it,
  support pointer-drag pan and wheel/pinch zoom basic handling for the demo (L15 refines the exact
  trackpad behaviour later), and show a HUD with object count, visible count, FPS and active backend;
  keep the existing benchmark query parameters working for `perf-baseline`.
- `docs/adr/ADR-0009-canvas-text-and-overlay.md`: it was written with the stage plan; confirm it and
  refine it only if the implementation forces a change (document the deviation and consequences).
- Evidence: serve on the worktree slot port; capture desktop and mobile screenshots plus a log with
  commands, statuses and counts under `reviews/evidence/`.
- `.changes/P4-02-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Text rendering itself, gestures, selection, snapping, resize, undo, WebGPU (later stage tasks).
- Real board data or a server; contract schema changes; new dependencies; changing the perf or
  visual harness thresholds (P4-03/P4-04 own those).

## Acceptance

A1 WHEN the playground opens with `?scene=sample`, THEN it renders exactly 500 cards and 50 zones on
the token background, the HUD shows counts and FPS, and pan/zoom move the view without changing the
data.
A2 WHEN the scene builder runs twice on any machine, THEN it returns identical objects, ids and
world bounds, and the test suite proves the deterministic counts and the stress scene (10,000).
A3 WHEN ADR-0009 is read, THEN it decides text, overlay and image strategy for engine-core with
alternatives and consequences, and `docs/engine.md` documents scenes, hook and query parameters.
A4 WHEN the task is done, THEN `board-check`, `boundaries`, `design-check` and `unit` exit 0 with
records committed, and the desktop/mobile screenshots plus the serve log are under
`reviews/evidence/P4-02-*`.

## Specifications

- Scenes are deterministic pure functions of their arguments: no `Math.random`, no `Date`, no
  locale-dependent formatting. Ids are short stable strings (`card-0001`, `zone-0001`), not contract
  UUIDs; the contract fixture layer comes later.
- The sample board must look like a real board, not a grid: zones of different sizes, cards of
  different heights, blocks inside zones, deliberate overlap for layer order, objects near the world
  edge; keep the world inside the camera's fit clamp.
- The playground stays a static page (no bundler): importmap entries for engine and test-kit, values
  only from `tokens.css`, no external fonts, CDNs or images.
- Keep the benchmark mode `?bench=50000&samples=600&warmup=120` with `window.__engineBenchmark` and
  the `PERF_RESULT` line unchanged (P2-04 evidence depends on it), and add a deterministic ready hook
  (`window.__enginePlayground.ready`) so harnesses can wait instead of sleeping.
- ADR-0009 is short (300–600 words) and in the project's ADR shape: date, status accepted,
  supersedes, context, decision, consequences, alternatives.

## Pitfalls

- The screenshot tool launches Chrome; if the session sandbox refuses it, record the exact error and
  request a wider one-shot approval — never commit a screenshot from a different build or port.
- Do not let the HUD update at 60 Hz cause layout work that pollutes perf numbers; update text once
  per second like the current FPS counter.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command. If the test-kit
  build path differs, document the real importmap path in `docs/engine.md`.

## Edge cases

- Scene counts at 0 and the maximum document size (50,000) stay valid.
- The sample board must fit at the camera's minimum zoom on 1440×900; state a clamped zoom. Mobile:
  no overflow, HUD readable, canvas keeps its aspect.
