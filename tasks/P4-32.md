# P4-32 — Engine follows contract 0.3.0

> Engine maintenance. Found in P0-38 (2026-10-28); owner go-ahead "Yes, fix it", including the two
> test expectations.

## Goal

The engine builds and its unit tests pass again on main. P5-01 raised the contract to 0.3.0 and
regenerated `packages/contracts/generated/contract.h` (`kContractVersion = "0.3.0"`). Its commit
lists `packages/engine/` among the contract follow-ups, but three places in the engine still pin
0.2.0:

1. **Compile-time check** — `packages/engine/src/engine.cpp` asserts
   `kContractVersion == "0.2.0"` in a `static_assert`, so every engine target (native and WASM)
   fails to compile. It becomes 0.3.0, with the same message pattern.
2. **Unit checks** — `packages/engine/test/engine_test.cpp` and
   `packages/engine/test/engine_core_test.cpp` each expect the generated version to be 0.2.0. Both
   expectations become 0.3.0 (owner-approved test change, recorded in the review). No other test
   changes.
3. **Test support message** — the validation message in `packages/engine/test/support.mjs` and the
   header comment of `packages/engine/test/layers.test.mjs` name the contract version the
   operations are validated against; they say 0.3.0.

Nothing else in the engine depends on the version. Contract 0.3.0 only changes the sync protocol: an
optional `contractVersion` in hello, the welcome echo, and the serverSeq and snapshot reference
rules. The board-content, operation and reorder schemas that the engine consumes are unchanged.
The engine docs' history notes ("contract 0.2.0, P4-25" for `reorder`, zones as containers) stay,
because they name the version that introduced those features.

**Why:** a red `cpp-unit` on main hides every later engine regression, and `wasm-build` cannot
produce the module the playground and the visual gate load. Fixing it is the engine's part of P5-01's
contract follow-ups.

**Satisfies:** D10
