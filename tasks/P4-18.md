# P4-18 — Auto-pan (L16)

## Goal

While an object or selection is dragged into the 48 px edge zone the view scrolls along without a
jump, the drag continues beyond the visible area, and no auto-pan happens without a drag.

**Why:** L16 — an object must be draggable past the visible edge without letting go, and the view
motion must stay calm and tied to the drag.

**Satisfies:** D10

## Scope

- `packages/engine/` auto-pan policy as a pure, testable function: given the pointer position, the
  viewport, the active drag state and a time delta, return the camera pan delta (0 outside the
  `tokens::space_48` edge band). The speed ramps from 0 at the band's inner edge to a bounded maximum
  at the viewport edge (no jump at the boundary, no unbounded acceleration), the direction follows
  the pointer relative to the viewport, and the result is 0 when nothing is dragged.
- `packages/engine/` input integration: while a drag is active (single object or multi-selection),
  one request-animation-frame loop calls the policy and pans the camera through the existing
  view-only callback; the drag preview is recomputed against the updated camera so the grabbed world
  point stays under the pointer and the object keeps following beyond the visible area. The loop
  starts only with a drag, stops on release, cancel, lost capture or pointer leaving the window, and
  never writes the document — the release still commits exactly one move/group operation with its
  inverse through the P4-05 seam.
- `packages/engine/` no regressions: pan/zoom by pointer/wheel/pinch stays unchanged; auto-pan does
  not run during a plain pan, a resize (P4-17 owns its own edge behaviour), or when the pointer is
  outside the edge band; the world coordinates of the committed move are the pointer-derived
  position at release.
- `apps/engine-playground/`: a demo/capture that starts a drag near the edge, pans until the object
  is beyond the visible area and releases; a deterministic capture record under `reviews/evidence/`
  records the camera pan per frame, the drag position and the single committed operation
  (desktop 1440×900, mobile 390×844); every committed reference image stays 0-diff.
- Tests: pure policy tests (outside band = 0, ramp monotonic and bounded, direction per edge/corner,
  no drag = 0, max speed clamp), integration tests with a fake camera/clock (camera pans, preview
  follows, loop stops on release/cancel, exactly one operation on release), `cpp-unit` regression.
  `.changes/P4-18-<short-name>.md` (area `engine`, kind `minor`); `docs/engine.md` documents the edge
  band, ramp, loop lifecycle and the one-operation release.

## Out of scope

- Touch auto-pan (hardening), auto-pan for resize (P4-17), viewport persistence (P4-22), new visual
  baselines, contract/database changes, new dependencies, changed or deleted tests.

## Acceptance

A1 WHEN an object or selection is dragged into the 48 px edge band, THEN the view pans along without
a jump while the drag continues beyond the visible area, and the release still commits exactly one
move/group operation; the capture record proves the pan and the single operation.
A2 WHEN nothing is dragged, or the pointer is outside the band, or the drag is cancelled, THEN no
auto-pan runs; unit tests cover the policy and the loop lifecycle, and `board-check`, `boundaries`
and `cpp-unit` pass with records.

## Specifications

- Values only from tokens: the 48 px band is `tokens::space_48`; no raw values for the band, the
  ramp or the camera clamp (the camera range and zoom clamp already exist).
- The pan is view-only (AD-2): the engine working copy is never written by the loop; the drag preview
  is presentation state.
- One gesture = one operation (AD-1): auto-pan adds no operation and does not split the drag.
- Time-based ramp: the same time delta gives the same pan on every frame (deterministic in tests
  with an injected clock), and the loop stops cleanly (no leaked animation frame).
- No new token, dependency or contract change; if a value seems missing, record an open question.

## Pitfalls

- A jump on entering the band: the ramp must start at 0 at the band edge, not at the maximum.
- The grabbed point must stay under the pointer while the camera moves, or the object drifts behind
  the cursor.
- Starting the loop without a drag or restarting it twice leaks animation frames; test the lifecycle.
- A cancelled drag must restore the object and stop the pan without an operation.
- Do not add command-buffer instances or change the object pass: reference images stay 0-diff.
