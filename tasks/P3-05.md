# P3-05 — SDK, RLS tests and backend acceptance

## Goal

The typed SDK creates an account, workspace, board and note; the acceptance script proves a second
account sees nothing; `rls-tests` prove workspace isolation at the database level for the app role;
an ADR records the API and session model.

**Why:** this closes the backend-core exit criteria — SDK script, second account sees nothing and
green RLS tests.

**Satisfies:** D9

## Scope

- `packages/sdk/` (`@project-air/sdk`, ESM TypeScript, no dependency): `createClient({baseUrl,
  session})` with typed methods for workspaces, boards, notes and cards (list/get/create/update/
  delete), using the generated contract types and the API envelopes; typed `ApiError` with `code`,
  `messageKey` and `requestId`; unit tests against an in-process stub server.
- `services/platform/test/rls/*.test.mjs` — `rls-tests` as the restricted `app_user` role:
  - two accounts, two workspaces; account A sees only its rows (select/update/delete), account B
    sees nothing of A (including via joins and pagination), inserting into a foreign workspace
    fails;
  - no `BYPASSRLS`/`SUPERUSER`/ownership on `app_user`; `FORCE ROW LEVEL SECURITY` on every table;
  - missing `app.account_id` yields zero rows; a connection reused after a transaction does not
    inherit the previous account.
- `tools/dev/acceptance-backend.mjs` — self-contained stage acceptance: resets the slot database,
  migrates, boots `services/platform` + `services/auth` in process (test-session mode), then uses
  the SDK to 1) create account A (test session), 2) create workspace, board and note, 3) list them
  again, 4) create account B and prove lists are empty and get by id is `NOT_FOUND`; prints
  `PASS backend-core acceptance` and exits 0 on success.
- `docs/adr/ADR-0008-api-session-model.md` — API versioning (`/v1`), envelopes, cursor pagination,
  permission matrix, session handling (Kratos cookie validated by `services/auth`, test-session
  mode only in dev/test, `SET LOCAL app.account_id` per transaction, `app_user` + RLS as the second
  line of defence), and the limits of this stage.
- Update `docs/gates/postgres.md`/`docs/quality.md` only if a command/path changed; `docs/versions.md`
  gets no new dependency.
- `.changes/P3-05-sdk-rls-acceptance.md` (area `platform`, kind `minor`).

## Out of scope

- New API routes (P3-04), auth flows beyond the test mode, media/realtime, UI, OIDC/SDK codegen from
  OpenAPI, rate limiting implementation, CI changes.

## Acceptance

A1 WHEN the SDK is used, THEN it creates and lists workspaces, boards and notes with the contract
types and maps API errors to typed `ApiError` values.
A2 WHEN the RLS tests run as `app_user`, THEN account B sees nothing of account A, cross-workspace
writes fail and no bypass path exists.
A3 WHEN `node tools/dev/acceptance-backend.mjs` runs against a fresh slot, THEN it creates account,
workspace, board and note via the SDK and the second account sees nothing, printing `PASS`.
A4 WHEN `board-check`, `boundaries`, `unit` and `rls-tests` run, THEN all exit 0 with records
committed.

## Specifications

- SDK: one file per resource plus `client.ts`; no runtime dependency; `fetch` only; base URL and
  session injected; errors never swallow the request id.
- Acceptance script: read ports and database from `.polier-slot`, never hard-code; start/stop only
  its own servers; exit 2 with a clear message when the stack/env is missing; safe to rerun (reset).
- RLS tests: connect as `app_user` with the env connection string; use `SET LOCAL` inside
  transactions; assert with `count(*)` and direct `SELECT` calls; no dependency on API code.
- ADR-0008 follows the existing ADR shape (context, decision, consequences with binds/prevents,
  alternatives: session cookies vs JWT, `/v1` vs unversioned, RLS vs app-only checks).
- One commit, `.changes` entry, evidence records before the commit (base commit remains the parent).

## Pitfalls

- The acceptance script must not require a running Docker-managed app server beyond Postgres/Mailpit;
  it boots the Node services itself.
- A second account must get `NOT_FOUND` for foreign resources, not `FORBIDDEN`.
- RLS tests that run as the owner (`POSTGRES_USER`) prove nothing; assert the role name when
  connecting.
- The SDK must not deep-import generated files from another package path that boundaries forbid;
  `packages/sdk` may import `packages/contracts` only.
- `board-check` before any `pnpm` command; tests are exclusive on the `db` resource.

## Edge cases

- Empty results → `items: []`, `nextCursor: null`; unknown id → `NOT_FOUND`.
- Two sessions in one test: never share a pool connection across account switches without
  transaction boundaries.
- Re-running the acceptance script leaves a clean, migrated slot database.
- SDK call with no session → `AUTH_REQUIRED`, with an expired test session → 401.

## Gates

1. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0 (before any install).
2. `boundaries`: `python3 $POLIER/tools/boundaries.py .` → exit 0.
3. `unit`: `pnpm --filter ./packages/sdk test` → exit 0.
4. `rls-tests`: `node --test services/platform/test/rls/*.test.mjs` → exit 0, second account sees
   nothing.
