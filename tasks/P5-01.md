# P5-01 — Sync contract 0.3.0: settle the pre-realtime open points

## Goal

Close the four pre-realtime sync open points in one `0.3.0` contract bump: a single documented
version-negotiation rule (including the blueprint's per-message version), a fresh-board `serverSeq`
bootstrap of 1 with a from-0 catch-up fixture, an enforced `hello`-first rule, and validated
reconnect ordering plus `<boardId>:<serverSeq>` `snapshotRef`; valid and invalid fixtures, regenerated
TS/C++ codegen and updated docs.

**Why:** `docs/contracts.md` lists these points as "settle before realtime/SDK"; P5-02…P5-04 build
their wire semantics on this frozen contract.

**Satisfies:** D11

## Scope

- `packages/contracts/` sync schema: decide and implement the version-negotiation rule required by
  the blueprint §5.1 (`contractVersion` on every message, or a documented, tested alternative) and
  document the decision in `docs/contracts.md`; keep the existing once-per-connection `hello`/`welcome`
  negotiation coherent with it.
- `packages/contracts/` `serverSeq` bootstrap: a fresh board starts at 1, `fromServerSeq: 0` names the
  empty catch-up case, and `snapshotRef` must be exactly `<boardId>:<serverSeq>`; add fixtures for both
  the valid and the invalid (`0` on `welcome`, mismatched board id, non-positive snapshot sequence)
  forms.
- `packages/contracts/` `hello`-first and reconnect ordering: the first client message must be
  `hello`, reconnect must send `resyncRequest` only after `joinBoard`, and the session test/corpus
  enforces both with problem fixtures instead of prose.
- `packages/contracts/` the 0.3.0 bump in the same task: `board.contracts[].version`, every schema
  `$id`, the root `contractVersion`, the fixtures-gate corpora (valid and invalid), regenerated TS and
  C++ codegen kept identical, and the dependant packages updated where the type changed.
- `docs/contracts.md`: the four decisions, the exact rules, the new 0.3.0 tag note and the fixtures
  that pin them; `.changes/P5-01-<short-name>.md` (area `contracts`, kind `minor`).

## Out of scope

- Implementing the sync service or CRDT documents (P5-02+), new message types beyond the open points,
  auth/session changes (ADR-0008 is settled), any protocol change that is not one of the four points,
  new dependencies.

## Acceptance

A1 WHEN the 0.3.0 sync contract is checked, THEN the version-negotiation rule is documented, enforced
by fixtures and implemented in the schema, and a client/server pair that skips it is rejected.
A2 WHEN a message carries `serverSeq`/`snapshotRef` or the connection is a reconnect, THEN a fresh
board starts at 1, `fromServerSeq: 0` is the empty catch-up, `snapshotRef` must equal
`<boardId>:<serverSeq>`, `hello` comes first and `resyncRequest` follows `joinBoard` — each rule has a
valid and an invalid fixture.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `contracts`, `codegen` and `unit` exit 0
with records, the version is bumped consistently (board, schema ids, root version), the regenerated
TS/C++ code is identical, and `docs/contracts.md` documents the decisions.

## Specifications

- Contract procedure in the same task: bump `board.contracts[].version`, every schema `$id` and the
  root `contractVersion`; regenerate TS + C++ and keep parity; run the `contracts` and `codegen`
  gates.
- Every new rule needs a valid and an invalid fixture in the fixtures-gate corpus, not only prose;
  the sync session test must actually enforce `hello`-first and the reconnect order.
- Keep the 0.2.0 content and operation semantics unchanged; only the four named points change.
- `contracts.py check`'s base-branch classification is conservative: a new payload with required
  fields lives in its own schema file; if a rule cannot be additive, document it and bump as the
  procedure requires.
- No new dependency; no service or engine code change beyond the regenerated contract headers/types.

## Pitfalls

- A per-message `contractVersion` is a breaking addition; if the schema cannot stay backward
  compatible, that is exactly what the 0.3.0 bump is for — do not silently weaken the rule.
- The fixtures-gate corpora and the sync session test are separate; update both.
- `codegen` compares generated files: run it and commit the regenerated output in the same task.
- `serverSeq: 0` is meaningful only for `fromServerSeq`; accepting it on `welcome`/`snapshotRef` is
  the bug the fixture must catch.
- Do not break the ADR-0008 `requestId`/`?requestId=` transport while touching the sync messages.

## Gates

1. `board-check`: `python3 $POLIER/tools/check.py .` -> exit 0.

5. `unit`: `pnpm test --affected` -> exit 0.
