# P4-14 — Dragging versus editing (L03)

## Goal

Pointer input separates click, drag and edit: a press moving less than 4 px is a click and writes
nothing; a note card drags on its whole body, a block or zone only on its 40 px header; presses in
fields, buttons, selects, editable and scrollable areas never drag; grips show `grab`/`grabbing`;
block and zone headers show their `--faint` hover surface after 120 ms; every completed drag commits
exactly one move operation with inverse through the P4-05 seam. The engine input layer owns the
policy; the playground consumes it.

**Why:** every later gesture — selection, snapping, resize, zone membership, the overlay editor —
starts from the same press/drag decision.

**Satisfies:** D10

## Scope

- `packages/engine/` new input module under `src/bridge/` (for example `input.ts`): one pointer state
  machine over the bridge API (hit test, document slots) replacing the playground's ad hoc pointer
  code. It owns the 4 px screen threshold (`tokens::drag_threshold`), the grip policy (cards: whole
  rectangle; blocks and zones: only the `tokens::header_height` band), pointer capture and
  `pointercancel`, right-button/multi-touch rejection, and the conversion of a completed drag into one
  `drag-single` gesture built with `buildOperation` on the `DocumentPort` and pushed onto the P4-05
  history; a release below the threshold writes nothing.
- `packages/engine/` suppression policy: `input`, `textarea`, `select`, `button`, `[contenteditable]`,
  `[data-field]` and elements whose computed overflow scrolls never start a drag and keep their own
  pointer/wheel handling.
- `packages/engine/` header hover surface: blocks and zones show a `tokens::faint` band (DOM chrome
  per ADR-0009, opacity/transform only, 120 ms per design rule §7) while hovered; not a canvas glyph,
  no icon. Cursors and the surface are presentation state, never document state.
- `apps/engine-playground/`: replace the demo's pointer pan/zoom with the input layer, keep pan/zoom
  view-only, and demonstrate on the sample and `?scene=layers` scenes that card body, block header and
  zone header drag move one object as one operation while a block/zone body below the header, a field
  and a scroll area do nothing. Rebuild bridge and WASM.
- Tests: TypeScript suite for the state machine (threshold at 3.9/4.1 px, click writes nothing, grip
  policy per kind, field/scroll suppression, cursor mapping, hover timing, one operation per drag,
  cancel restores) plus the `cpp-unit` regression. No new visual baseline: every committed image
  stays 0-diff because input state is invisible at rest.
- `docs/engine.md`; `.changes/P4-14-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Snapping (P4-15), multi-selection (P4-16), resize (P4-17), auto-pan (P4-18), keyboard and context
  menu (P4-20), zone membership (P4-27), the DOM editor overlay (P4-23), text editing, contract

## Acceptance

A1 WHEN the pointer moves less than 4 px and is released, THEN no drag starts and no position
operation is written (no `DocumentPort` write, no history entry); a drag that crosses the threshold
starts exactly once.
A2 WHEN a note card body, a block header or a zone header is dragged, THEN exactly one move operation
with its inverse is committed on release and the object follows the pointer 1:1; dragging a block or
zone body below its 40 px header moves nothing. Unit tests and the playground confirm each case.
A3 WHEN a press starts inside a field, button, select, editable area or scrollable area, THEN no drag
starts and the element keeps its own pointer/wheel handling; grips show `grab`/`grabbing`, other
surfaces `default`, fields `text`; the block/zone header shows its `--faint` hover surface after
120 ms. Unit tests and the playground confirm it.
A4 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `visual` and `unit` exit 0
with records under `reviews/evidence/`, every committed reference image is 0-diff, and
`docs/engine.md` describes the separation.

## Specifications

- Numbers only from tokens: 4 px threshold, 40 px header, 120 ms hover, `--faint`/`--accent`; no raw
  values (design-check).
- The threshold is screen px; seam positions are world px; grid/snap values belong to P4-15.
- One gesture = one operation (AD-1); no direct document writes, and a cancelled drag leaves nothing.
- No second pointer handler in the playground; pan/zoom stay view-only (`setCamera`).
- Hover surface and cursors are DOM/presentation (ADR-0009), never document state or canvas glyphs.

## Pitfalls

- Move the playground's pointer code into the input layer; two handlers would pan while dragging.
- Visual captures run without a pointer; keep hover chrome and cursors out of the at-rest frame, or
  every baseline drifts.
- Release the pointer capture on `pointercancel`, `lostpointercapture` and blur; a stuck capture
  breaks later gestures.
- Rebuild bridge and WASM before the visual gate; run `board-check` before any `pnpm` command.
