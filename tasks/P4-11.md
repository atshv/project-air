# P4-11 — WebGPU render pipeline behind the command buffer

## Goal

A WebGPU module renders the existing 24-byte command buffer with one instanced draw: WGSL
pipeline/shader, instance-buffer upload, the same tone/layer handling and draw order as WebGL2,
resize and clear, plus native stubs. No second data path: the core's command buffer is the only
input.

**Why:** owner decision `Q19` — WebGL2 stays the measured default, WebGPU is the second backend with
fallback and a two-backend image comparison; P4-11 is the pipeline P4-12 selects and P4-13 compares.

**Satisfies:** D10

## Scope

- `packages/engine/` a WebGPU module next to the WebGL2 one (`src/render_webgpu.cpp`,
  `include/engine/render_webgpu.h`): create through the existing canvas selector; one WGSL
  vertex/fragment program consuming the 24-byte `Instance` layout as instance attributes
  (`x,y,w,h` floats; `tone`, `layer` uints), the same top-left screen space, `toneColor()` mapping
  and draw order, one `draw(instanceCount)` per frame. WebGPU is browser-only, so the C++ module
  calls a small JS helper (Emscripten `EM_JS`/`--js-library`); C++ still owns the frame decision and
  the buffer bytes.
- `packages/engine/` instance upload: `CommandBuffer` bytes into one reused `GPUBuffer` (bounded
  growth, no per-object JS call), clear to `tokens::canvas`, resize/reconfigure on the recorded CSS
  size and DPR, `tokens::card`/tone colours and design layers unchanged, no raw values.
- `packages/engine/` C ABI: new exported WebGPU entry points (for example `engine_create_webgpu` and
  a frame call) in the WebGL2 style; the existing WebGL2 entry points keep their behaviour. Backend
  selection/fallback/HUD are P4-12/P4-13.
- `packages/engine/` native build: stubs for every new entry point failing cleanly with
  `engine_last_error` and keeping the native suites green; `wasm-smoke` covers the new failure paths
  (create without a WebGPU canvas, frame before create) and the export/JS-library wiring.
- `wasm-build`/`wasm-size` stay green with the module and shader string inside the 300 KiB gzip
  budget; Emscripten flags change only as far as the JS helper needs.
- Tests: native stub tests (create/frame/resize fail cleanly without Emscripten), unchanged
  command-buffer determinism, and an optional browser smoke (extra evidence, not a board gate) that a
  WebGPU frame renders the layers scene without errors, recorded under `reviews/evidence/`.
- `docs/engine.md`: the WebGPU module, the shared command-buffer seam, shader/pipeline/instance
  buffer, and the note that backend selection/fallback (P4-12) and the switch/comparison (P4-13) are
  separate tasks. `.changes/P4-11-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Backend selection, capability detection and fallback (P4-12); playground switch, HUD backend name
  and two-backend visual comparison (P4-13); porting the glyph/atlas and chrome passes (P4-13 needs
  them for an honest two-backend comparison); new dependencies; changed or deleted tests; contract
  changes.

## Acceptance

A1 WHEN a WebGPU adapter/device is available, THEN the module renders the existing 24-byte command
buffer with one instanced draw, the same tone/token colours and draw order and the same top-left
screen geometry as WebGL2, with no second data path or per-object JS call.
A2 WHEN WebGPU is unavailable or the build is native, THEN the module fails cleanly with
`engine_last_error` (no crash), the native stubs keep `cpp-unit` green, and the WASM export list and
`wasm-smoke` cover the new entry points and failure paths.

## Specifications

- One command buffer, one pipeline, one instanced draw: no recomputed culling, sorting or colours.
- Values only from tokens (`canvas`, `card`, tone colours, layer order); no raw colours/sizes in the
  module or WGSL.
- Native stubs mirror WebGL2: no browser API at compile time, clean `engine_last_error` failure.
- Keep WebGL2 byte-identical (its reference images must stay 0-diff); the smoke and browser harnesses
  keep working.
- No dependency; Emscripten 6.0.13 and CMake 4.4.4 stay pinned.

## Pitfalls

- WebGPU is asynchronous: the create call must block the first frame until ready or fail cleanly,
  never render with a partial device.
- A second WGSL palette copy drifts from `tokens.h`; generate or pass it.
- The mixed float/uint 24-byte layout renders garbage without an error if mismatched; assert the
  stride.
- A JS library changes WASM/JS sizes; rerun `wasm-build`/`wasm-size` after each flag change.
- Never restructure the WebGL2 path in a way that changes its bytes; its visual gate is the proof.
