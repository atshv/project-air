# P0-26 — Toolbar and zone with notepad and image window in the preview

> **Size:** 400–900 words. UI task in the design preview (`apps/web/preview/`), not the product.

## Goal

The live preview demo gets a top-centre floating **toolbar** and a static **zone** containing a
notepad and a small image window with the owner-provided photo; masthead, README and screenshots
are updated in the same task (demo cadence).

**Why:** the owner asked for a visible design step; toolbar and zone/content composition are part
of the canvas design language.

**Satisfies:** D3

| --- | --- | --- | --- |
| Toolbar container | top/centre, surface, 1 px border, pill radius, shadow, padding 8, gap 4 | `var(--space-12)`, `var(--surface)`, `var(--border)`, `var(--radius-pill)`, `var(--shadow)`, `var(--space-8)`, `var(--space-4)` |
| Tool button | 36 × 36, medium radius, 20 px icon; rest muted / hover faint+fg / active accent-soft+accent | `var(--icon-bar)`, `var(--radius-md)`, `var(--muted)`, `var(--faint)`, `var(--fg)`, `var(--accent-soft)`, `var(--accent)` |

## Pitfalls

- `board-check` before any `pnpm` command; `design-check` rejects raw colours/off-grid spacing/
  numeric z-index.
- Write the `.changes` entry before stamping the masthead time.
- Keep the cards' home positions (4 %/5 %, 90 %/90 %) and the zoom pill clear; toolbar/zone must not
  capture card pointer/keyboard events.
- The image is local (relative path, no remote URL/data URI). Do not edit `CHANGELOG.md`,
  `STATUS.md` or `board.json`.

## Edge cases

- 390×844: toolbar fits or scrolls inside the demo without page overflow; zone readable.
- Missing image asset: bordered placeholder, no broken-icon layout shift.
- Tab order reaches toolbar, cards and zoom buttons; focus outline visible on the dark surface.
