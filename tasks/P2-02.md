# P2-02 — Engine core model and render command buffer

## Goal

The C++20 core holds up to 50,000 rectangles in flat arrays, applies the camera transform and emits
a deterministic instanced render command buffer; native unit tests cover the model, ordering and
determinism without a GPU.

**Why:** the WebGL2 renderer and the performance baseline consume this core; it keeps the engine a
working copy that never talks to the network (AD-2) and drives rendering from one command buffer
instead of per-object JS calls.

**Satisfies:** D8

## Scope

- `packages/engine/` C++ modules (header + source per module, names final in this task):
  - `doc` — flat arrays of rectangles (`x`, `y`, `width`, `height`, fractional-index `z`, tone
    reference), no per-object heap allocation per frame, `reserve(50_000)`.
  - `camera` — pan/zoom as a 2D affine transform, world↔screen conversion, visible bounds; 16 px
    canvas grid constants from the design tokens.
  - `spatial` — uniform grid or sorted-axis index to cull rectangles outside the visible bounds.
  - `render` — a command buffer of instance records (screen-space quad + tone) in stable draw order;
    two identical documents produce byte-identical buffers.
- Use only what the contract and ui-kit generate: include `contract.h` (entity/operation types where
  relevant, `kContractVersion`) and `tokens.h` (colours/spacing values); no hard-coded visual values
  (AD-7) and no network/database code (AD-2).
- Native CTest unit tests under `packages/engine/test/` (`engine_core_test.cpp` + support):
  - camera round-trip and bounds, including zoom extremes;
  - culling keeps exactly the visible rectangles and stable order;
  - determinism: generating a 50,000-rectangle command buffer twice yields identical bytes;
  - performance sanity: one 50,000-rectangle command buffer is generated within a generous native
    bound (e.g. 100 ms) so the CPU side cannot be O(n²) silently;
  - empty document, overlapping rectangles, camera outside the content.
- No GPU code in this task; the command buffer is renderer-agnostic. No new dependencies.
- `.changes/P2-02-engine-core.md` (area `engine`, kind `minor`).

## Specifications

- Flat data layout: struct-of-arrays or one `std::vector<Rectangle>`; ids as strings are allowed for
  the spike, but no per-frame allocation or map lookups in the hot loop.
- Fractional `z` ordering: sort by the contract's fractional index string; equal indices keep
  insertion order.
- Camera: `u = (x - camX) * zoom`, `v = (y - camY) * zoom` family of transforms; document the exact
  convention in the header comments. Zoom clamps (e.g. 0.1–8) are spike values, not final UI.
- Command buffer: allocate once, `clear()` + `reserve()`, no growth after warm-up; instance record
  layout is documented for the WebGL2 renderer (P2-03) and must be reused unchanged there.
- Errors: return `air::engine::Status`/`bool` with a reason string; no exceptions across the bridge.
- Tests are C++/CTest only; no new libraries.

## Pitfalls

- Do not implement rendering or GL in this task; the command buffer is the seam.
- `-Wall -Wextra -Wpedantic -Werror` in both native and Emscripten builds: fix warnings.
- Do not copy token values into headers; include `tokens.h` and use its constants.
- Keep the 50,000-rectangle test fast enough for `cpp-unit` (target < 1 s, hard cap 5 s).
- `board-check` before any `pnpm` command; the engine has no npm dependency to add.

## Edge cases

- Empty document, single rectangle, all rectangles outside the viewport, identical z indices.
- Extreme zoom and negative/very large world coordinates (clamping must not crash).
- `float` vs `double`: choose `float` for instance data (documented) and keep camera math stable.
