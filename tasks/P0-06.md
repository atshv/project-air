# P0-06 — Per-slot dev setup and teardown

## Goal

Each worktree gets its own database and bucket from `.polier-slot` through `tools/dev/setup` and
`tools/dev/teardown`; slot 0 is never touched; one command each.

**Why:** parallel test runs must never collide (AD-9); backend, media and auth tasks need their own
slot database and bucket.

**Satisfies:** D2

## Scope

- `tools/dev/setup`, `tools/dev/teardown` (executable; runnable as `bash tools/dev/setup` because
  the `dev-setup` gate uses that form), `tools/dev/README.md`, and the `## Commands` section of
  `tools/dev/ARCHITECTURE.md`.
- Read every runtime value from `.polier-slot` in the worktree root (slot number `N`, ports,
  `db_name`, `bucket`; inspect it with `python3 $POLIER/tools/slot.py show`). Never hard-code a
  port, database name or bucket name.
- `setup`: ensure the shared compose stack from `infra/compose/` is running (idempotent
  `docker compose -f infra/compose/compose.yaml up -d --wait`), then create the slot database and
  the slot bucket. Use only tools inside the containers (`docker compose exec -T postgres psql`,
  SeaweedFS `weed shell` or its S3 API) — no host `psql`/`aws`/`minio` client, no new dependency.
  Idempotent: a second run must not fail.
- `teardown`: drop the slot database and bucket idempotently; **refuse slot 0** with a clear
  message and change nothing; never run `docker compose down -v`; never touch another slot's data.
- `tools/dev/README.md`: setup and teardown usage, the slot-0 safety rule, the note that the
  shared stack is started but never stopped by these scripts.

## Out of scope

- Compose definitions (`P0-07`), migrations beyond an empty database, seed application data, app
  code, CI.
- Any change outside `tools/dev/`.

## Acceptance

A1 WHEN `bash tools/dev/setup` runs in a worktree with a `.polier-slot` for slot N, THEN the
database named in the slot file exists and the bucket exists, exit 0; a second run exits 0
(idempotent).
A2 WHEN `bash tools/dev/teardown` runs for slot N, THEN the slot database and bucket are gone and
exit 0; with slot 0 it refuses with a non-zero exit and changes nothing.
A3 WHEN the scripts are inspected, THEN no port, database name or bucket name is hard-coded; all
values come from `.polier-slot`, and two different slots yield different names.
A4 WHEN `python3 $POLIER/tools/gate.py --task P0-06 --name dev-setup --shell "python3 $POLIER/tools/slot.py acquire && bash tools/dev/setup"` runs, THEN it exits 0; `python3 $POLIER/tools/check.py .` exits 0 (run it before `pnpm install`); both gate records are committed.

## Specifications

- **Language:** bash with `set -euo pipefail` plus Python 3 stdlib for JSON parsing (no Node
  dependency needed); both files executable.
- **Slot file:** `.polier-slot` is a JSON object written by `tools/slot.py acquire`; read its keys
  in the scripts and fail with a clear message when it is missing.
- **PostgreSQL:** read the container user from the compose environment (`docker compose exec -T
  postgres sh -c 'psql -U "$POSTGRES_USER" -d postgres ...'`), never print passwords.
- **S3 bucket:** create/delete through the SeaweedFS container (`weed shell`); verify the bucket
  listing before/after.
- **Gate command:** report the exact `dev-setup` command you used; the lead keeps
  `docs/quality.md` in sync.
- **Evidence:** commit the `dev-setup` gate record and a short manual log with the created and
  removed database/bucket names (no values) and the slot-0 refusal in `reviews/evidence/`.

## Pitfalls

- The compose stack is shared by all worktrees: start it if needed, but never `down -v`, never
  drop another slot's database or bucket, and never touch slot 0's data.
- The gate runs `slot.py acquire` first; in your worktree the slot already exists, so it is reused.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm install` (this task does not
  need one).
- Quote every variable; a slot with spaces in the worktree path must still work.

## Edge cases

- Stack not running → `setup` starts it and waits for healthy; a failing service is an `infra`
  result, not a code failure.
- Database/bucket already exists → keep it and exit 0 (idempotent), do not drop it.
- `.polier-slot` missing or slot 0 → clear error, non-zero exit, nothing changed.

## Gates

1. `dev-setup`: `python3 $POLIER/tools/gate.py --task P0-06 --name dev-setup --shell "python3 $POLIER/tools/slot.py acquire && bash tools/dev/setup"` → exit 0.
2. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0.
