# P4-13 — WebGPU switch and two-backend image comparison

## Goal

The playground switches between WebGL2 and WebGPU by query parameter with automatic fallback, the HUD
names the active backend and renderer, and the visual gate compares both backends at both viewports;
docs and ADR-0006 record switch, fallback and the two reference sets.

**Why:** owner decision `Q19` — WebGPU is the second backend with fallback and a two-backend image
comparison; P4-13 closes the `visual-final` two-backend gap.

**Satisfies:** D10

## Scope

- `apps/engine-playground/`: `?backend=webgl2|webgpu` (default WebGL2, the measured backend) using
  P4-12 selection; automatic fallback with the reason in the HUD and `getState()`; the HUD names the
  backend and renderer/adapter; unknown values fail closed, never silent.
- `packages/engine/` WebGPU parity: the WebGPU path renders what the scenes contain — objects, the
  chrome pass (header bands/rules, guides, selection frames, zone highlights) and the glyph/text
  pass (atlas texture + sampler, same placements/palette) — same command buffers/layouts and token
  palette, no second data path.
- `packages/engine/test/visual/run-visual.mjs`: capture every scene at both viewports for **both**
  backends; per-backend set `<scene>-<viewport>-<backend>.png`; commit the 28 new `-webgpu`
  baselines through the reviewed `--update` path; the renderer check stays fail-closed and gains the
  WebGPU rule (adapter positively identified as real GPU, e.g. vendor `apple`/architecture
  `metal*`; software/unknown/missing → `infra`, never a pass); the capture record stores backend,
  renderer/adapter, per-capture diff and a cross-backend comparison with documented numbers and
  tolerance, approved in review.
- `docs/gates/visual-diff.md`: backend list, both reference sets, capture-record fields, the WebGPU
  fail-closed rule, the Baseline history; `docs/engine.md`: switch, fallback, HUD naming, WebGPU
  passes; ADR-0006 consequences (WebGPU implemented behind the same command buffer, with fallback);
  `.changes/P4-13-<short-name>.md` (area `engine`, kind `minor`).
- Tests: backend/renderer selection visible in `getState()` under both backends; the fallback path
  with a forced-unavailable probe (fake or query hook) reports the reason and renders WebGL2; the
  WebGPU renderer identification is exercised in the harness; existing WebGL2 images stay 0-diff.

## Out of scope

- WebGPU-specific performance claims (webgpu is not the measured default; `perf` stays WebGL2),
  backend selection internals (P4-12), new scenes, a WebGPU-only showcase, new dependencies, changed
  or deleted tests, contract/database changes.

## Acceptance

A1 WHEN `?backend=webgpu` is requested and WebGPU is available, THEN the playground renders with
WebGPU and the HUD/`getState()` name the backend and the adapter; WHEN WebGPU is unavailable, THEN
the page falls back to WebGL2 without crashing and shows the fallback reason; an invalid value fails
closed.
A2 WHEN the visual gate runs, THEN it captures every scene at both viewports for both backends, each
backend has its committed reference set and passes 0-diff, the WebGPU adapter is positively
identified (fail-closed against software/unknown), the cross-backend comparison is recorded with its
tolerance, and every existing WebGL2 image stays 0-diff.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `visual` and `design-check` exit 0 with
records under `reviews/evidence/`, and `docs/engine.md`, the ADR-0006 consequences and
`docs/gates/visual-diff.md` document the switch, fallback, backend naming and the two reference sets.

## Specifications

- Default backend stays WebGL2; `?backend=` switches only on request. The fallback is a runtime
  decision through P4-12, not a page-level try/catch hiding the reason.
- Baselines: per-backend exact match against that backend's own set; new images only via the
  reviewed `--update` path; never change an existing image. Cross-backend antialiasing differences
  are recorded with numbers and a reviewed tolerance, never claimed exact.
- Renderer policy: WebGL2 keeps the ANGLE/known-GPU rule; WebGPU requires a positively identified
  adapter and rejects software/unknown/missing as `infra`.
- WebGL2 output stays byte-identical (28 existing images 0-diff); WebGPU reuses the same buffers,
  palette and order.
- `visual` is exclusive: run alone; perf/idle stay WebGL2 and must keep passing.

## Pitfalls

- Missing text/chrome on WebGPU is a visual failure: port the glyph/chrome passes before claiming
  parity.
- A cross-backend diff accepted as "antialiasing" hides colour/order bugs; record and review numbers.
- A WebGPU adapter can be software or "unknown" in headless CI; fail closed.
- Switching backends must not leak the other renderer; test that only one is active.
- New baselines double the set; update Baseline history and the reference table in the same task.
