# P4-28 — L01 final proof, two-backend reference images and stage showcase

## Goal

The final L01 measurement proves 10,000 objects at 60 fps, the 500 cards + 50 zones proof under
50 ms, every enforced run within basis + 10 % and no offscreen rendering; the reference images are
green at both committed viewports; desktop and mobile showcase screenshots plus the stage handoff
are committed. This task produces the two stage-exit records `perf-final` and `visual-final`; the
earlier `perf`/`visual` records are task gates.

**Why:** stage 5 exits only on measured proof, not on task completion; P4-28 is that proof and the
demo-cadence showcase the owner sees.

**Satisfies:** D10

## Scope

- `packages/engine/` `perf-final`: run the L01 final proof on the committed basis — 10,000-object
  pan/zoom at p95 <= 16.7 ms with no frame interval above 16.7 ms, the 500 cards + 50 zones proof
  under 50 ms including the culling verification (at least 50 sampled cameras, 0 visible-set
  mismatches), every p50/p95/p99/mean within basis + 10 % — and commit the record under
  `reviews/evidence/`. The basis record is read-only; no budget is adjusted, no number dropped or
  rounded, and the real GPU is recorded.
- `packages/engine/` `visual-final`: run the full reference set at 1440×900 and 390×844, 0-diff, and
  commit the capture record. A WebGPU set is proven only if the WebGPU backend (P4-11 … P4-13) is
  actually merged; when it is not, record the missing two-backend part as an explicit open point in
  the record and in `docs/engine/` — never as a silent pass.
- `apps/engine-playground/`: a deterministic stage showcase state (for example `?scene=showcase`)
  that shows the engine-core capabilities — zones with titles and members, card titles and previews,
  selection chrome, sharp zoom — captured as desktop (1440×900) and mobile (390×844) screenshots
  under `reviews/evidence/`; the capture tool reports camera, counts and rendered frames.
- `docs/engine/`: the stage report and final measurement table (basis vs final, dates, paths, hardware);
  `docs/quality.md` updated only where the final gate behaviour changed; the stage handoff text.
- `.changes/P4-28-<short-name>.md` (area `engine`, kind `minor`). `reviews/evidence/` holds the
  `perf-final`/`visual-final` records and the showcase images.

## Out of scope

## Specifications

- The basis is read-only; the final proof compares against the committed basis, and every record
  carries date, hardware/browser/GPU, numbers and paths.
- `perf-final` and `visual-final` are exclusive browser gates: run them alone, never next to each
  other or any other Chrome gate.
- The showcase captures are deterministic (paused scheduler, hidden volatile HUD item, no
  animations) like the visual harness; no screenshot from an unreleased build.
- The room to report is the record: an unmet dependency or missing backend is an `open_question`, not
  a redefined acceptance.
- Values only from tokens in the showcase state; design-check must pass.

## Pitfalls

- Re-running the basis or editing it invalidates the comparison; never regenerate the basis here.
- A software renderer makes the run `infra`, not evidence; fail closed.
- Updating a reference image to make visual-final pass is forbidden; an unexpected diff is a bug.
- Claiming "two backends" from a WebGL2-only run is exactly the silent pass A2 forbids.
- Keep the showcase stable across runs; unstable captures are not evidence and cannot be committed.
