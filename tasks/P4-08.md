# P4-08 — Text atlas and glyph texture pipeline (L02)

## Goal

The engine renderer samples a runtime glyph atlas: the bridge rasterises the token font stack into an
RGBA texture, the C++ side uploads it, resolves glyph metrics and draws textured glyph quads; no font
file is bundled and native tests cover atlas upload, DPR-correct metrics, missing glyphs and the
texture-limit fallback.

**Why:** L02 needs text on the canvas. ADR-0009 decided a runtime atlas: the licence list forbids a
bundled OFL font, and the browser already renders the token system-font stack. P4-09 (layout,
ellipsis) and P4-10 (titles, visible quality) build on this pipeline.

**Satisfies:** D10

## Scope

- `packages/engine/` new module `text` (`include/engine/text.h`, `src/text.cpp`):
  - **Styles from tokens:** roles `title` (`font_sans`, `text_15`, `weight_semibold`) and `body`
    (`font_sans`, `text_13`, `weight_regular`) with `line_height`; the bridge reads them through the
    C ABI and composes the CSS `font` string.
  - **Atlas plan:** glyph count, CSS cell size, DPR and `MAX_TEXTURE_SIZE` give a power-of-two size,
    columns and a raster scale; the scale starts at the DPR and halves (floor 1) until it fits, else a
    `Status` failure.
  - **Glyph table:** validated upload of RGBA pixels and packed metrics (code point, atlas rect,
    bearing, advance in raster px), reported in CSS px; glyph 0 is the required placeholder that an
    unknown code point resolves to.
  - **Glyph buffer:** deterministic `GlyphInstance` records (screen quad + UV) from world-anchored
    runs placed by advance only, culled, reserved once.
- `render_gl`: RGBA texture upload per atlas build, one instanced glyph draw after the object pass,
  tinted with `tokens::fg`; new exported C ABI calls with native stubs.
- `src/bridge/engine.ts`: `buildTextAtlas()` rasterises ASCII, Latin-1 (umlauts) and the placeholder
  with OffscreenCanvas (fallback `<canvas>`), rebuilds on a DPR change; `addTextRun`/`clearTextRuns`.
- `apps/engine-playground/`: opt-in `?text=1` demo run; default scenes, baselines and perf unchanged.
- Tests: native cases for styles, plan/fallback, upload validation, DPR-equal CSS metrics, the
  placeholder, glyph-buffer determinism and culling; `wasm-smoke` checks the exports.
- `docs/engine.md` text section; `.changes/P4-08-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Line layout, wrapping, ellipsis, card titles bound to objects, title editing (P4-09/P4-10, L18).
- Zoom-bucket re-rasterisation (P4-10); the atlas is rebuilt on a DPR change only.
- Draw order/layers (P4-06, another session), WebGPU, the visual baseline update (P4-09 has `visual`).
- Contract changes, new dependencies, a bundled font file, changed or deleted tests.

## Acceptance

A1 WHEN the bridge builds the atlas, THEN the glyphs come from the token font stack via Canvas2D, the
C++ side validates and uploads the RGBA texture and metrics, and no font file exists in the repository
or bundle; native tests cover upload validation.
A2 WHEN the device pixel ratio is 1, 2 or 3, or the texture limit is too small, THEN glyph metrics in
CSS px stay equal across ratios, the planner halves the raster scale until it fits or fails with a
`Status`, and an unknown code point draws the placeholder; native tests confirm each case.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `wasm-build`, `wasm-size` and
`typecheck` exit 0 with records under `reviews/evidence/`, and `docs/engine.md` describes the
pipeline.

## Specifications

- Typography values come only from `tokens.h` (AD-7); the bridge composes the CSS font string from
  values returned by the C ABI.
- Metrics cross the C ABI as a packed float array; one call per atlas build, never one per glyph.
- The glyph pass is one program bind, one texture bind and one instanced draw; with no runs it draws
  nothing, so the perf gate's frame cost is unchanged.
- No exceptions across the C ABI: failures return 0/-1 and set `engine_last_error`.

## Pitfalls

- `measureText` boxes can be fractional or negative: round cells outward, keep 1 raster px padding.
- Premultiplied alpha: upload with `UNPACK_PREMULTIPLY_ALPHA_WEBGL` off and blend `ONE,
  ONE_MINUS_SRC_ALPHA` consistently with the object pass.
- `render_gl.cpp` is also edited by P4-06; keep the glyph pass in its own functions to keep the merge
  small.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- Empty run, a run fully outside the viewport, a run before any atlas was uploaded (no glyphs drawn,
  no failure), an atlas replaced while runs exist (runs re-resolve against the new table).
- DPR 0, negative, NaN or above 8; `MAX_TEXTURE_SIZE` below one cell.
- A code point above U+FFFF and a lone surrogate in the TypeScript string.
