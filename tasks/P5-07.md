# P5-07 — crdt-convergence proof: 10,000 rounds, offline clients and own-only undo

## Goal

Prove realtime convergence: 10,000 randomized rounds without divergence (`crdt-convergence` gate),
two clients editing offline converge to the same snapshot after reconnect, and undo/redo only ever
applies the client's own operations (L11 realtime rule); the gate command and its record are
committed.

**Why:** the stage exit gate `crdt-convergence` and the L11 realtime acceptance; the live proof of the
contract's pre-realtime open points and of the CRDT/SDK/service stack.

**Satisfies:** D11

## Scope

- `packages/crdt/` (or a harness under `services/sync/test/`) a deterministic convergence harness:
  seeded randomized operation rounds (10,000, several seeds documented) applied by two or more
  `BoardDoc` replicas in different orders with interleaved offline phases, merged with
  `applyUpdate`/`merge`, ending in identical encoded state and snapshot; zero divergences required,
  runtime and seeds recorded.
- `packages/sdk/` + `services/sync/` the offline-client proof: a headless-browser harness (Chrome for
  Testing, the SDK built as an ESM page; own server on the slot port) with **two pages** that join
  one board, make edits, go offline (CDP network emulation or a closed socket), keep editing offline,
  reconnect and `resyncRequest`, and end in the same document/snapshot as the service; the run
  record contains the per-client document hashes before/after and the missed-update counts. If a
  browser step cannot be made deterministic, fall back to two SDK-Node clients **and record the
  limitation explicitly** — never claim a browser proof that did not run.
- `packages/sdk/` (with the P4-21/P4-05 history) the L11 realtime rule: the session history stores
  only the client's own operations; an undo applies exactly one inverse for a local operation and
  never touches another client's changes; a two-client test proves A's undo leaves B's edit and both
  converge.
- `docs/gates/crdt-convergence.md` (new): gate command, thresholds (10,000 rounds, 0 divergences,
  offline convergence, browser/no-browser recorded), evidence paths, exclusive-run rule and
  environment requirements; `docs/quality.md` replaces the `[VERIFY: stage realtime]` row with the
  real command. `docs/realtime.md` documents the proof; `.changes/P5-07-<short-name>.md` (area
  `sync`, kind `minor`).

## Out of scope

- Load/performance (P5-08), presence payloads (P5-05), web UI, contract changes, new dependencies,
  production deployment, a second CRDT backend.

## Acceptance

A1 WHEN the convergence gate runs, THEN 10,000 seeded randomized rounds (multiple seeds) show zero
divergences, two offline replicas merge to identical encoded state/snapshot, and the gate exits 0 with
a committed record under `reviews/evidence/`.
A2 WHEN two clients edit offline and reconnect to the real sync service, THEN both end in the same
document/snapshot as the service, the catch-up delivers exactly the missed updates, and the record
states whether the client was a headless browser or a Node SDK client (no silent substitution).
A3 WHEN a client undoes a local operation with remote changes present, THEN exactly that inverse is
applied, the other client's changes are untouched, both converge, and `board-check`, `boundaries` and
`unit` pass with records.

## Specifications

- Deterministic: seeded PRNG, fixed operation pools, no ambient randomness/clock in the pure
  convergence phase; the stack phase uses the slot ports/database and cleans up its processes/rows.
- The gate command and thresholds live in `docs/gates/crdt-convergence.md` and `docs/quality.md`
  (both updated in this task); the gate is exclusive (server + browser on the slot).
- The browser page imports the built SDK ESM; no bundler dependency is added; the harness serves
  `packages/sdk/dist/`, the contracts/crdt builds and a static page.
- Undo provenance: operations carry the actor/client identity; the local history records only local
  operations (L11 "never undo another person's operation").
- Evidence: JSON record with seeds, rounds, divergences, document hashes, missed-update counts,
  browser/Node flag, environment; record paths listed in `reviews/evidence/`.
- No new dependency; contract 0.3.0 frozen; boundaries respected.

## Pitfalls

- Comparing only a final JSON snapshot can hide operation-order divergence in `z`/parents; compare
  encoded state **and** snapshot for every round.
- Offline simulation must actually stop the transport (closed socket / CDP offline), not just skip a
  send; otherwise the test proves nothing.
- Undo of a local operation must not be replayed as a new local edit after a remote update with the
  same field; check convergence after the undo.
- Two pages must use distinct client ids/sessions; sharing one client id makes the test meaningless.
- Cleanup: stop only the processes the harness started, reset the slot data, no leftover rows.
- A browser fallback is acceptable only if recorded; a silent Node substitution is a failed review.
