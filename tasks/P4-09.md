# P4-09 — Glyph layout, text instances and ellipsis (L02)

## Goal

Text runs get a layout: a run can be a single line with an ellipsis or a wrapped block that clips to
its box, laid out once from the P4-08 glyph atlas in CSS pixels (DPR-independent) and drawn through
the existing glyph command buffer, with no per-glyph JavaScript call; typography comes only from
tokens.

**Why:** the atlas alone does not render readable cards. Layout and ellipsis are the visible half of
L02, P4-10 binds titles and previews to objects with it, and the owner's zone parity (P4-29/P4-30)
needs one-line zone names with an ellipsis exactly like the live demo.

**Satisfies:** D10

## Scope

- `packages/engine/` module `text`:
  - **Flows:** `line` (P4-08 behaviour, unchanged bytes), `ellipsis` (one line, cut to the box width
    with U+2026; three full stops when the atlas lacks it; nothing when even the ellipsis does not
    fit) and `wrap` (greedy word wrap at spaces, hard break at U+000A, character break for a word wider
    than the box, lines beyond the box height clipped and the last visible line ending in an
    ellipsis).
  - **Layout function** `layoutText` (pure, testable): code points + role + flow + box (CSS px) →
    glyph placements relative to the run anchor plus line count, truncation flag and laid-out size.
    Line height = token font size × token line height. Trailing spaces of a line are not drawn.
  - **Cache:** a run keeps its placements and recomputes them only when the atlas generation changes;
    the glyph buffer maps placements through the camera and culls them as before.
- `render_gl`/`text_gl`: C ABI `engine_text_add_box_run(x, y, role, flow, width, height, codePoints,
  count)`; the P4-08 call stays the `line` flow. Native stubs as before.
- `src/bridge/`: the default glyph set adds U+2026; `addTextRun({ ..., flow, box })`.
- `apps/engine-playground/`: the `?text=1` demo shows a title cut with an ellipsis, a wrapped and
  clipped preview with umlauts and a short title that fits; a visual scene captures it.
- Tests: native layout cases (fit, ellipsis width, ellipsis fallback, box narrower than the ellipsis,
  wrap at spaces, hard break, long-word break, height clip with ellipsis, empty run, DPR 1 vs 2
  identical placements, cache refresh on atlas replacement, determinism); `wasm-smoke` checks the new
  export.
- `docs/engine.md`; `docs/gates/visual-diff.md` for the new scene; `.changes/P4-09-<short-name>.md`
  (area `engine`, kind `minor`).

## Out of scope

- Binding titles to cards/blocks/zones and header sizes (P4-10), title editing (P4-23, L18),
  zoom-bucket re-rasterisation, bidirectional text, hyphenation, kerning, WebGPU.
- Contract changes, new dependencies, a bundled font, changed or deleted tests.

## Acceptance

A1 WHEN an `ellipsis` run is wider than its box, THEN the drawn glyphs plus U+2026 fit inside the box
width, a fitting run is drawn unchanged and a box narrower than the ellipsis draws nothing; native
tests and the visual reference confirm it.
A2 WHEN a `wrap` run is laid out, THEN lines break at spaces, at U+000A and inside an over-long word,
lines beyond the box height are clipped with an ellipsis on the last visible line, and placements in
CSS px are identical at DPR 1 and 2; native tests confirm each case.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `wasm-build`, `wasm-size`,
`visual` and `typecheck` exit 0 with records under `reviews/evidence/`, the P4-08 `line` flow keeps
byte-identical glyph buffers, and `docs/engine.md` describes the layout.

## Specifications

- All widths and positions are CSS px; the camera scales them, so zoom never changes a line break.
- One layout per run per atlas generation; a frame without runs touches no text state.
- No exceptions across the C ABI; failures return 0 and set `engine_last_error`.

## Pitfalls

- Keep the `line` flow's arithmetic exactly as in P4-08, or its byte-identical tests drift.
- The ellipsis may add up to three glyphs: count them against the glyph limit.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- Empty run; a box width of 0 or NaN; a space-only run; consecutive spaces; a line that is exactly the
  box width; a box height below one line; an atlas replaced while runs exist.
