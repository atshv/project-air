# P0-02 — Protect main and document repository settings

## Goal

`main` of `atshv/project-air` accepts changes only through pull requests with green CI and one
review, and the repository settings are documented in `docs/runbooks/repository.md`.

**Why:** every later task merges through this protection. Without it a direct push or a red CI
run can land on `main` and reach a release.

**Satisfies:** D6

## Scope

- Branch protection (or ruleset) for `main`: pull request required, 1 approving review, required
  status checks (the CI job name is added when P0-08 exists; until then "require status checks"
  is enabled without names), no force pushes, no deletion, linear history optional (owner
  decision).
- `docs/runbooks/repository.md`: visibility (private), default branch, protection settings,
  who may approve and merge, how to change settings (owner only), date and who applied them.

## Out of scope

- CI workflow (P0-08), environments and secrets (P0-15), Dependabot (P0-16).

## Acceptance

A1 WHEN someone pushes directly to `main`, THEN GitHub rejects the push.
A2 WHEN a pull request has no approving review or a failing required check, THEN it cannot be
merged.
A3 WHEN `docs/runbooks/repository.md` is read, THEN it lists every setting above with its value,
the date it was applied and the person who applied it.

## Context pack

**Read exactly:**

- `ARCHITECTURE.md` (AD-10), `AGENTS.md`, `STATUS.md`, `docs/quality.md`
- `docs/owner/canvas-suite-blueprint.md`, section 22.2 (German)

**Do not read:** other briefs, `reference/`.

**Budget:** ≤ 15k tokens input.

## Specifications

- **Who acts:** the repository settings are changed by the **owner** in the GitHub web UI (an agent
  must not change account or repository settings). The agent writes the runbook and runs the gate.
- **New files:** `docs/runbooks/repository.md`.
- **Gate output:** the JSON from the protection endpoint is the evidence; it must show required
  pull request reviews and disabled force pushes.

## Pitfalls

- Branch protection on private repositories depends on the GitHub plan; if the plan does not offer
  it, record that in `open_questions` with the plan name instead of working around it.
- Required status checks can only name a check after it has run once; the name is added in P0-08.

## Edge cases

- The owner prefers rulesets over classic protection: document the ruleset; the gate command then
  becomes `gh api repos/atshv/project-air/rulesets` and the lead updates `docs/quality.md`.

## Gates

1. `branch-protection`: `gh api repos/atshv/project-air/branches/main/protection` → exit 0, shows
   required reviews and `allow_force_pushes.enabled: false`.

## Limits

- **Scope:** only `docs/runbooks/repository.md`.
- **Stop:** 1 round; when the plan blocks protection, `status: blocked` + reason.
