# P4-22 — Remember view (L17)

## Goal

The playground stores camera position and zoom per board and device with a guarded read and write,
restores them on opening, starts a new board fitted and never shares a viewport across boards.

**Why:** L17 — after a reload the same section of the board is shown, and storage must never throw or
leak a viewport between boards.

**Satisfies:** D10

## Scope

- `apps/engine-playground/` camera persistence module: a small storage adapter with guarded
  `try`/`catch` reads and writes (localStorage can throw on access, quota or privacy modes), a
  versioned record `{ boardId, deviceKey, panX, panY, zoom }`, validation of finite numbers and a
  zoom clamp to the engine camera range (0.1 … 8), and a per-board + per-device key (the board id of
  the loaded scene/contract board and a documented device fingerprint such as viewport class + DPR).
  Reads never throw; writes never throw; a corrupt/foreign/unknown-version record is ignored.
- `apps/engine-playground/` lifecycle: on opening, restore the record for the current board+device
  before the first fitted frame when it is valid; otherwise (no entry, new board, invalid record)
  apply the L19 fit ("show all" behaviour) as today. Writes happen only on user camera changes
  (pan/zoom/fit), debounced and on page hide; a new board must never write the previous board's
  entry, and a programmatic restore/fit must not overwrite another board's entry.
- `packages/engine/` only the minimal hook the adapter needs (camera read/apply and the board id);
  no new camera behaviour, no persistence in the engine core.
- `apps/engine-playground/` a capture/record proving: reload restores the same section, a new board
  starts fitted, two boards keep separate entries, storage exceptions fall back to the fitted view;
  record under `reviews/evidence/` (desktop 1440×900, mobile 390×844); no reference image changes.
- Tests: unit tests with a fake storage for restore, per-board/device separation, invalid JSON,
  version mismatch, throwing getter/setter, quota error, zoom clamp, no write on restore, fit
  fallback; `unit` gate green. `.changes/P4-22-<short-name>.md` (area `engine`, kind `minor`);
  `docs/engine.md` documents the record, key, guarded access and the fit fallback.

## Out of scope

- Cross-device sync of the view, realtime collaboration, remembering selection/panel state, engine
  camera changes, new visual baselines, contract/database changes, new dependencies, changed or
  deleted tests.

## Acceptance

A1 WHEN a valid stored view exists for the current board and device, THEN opening restores that
camera and a reload shows the same section; a board without an entry starts fitted, and two boards
keep separate entries that never leak into each other.
A2 WHEN storage is unavailable, throws, holds invalid JSON or an unknown version, THEN the app opens
with the fitted view without an uncaught error; unit tests cover the guarded paths and
`board-check`, `boundaries` and `unit` pass with records under `reviews/evidence/`.

## Specifications

- Every storage access is guarded; no uncaught exception may reach the page and no unguarded
  `localStorage` access exists in the code.
- The key contains both the board id and the device fingerprint; a viewport is never shared across
  boards or devices.
- The record is versioned; an unknown version is ignored (fitted view), never reinterpreted.
- Restore happens before the first fitted frame; a programmatic fit/restore does not write, only a
  user camera action does.
- Zoom is clamped to the camera range on read and on write; non-finite values are rejected.
- No new token, dependency or contract change.

## Pitfalls

- `localStorage` can throw on the property access itself (privacy mode); wrap the access, not only
  the call.
- A scene reload with a different board id must not restore the previous board's camera.
- Writing on every camera frame floods storage; debounce and write on page hide.
- Restoring a stale zoom outside the range must clamp, not fail the page.
- The device fingerprint must be stable across reloads or the record never restores.
