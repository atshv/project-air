# P0-03 — Workspace folders and package READMEs

## Goal

Every `packages[]` folder from `board.json` exists with a README that states its purpose, the
stage-1 packages also have an `ARCHITECTURE.md`, and `docs/module-map.md` lists them all.

**Why:** every later task writes inside these folders; `check.py` fails while a package folder is
missing, and package files are the small context each worker loads.

**Satisfies:** D1

## Scope

- Create the 21 folders listed in `board.json` → `packages[]` (`packages/*`, `services/*`,
  `apps/*`, `tools/*`, `infra`), plus `tests/` with a README.
- One `README.md` per folder: one-sentence purpose (from `docs/module-map.md`), kind, stage in
  which it is built, link to the root `ARCHITECTURE.md`.
- `ARCHITECTURE.md` (≤ 400 words, from the package template structure: purpose, inputs, outputs,
  invariants, allowed imports, commands) for the stage-1 packages only: `packages/ui-kit`,
  `tools/design-check`, `tools/language-check`, `tools/release`, `tools/dev`, `infra`.
- Update `docs/module-map.md` only if a purpose or stage changes while writing the READMEs.

## Out of scope

- Any code, manifest or configuration (P0-04 and later).
- `ARCHITECTURE.md` for packages built in later stages (written by the stage that creates them).
- Anything under `reference/` (read-only).

## Acceptance

A1 WHEN `python3 $POLIER/tools/check.py .` runs after the task, THEN it reports no missing package
folder and no package file over its word budget.
A2 WHEN any `packages[].path` is opened, THEN it contains a `README.md` whose purpose sentence
matches `docs/module-map.md`, and no folder is empty.
A3 WHEN a stage-1 package is opened, THEN its `ARCHITECTURE.md` states purpose, inputs, outputs,
at least one invariant, the `may_import` list from `board.json`, and commands marked
"set by P0-04" until the workspace exists.

## Context pack

**Read exactly:**

- `ARCHITECTURE.md`, `AGENTS.md`, `STATUS.md`, `docs/module-map.md`, `docs/quality.md`
- `docs/monorepo-layout.md`
- `board.json` → `packages[]`
- `docs/owner/canvas-suite-blueprint.md`, sections 3 and 4 (German; purpose of each package)

**Do not read:** other briefs, `reference/`.

**Budget:** ≤ 25k tokens input.

## Specifications

- **Kind:** documentation and folders only.
- **New files:** `<package>/README.md` for all 21 packages, `tests/README.md`, `ARCHITECTURE.md`
  in the six stage-1 packages listed above.
- **Changed files:** `docs/module-map.md` only if needed.
- **Language:** English; no German UI text.
- **Invariants to reference:** root `AD-7` for `packages/ui-kit`, `AD-8` for
  `tools/language-check`, `AD-9` for `tools/dev`, `AD-10` for `tools/release`.

## Pitfalls

- Git does not track empty folders; every folder needs its README.
- The package-file budget is 400 words for `ARCHITECTURE.md`; `check.py` measures it.
- Do not invent build commands; write "set by P0-04".

## Edge cases

- A package whose purpose is unclear from the blueprint → `open_questions`, not a guess.
- `infra` is a single folder with kind `infra`; its sub-areas (`compose/`, `migrations/`,
  `deploy/`) are created by the tasks that fill them.
