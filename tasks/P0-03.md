# P0-03 — Workspace folders, package READMEs and architectures

## Goal

Every `packages[]` folder from `board.json` exists with a `README.md` that states its purpose and
an `ARCHITECTURE.md` (≤ 400 words), and `docs/module-map.md` lists them all.

**Why:** every later task writes inside these folders; `check.py` fails once a package folder
exists without an `ARCHITECTURE.md`, and the package files are the small context each worker
loads.

**Satisfies:** D1

## Scope

- Create the 21 folders listed in `board.json` → `packages[]` (`packages/*`, `services/*`,
  `apps/*`, `tools/*`, `infra`), plus `tests/` with a README.
- One `README.md` per folder: one-sentence purpose (from `docs/module-map.md`), kind, stage in
  which it is built, link to the root `ARCHITECTURE.md`.
- One `ARCHITECTURE.md` (≤ 400 words) per folder with the package template structure: purpose,
  inputs, outputs, invariants, allowed imports, commands. Take purpose, inputs and outputs from
  the blueprint sections 3 and 4, reference the root invariants that bind the package, copy
  `may_import` exactly from `board.json`, and mark every command "set by P0-04" until the
  workspace exists.
- `tests/README.md`: the test layers from the blueprint (integration, e2e, perf) and which later
  task adds their tooling.
- Update `docs/module-map.md` only if a purpose or stage changes while writing.

## Out of scope

- Any code, manifest or configuration (P0-04 and later).
- Detailed module lists, real build details and test tooling; the stage that creates the code
  expands the package `ARCHITECTURE.md` files.
- `apps/admin` from blueprint section 3 — it is not on the board; do not create it.
- Anything under `reference/` (read-only).

## Acceptance

A1 WHEN `python3 $POLIER/tools/check.py .` runs after the task, THEN it exits 0 and names no
missing package `ARCHITECTURE.md` and no package file over its word budget.
A2 WHEN any `packages[].path` is opened, THEN it contains a `README.md` whose purpose sentence
matches `docs/module-map.md` and an `ARCHITECTURE.md`; no folder is empty.
A3 WHEN any package `ARCHITECTURE.md` is read, THEN it states purpose, inputs, outputs, at least
one invariant, the `may_import` list from `board.json`, and commands marked "set by P0-04".
A4 WHEN `python3 $POLIER/tools/boundaries.py .` runs after the task, THEN it exits 0 and no
"package path ... does not exist on disk" warning remains.

## Context pack

**Read exactly:**

- `docs/monorepo-layout.md`
- `board.json` → `packages[]`
- `docs/owner/canvas-suite-blueprint.md`, sections 3 and 4 (German; purpose of each package)

**Do not read:** other briefs, `reference/`.

**Budget:** ≤ 25k tokens input.

## Specifications

- **Kind:** documentation and folders only.
- **New files:** `<package>/README.md` and `<package>/ARCHITECTURE.md` for all 21 packages,
  `tests/README.md`.
- **Changed files:** `docs/module-map.md` only if needed.
- **Language:** English; no German UI text.
- **Invariants to reference** (from `ARCHITECTURE.md` section 4): `AD-1` crdt, `AD-2`
  engine/sdk/sync, `AD-3` every package, `AD-4` contracts/platform/web, `AD-5` platform/auth,
  `AD-6` ai, `AD-7` ui-kit/engine/web, `AD-8` web/auth/ai, `AD-9` tools/dev/infra, `AD-10`
  tools/release. Do not invent invariants or numbers.
- **README fields:** purpose, kind (`package`, `service`, `app`, `tool`, `infra`), stage in
  which it is built, link to the root `ARCHITECTURE.md`.

## Pitfalls

- `check.py` (Polier 1.0.0) requires an `ARCHITECTURE.md` in every package folder that exists:
  creating a folder with only a README fails the board check. Create both files together.
- Git does not track empty folders; every folder needs both files.
- The 400-word budget for `ARCHITECTURE.md` is an error, not a warning.
- Do not invent build commands; write "set by P0-04".
- Do not copy or symlink files between packages; each folder gets its own text.

## Edge cases

- A package whose purpose is unclear from the blueprint → `open_questions`, not a guess.
- `infra` is a single folder with kind `infra`; its sub-areas (`compose/`, `migrations/`,
  `deploy/`) are created by the tasks that fill them and are only listed in its architecture
  text.
