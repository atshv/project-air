# P6-04 — Board page host: engine, toolbar, zoom and view persistence (L00, L17)

## Goal

The board page mounts the engine on a real WebGPU/WebGL2 surface, loads the board document through
the SDK board-sync client, renders the toolbar (L00) and zoom controls, keeps camera/view per board
persisted (L17) and maps pointer/keyboard input to engine tools; the empty board state is shown.

**Why:** the board page is the product's core surface; L00/L17 are the first two web canvas orders.

**Satisfies:** D12

## Scope

- `apps/web/` board page `/boards/:id`: board metadata via the SDK (`boards.get`), missing/forbidden
  returns to `/boards`; title, back navigation, empty/loading/error states from messages.
- `apps/web/` engine host: create the engine from `@project-air/engine`, mount/size its canvas (DPR,
  resize, unmount cleanup) and reuse the playground's document-port wiring. **WebGL2 stays the
  default (Q19)**; WebGPU only with an actual adapter and a fail-closed fallback.
- `apps/web/` board content: one SDK `BoardSyncClient` owns the `BoardDoc`; the page installs it
  through the document port, applies remote updates to the engine and exposes the local-operation
  path (one gesture = one contract operation with inverse) that P6-05/P6-07 complete; sync URL and
  client id come from the session, and the Vite proxy forwards the sync WebSocket from `.polier-slot`.
- `apps/web/` view persistence (L17): the engine `view-persistence` bridge with the per-board/device
  key, throttled save, restore on load, "fit all" as default; trackpad/pinch comes from the engine
  input (P4-24) — do not re-implement it.
- `apps/web/` toolbar (L00): top-centre icon bar, 36/20 px, groups with dividers, one accent primary,
  tooltips after 300 ms, icons/messages from the packages; tools map to engine tools (select, note,
  zone, block, connect, pan) with active state, `aria-pressed`, keyboard reachability; +/−/fit zoom
  controls with the view-persistence limits.
- `packages/engine/` package export map: add the logic subpath exports the app needs
  (`./logic/operations.js`, `./logic/document-port.js`, `./logic/history.js`,
  `./bridge/view-persistence.js` — matching the playground's import-map targets) so the Vite build
  consumes the same modules; no behaviour change, engine tests stay green.
- Tests: pure helpers (toolbar model, view key/restore/clamp, backend fallback) with `node --test`;
  DOM/engine integration is P6-08 e2e. `.changes/P6-04-<short-name>.md`; README notes.

## Out of scope

- Editing gestures/panel/editor (P6-05/P6-07), realtime save status/presence UI (P6-07), e2e (P6-08),
  performance measurement (hardening), images/previews (hardening), SSR.

## Specifications

- Backend: WebGL2 default (Q19); WebGPU only with an actual adapter and a fail-closed fallback when
  creation/ready fails; the choice is recorded (no silent switch mid-session).
- One gesture = one contract operation (AD-1): in-gesture previews via the bridge, the commit via
  the SDK autosave/sync path.
- View persistence: reuse `VIEW_STORAGE_PREFIX`/`storageKeyFor`; no second camera store; clamp to
  engine limits; "fit" is the default.
- Toolbar: exactly one accent primary, 36/20 px, dividers, 300 ms tooltips, labels from messages,
  visible focus.
- Engine package export changes are additive and must not alter runtime behaviour; run the engine
  suite after.
- Ports/URLs only from `.polier-slot` (web 4300, sync 4330 via proxy) with env overrides; no
  hardcoded URLs.
- Unmount destroys the engine, observers and sync client; no timers stay.

## Pitfalls

- Vite dev proxy must forward the WebSocket upgrade for the sync endpoint (`ws: true`), otherwise
  live updates silently stop in dev while e2e builds work differently.
- A canvas sized before layout is 0×0/blurry; size on ResizeObserver and handle DPR.
- Applying an operation both optimistically and through the sync echo can duplicate entities; the
  document port must be the single writer of the engine state.
- A bad view record must not restore zoom 0 or an off-board camera; validate and fall back to fit.
- WebGPU `device.lost` must fall back once, not loop; unmount stops the rAF loop and closes the
  socket.
