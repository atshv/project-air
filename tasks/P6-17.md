# P6-17 — Dragging on the web canvas (L03, L07, L16, L20)

## Goal

Objects on the web canvas move with the pointer the way the playground and the live demo do it:
drag after the 4 px threshold, snapping with guides, auto-pan near the edge, and new objects placed
by the L20 rule, each gesture committing exactly one operation through the SDK on release.

**Why:** owner decision 2026-10-29 (close the stage-7 gaps first). Today the app only selects by
click and moves with the arrow keys; without dragging, nothing on the canvas feels like the demo.

**Satisfies:** D12

## Scope

- `apps/web/` pointer layer: wire the engine input module (L03) to the canvas with pointer capture:
  the whole card is the grip, zones/blocks only by their 40 px header, cursor `grab`/`grabbing`,
  1.02 lift while dragging, click vs drag vs edit never at once; `Escape`/`pointercancel` cancel
  without an operation.
- Snapping (L07) with up to three guides and Shift for free movement; auto-pan (L16) near the
  canvas edge while dragging; placement (L20) for new notes from the toolbar and the context menu.
- Commit: one contract operation per gesture through the existing commit path, so undo/redo, L05
  status and realtime work unchanged; a remote change during a drag never makes the dragged object
  jump.
- One pointer layer module in `apps/web/src/board/` that P6-18 and P6-19 extend; keep the L12
  keyboard map.
- Tests: pure tests for gesture-to-operation mapping and cancel; e2e for drag, snap, cancel,
  auto-pan.
- `.changes/P6-17-<short-name>.md` (area `web`, kind `minor`).

## Out of scope

- Multi-select and resize (P6-18), zones (P6-19, P6-20), blocks (P6-21), touch (hardening), edges.

## Acceptance

A1 WHEN a card is dragged more than 4 px and released, THEN it moves with snapping guides and
exactly one `moveCard` is acknowledged; under 4 px it only selects; `Escape` mid-drag restores it
with no operation.
A2 WHEN a drag reaches the canvas edge, THEN the view auto-pans; a new note from the toolbar or
context menu lands by the L20 rule; one undo reverts each gesture.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit`, `typecheck`, `design-check`,
`language-check` and `e2e` exit 0 with records and the change entry exists.

## Specifications

- Pointer deltas are divided by the zoom; drags track the pointer 1:1 and commit on release.
- Only engine package exports are imported; no copy of engine logic in the app.
- Every gesture has a cancel path; the working copy is identical after a cancel.

## Pitfalls

- React re-renders during a drag cost frames; keep drag state in refs and the engine.
- Context-menu and right-button drags must not start a move.
