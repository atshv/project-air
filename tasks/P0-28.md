# P0-28 — Zone detach interaction: drag notepad and photo out and back

> **Size:** 400–900 words. UI interaction in the static design preview (`apps/web/preview/`).

## Goal

The notepad and the image window can be dragged **out of the zone** onto the canvas with a subtle
progressive detach animation, stay free and **edge-less** while outside, and **dock back** into the
zone when dragged inside again (the same transition in reverse).

**Why:** zone content should behave like canvas objects that can be pulled out and put back; the
animation makes the state change legible instead of snapping.

**Satisfies:** D3

## Scope

- `apps/web/preview/index.html` — zone items get `data-zone-item` hooks and dock slots; hint/legend
  describe the behaviour; masthead last change `P0-28 — Zone detach interaction: drag notepad and
  photo out and back` + `.changes` mtime, Tasks + P0-28.
- `apps/web/preview/preview.css` — docked/detached states and the transition values; tokens only.
- `apps/web/preview/preview.js` — pointer drag for **both** zone items (mouse, pen, touch):
  - inside the zone the item moves with the pointer, clamped to the zone;
  - as the pointer moves outward past the zone edge, a **detach progress 0→1** eases over a short
    distance (e.g. 24–32 px): subtle scale (1→1.02), shadow grows, outline/border fades, and at
    progress 1 the item is released from the zone into canvas space (absolute position in the demo
    surface, clamped to the surface, above the zone, below the toolbar/cards chrome as appropriate);
  - dragging back toward/into the zone runs the progress in reverse and re-docks the item into its
    original slot with a short settle; no layout jumps of other content;
  - **no connection is created** for detached items: the existing A/B edge stays the only edge and
    never attaches to the zone items;
  - `prefers-reduced-motion: reduce` → no scale/shadow animation, state change immediate;
  - existing demo behaviour (cards A/B drag/keyboard/edge/zoom/toolbar, and the bilingual switch)
    must stay unchanged.
- `apps/web/preview/locales/en.json` and `de.json` (from P0-27) — add/update the hint/legend/status
  strings for the new interaction in both languages (identical keys).
- `apps/web/preview/README.md` — drag-out/in behaviour, thresholds, reduced-motion, screenshots;
  bump the `?v=` query in `index.html` to P0-28.
- `.changes/P0-28-zone-detach.md` (area `web`, kind `minor`).
- Evidence: `P0-28-docked.png`, `P0-28-mid-detach.png` (≈50 %), `P0-28-detached.png` (free, no
  edge), `P0-28-redocked.png` (1440×900; one mobile shot if layout changes) and

## Specifications

- Pointer events with `setPointerCapture`; one active drag; threshold constants documented in the
  drag code; transform-based animation (no per-frame layout thrash).
- Detach progress is a number 0..1; CSS variables (e.g. `--detach-progress`) or classes drive the
  visual; state classes `is-docked` / `is-dragging` / `is-detached` on the items.
- Dock slots are measured from the initial zone layout (not hard-coded); re-dock restores the slot
  exactly. Extracted items clamp to the demo surface with the same 16 px grid snap as the cards.
- Z-order: zone `--layer-blocks`, note cards/cards `--layer-note-cards`, dragged item
  `--layer-dragged-or-selected`, canvas chrome `--layer-canvas-chrome`; no numeric z-index.
- `prefers-reduced-motion` respected; motion values from tokens.
- German only in the locale JSON; no `ß`; du-form.

## Pitfalls

- Do not capture the cards' pointer events or the toolbar/switch; the drag starts only on the two
  zone items.
- Avoid re-dock on a wobble: hysteresis (detach >1.0, dock below a smaller threshold), tested.
- The zoom transform on the world layer: drag on a dedicated layer or account for the scale.
- `design-check` rejects raw colours/off-grid spacing/numeric z-index; `language-check` rejects
  German in code; `board-check` before any `pnpm`; the `.changes` mtime is the masthead time.

## Edge cases

- Fast drag in/out; release mid-detach (settle to nearest state); pointer cancel; ignore a second
  pointer.
- Zoomed (1.5/0.5) and compact (390 px) views: thresholds stay in screen pixels; items stay
  visible and clamped.
- Reduced motion: no animation, still detaches/docks correctly.
