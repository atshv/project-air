# P6-05 — Board interactions: context menu, keyboard and undo/redo UI (L12, L11 hint)

## Goal

The board page gets the L12 keyboard map (Cmd/Ctrl+D duplicate, Delete/Backspace, Esc, arrow 16 px /
Shift 160 px as one operation after 300 ms), the right-click context menu (200 px, 32 px items, muted
shortcuts), and the L11 undo/redo hint; shortcuts never fire in fields.

**Why:** L12 and the L11 web half are remaining web canvas orders and complete the engine-web input
wiring.

**Satisfies:** D12

## Scope

- `apps/web/` keyboard layer: Cmd/Ctrl+D duplicates (+16/+16), Delete/Backspace deletes, Esc closes
  menu/panel, arrows 16 px / Shift 160 px with **one** operation after a 300 ms burst; shortcuts are
  suppressed in input/textarea/contenteditable/dialog (documented allow-list for menus).
- `apps/web/` context menu (L12): 200 px wide, 32 px items (Open, Duplicate, Bring forward, Send
  backward, Delete) with muted shortcuts; P6-01 Menu primitives, roving focus/Enter/Escape, focus
  restored to the canvas; z-index from `layers.ts`.
- `apps/web/` operations: duplicate creates a new note + card as one group operation with inverse
  (AD-1, AD-4); delete uses the contract delete; Bring forward/Send backward use the contract
  `reorder` (fractional `z` + inverse) — add the small reorder action in `packages/engine/` if the
  session lacks it, never leave entries inert. Multi-select duplicate is out of scope if the session
  cannot; disable with a message and record the gap.
- `apps/web/` undo/redo (L11 web half): Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, bottom-centre hint
  "Undo: <action>" for 3 s; realtime undoes only the client's own operations (SDK `undoOwn`/`redoOwn`
  is the single history), never remote ones; remove any competing engine-history writer.
- Tests: pure helpers (keyboard mapping + field suppression, 300 ms grouping, menu model including
  disabled states/shortcuts, hint text from messages) with `node --test`; `.changes/
  P6-05-<short-name>.md`; README notes.

## Out of scope

- Panel/editor contents (P6-06), save status/presence UI (P6-07), e2e suite (P6-08), touch gestures
  (hardening), multi-select duplicate if the session cannot do it (documented gap), view persistence
  (L17, already P6-04).

## Acceptance

operation with its inverse (arrows grouped per 300 ms burst, duplicate +16/+16 with a fresh note,
delete, reorder bring/send), and no shortcut fires while a field/editor/dialog owns the focus.
A2 WHEN the context menu opens by mouse or keyboard, THEN it has the L12 size/items/shortcuts, is
keyboard operable, closes with Esc and restores focus; undo/redo (Cmd/Ctrl+Z, Shift variant) undoes
only the client's own operations in realtime, shows the 3 s "Undo: …" hint, and redo works.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit`, `typecheck`, `design-check` and
`language-check` exit 0 with records, any engine action addition keeps the engine suite green, and

## Specifications

- One gesture = one contract operation with inverse (AD-1); arrow bursts grouped after 300 ms; one
  operation builder, no duplicate paths.
- Modifier: `metaKey` on macOS, `ctrlKey` elsewhere; never fire while a field owns focus.
- Context menu: one at a time, clamped to the viewport, closes on outside/Escape/scroll, focus back
  to the canvas, items are real buttons from messages.
- Undo/redo: SDK own-op history is the single source; no parallel engine-history writer; redo after
  a remote operation stays local.
- Reorder uses the contract operation/inverse; the engine action is a real seam change with unit
  coverage, never a UI fake.
- Hint text uses the operation type/count wording from messages; it replaces itself, never stacks.
- Design: menu 200 px/32 px items, destructive tone from tokens, z-index from `layers.ts`.
- Real keyboard/menu DOM flows are P6-08 e2e; here pure logic is tested.

## Pitfalls

- A shortcut listener on `window` without a focus-target guard breaks typing in the editor — test
  the guard explicitly.
- Grouping arrows by a timer must flush on blur/Esc and not merge two distinct gestures.
- Duplicate must not share the note (AD-4); copy the note content into a new note in the same group
  operation.
- Bring/Send must not collide with other cards' `z`; use the fractional `z` helper and test
  ordering.
- The context menu can be cut off near the right/bottom edge; clamp the position.
- Undo of a create must not remove a note another card still references; the inverse of a group
  restores the previous state in order.
- Stale selection after a remote delete must disable the actions instead of throwing.
