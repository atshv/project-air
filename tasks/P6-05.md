# P6-05 — Board interactions: context menu, keyboard and undo/redo UI (L12, L11 hint)

## Goal

The board page gets the L12 keyboard map (Cmd/Ctrl+D duplicate, Delete/Backspace, Esc, arrow 16 px /
Shift 160 px as one operation after 300 ms), the right-click context menu (200 px, 32 px items, muted
shortcuts), and the L11 undo/redo hint; shortcuts never fire in fields.

**Why:** L12 and the L11 web half are remaining web canvas orders and complete the engine-web input
wiring.

**Satisfies:** D12

## Scope

- `apps/web/` keyboard layer on the board page: Cmd/Ctrl+D duplicates the selection by +16/+16,
  Delete/Backspace deletes, Esc closes the menu/panel/ends the gesture, arrows move by 16 px and
  Shift+arrows by 160 px; a held/repeated arrow sequence commits **one** contract operation 300 ms
  after the last key. Shortcuts are suppressed whenever the event target is an input, textarea,
  contenteditable (editor/panel) or a dialog; a documented allow-list handles menu shortcuts.
- `apps/web/` context menu (L12): right-click on a card/zone/block or empty board; 200 px wide,
  32 px items (Open, Duplicate, Bring forward, Send backward, Delete) with shortcuts right-aligned
  in the muted tone; built on the P6-01 Menu primitives with roving focus, arrow/Enter/Escape,
  focus restored to the canvas after close; z-index from `layers.ts`.
- `apps/web/` operations for the actions: duplicate creates a new note and card as **one group
  operation** with its inverse (AD-1, AD-4: a note exists once, the duplicate gets its own note);
  delete uses the contract delete with inverse; Bring forward/Send backward use the contract
  `reorder` operation (fractional `z` + inverse). If the engine's generic session lacks the reorder
  action, add the small action in `packages/engine/` (logic/gestures seam) so the menu entries are
  real — never leave them inert. Multi-selection duplicates are out of scope if the session does not
  support them; then disable the entry with a message and record the gap.
- `apps/web/` undo/redo UI (L11 web half): Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z (and Cmd/Ctrl+Shift+Z on
  macOS-like keyboards), with the bottom-centre hint "Undo: <action>" for 3 s from messages; in
  realtime only the client's own operations are undoable (SDK `undoOwn`/`redoOwn` from P5-07 is the
  single history), remote operations are never undone; the local (offline) path uses the same history
  — remove any competing engine-history writer on the page.
- Tests: pure helpers (keyboard mapping + field suppression, 300 ms grouping, menu model including
  disabled states/shortcuts, hint text from messages) with `node --test`; `.changes/
  P6-05-<short-name>.md`; README notes.

## Out of scope

- Panel/editor contents (P6-06), save status/presence UI (P6-07), e2e suite (P6-08), touch gestures
  (hardening), multi-select duplicate if the session cannot do it (documented gap), view persistence
  (L17, already P6-04).

## Acceptance

A1 WHEN the board page has focus, THEN the L12 keys perform their actions as exactly one contract
operation with its inverse (arrows grouped per 300 ms burst, duplicate +16/+16 with a fresh note,
delete, reorder bring/send), and no shortcut fires while a field/editor/dialog owns the focus.
A2 WHEN the context menu opens by mouse or keyboard, THEN it has the L12 size/items/shortcuts, is
keyboard operable, closes with Esc and restores focus; undo/redo (Cmd/Ctrl+Z, Shift variant) undoes
only the client's own operations in realtime, shows the 3 s "Undo: …" hint, and redo works.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit`, `typecheck`, `design-check` and
`language-check` exit 0 with records, any engine action addition keeps the engine suite green, and
the change entry exists.

## Specifications

- One gesture = one contract operation with inverse (AD-1); arrow bursts are grouped into one
  operation after 300 ms; no duplicate primitive paths (one operation builder).
- Platform modifier: `metaKey` on macOS, `ctrlKey` elsewhere; never fire while a field owns focus;
  ignore auto-repeat for on/off keys but include repeats in the grouped arrow operation.
- Context menu: only one open at a time, positioned inside the viewport, closes on outside click,
  Escape and scroll; focus returns to the canvas; menu items are real buttons from messages.
- Undo/redo: the SDK own-op history is the single source; do not run the engine history writer in
  parallel on the page; redo after a remote operation stays local (only own ops).
- Reorder: use the contract `reorder` operation and its inverse; if the engine session lacks the
  action, add a minimal one in the engine logic seam with unit coverage — do not fake it in the UI.
- Menu label "Undo: …" uses the operation type/count mapping (the P4-21 `describeOperation` wording)
  from messages; the hint never stacks, replaces itself.
- Design: menu width 200 px, items 32 px, one accent only for the destructive action's tone, tokens
  only, z-index from `layers.ts`.
- e2e covers the real keyboard/menu flows in P6-08; here the pure logic is tested.

## Pitfalls

- A shortcut listener on `window` without a focus-target guard breaks typing in the editor — test
  the guard explicitly.
- Grouping arrows by a timer must flush on blur/Esc and not merge two distinct gestures.
- Duplicate must not share the note (AD-4); copy the note content into a new note in the same group
  operation.
- Bring/Send must not collide with other cards' `z`; use the fractional `z` helper and test
  ordering.
- The context menu can be cut off near the right/bottom edge; clamp the position.
- Undo of a create must not remove a note another card still references; the inverse of a group
  restores the previous state in order.
- Stale selection after a remote delete must disable the actions instead of throwing.
