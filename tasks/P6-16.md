# P6-16 — Titles, previews and headers on the web canvas (L02 web part)

## Goal

The board canvas in `apps/web` shows what the live demo shows at rest: note cards with their title
and a clipped body preview, zones and blocks with their 40 px header and title, the quiet delete
affordance, and it stays in step with local edits and remote changes. The app stops projecting
anonymous rectangles.

**Why:** owner decision 2026-10-29 (close the stage-7 gaps first). L02 is `open` because the app
"projects rectangles only"; the value stage also needs titles on cards for search highlighting.

**Satisfies:** D12

## Scope

- `apps/web/` projection: replace `loadRectangles` in `BoardPage.tsx` with the engine document port
  keyed by object id (cards, zones, blocks in contract draw order), so hit testing returns ids, not
  array positions; one projection module with pure tests.
- `apps/web/` text binding: card title = note title, preview = note `plainText` (first lines, the
  engine clips); zone title = `zone.title`; block title from messages per block type; rebind on
  snapshot, on remote operations and on panel title/body edits without a full reload of the
  document; use the zoom bucket path for sharp text.
- `apps/web/` L02 chrome: delete affordance (`opacity: 0` at rest, visible on hover/focus/selection,
  `Tab` reachable, icon from `packages/ui-kit/icons/`, label from messages), selection frame per
  the engine chrome; the toolbar fit padding (48 + 16 px).
- Refactor the large `BoardPage.tsx` only where the projection needs it (extract the projection and
  binding into `apps/web/src/board/`).
- Tests: pure projection/binding tests with `node --test`; existing e2e stay green.
- `.changes/P6-16-<short-name>.md` (area `web`, kind `minor`).

## Out of scope

- Dragging and gestures (P6-17, P6-18), zone behaviour (P6-19, P6-20), block content (P6-21), images, edges.

## Acceptance

A1 WHEN a board with cards, a zone and a block loads, THEN each card shows its title and preview,
the zone and block show their header title, and nothing reads as a bare rectangle at 1440×900 and
390×844.
A2 WHEN the title or body is edited in the panel or a remote client changes it, THEN the canvas text
updates within one frame after the document change, without re-fitting the view or losing the
selection.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit`, `typecheck`, `design-check`,
`language-check` and `e2e` exit 0 with records and the change entry exists.

## Specifications

- The engine stores no text (AD-4): bindings are presentation input, rebuilt from the SDK document.
- Rebinding is incremental per changed object; a full rebind only on snapshot.
- Visible text only from `apps/web/messages`; German uses `ss`.

## Pitfalls

- Slot indices change when objects are added or removed; never cache a slot across a document
  change.
- A note body edit fires on every keystroke; throttle rebinding to the frame, not to a timer.
