# P0-44 — Live demo: document the pen and ink colours in the preview

> Static design preview (`apps/web/preview/`). Owner note (2026-10-27): the live preview is not
> bound to the usual brief budgets.

## Goal

Owner request of 2026-10-28: "die neuen funktionen mit zeichnen und farben in die preview aufnehmen
/ speichern" — the pen tool and ink colours (P0-43) must be documented and held in the preview page
itself, not only exist in the live demo.

1. **Toolbar icons.** The "Toolbar icons" section gains the pen tile (inline SVG drawn on the same 24
   grid / 1.6 stroke / `currentColor` as the ui-kit icons) and states that the pen is a live-demo
   control kept inline because `packages/ui-kit/icons/` has no pen icon yet, while the palette tile
   continues to load `palette.svg`; the intro no longer says "ten icons" without qualification.
2. **Ink and colours section.** A documented block (part of the component documentation, next to the
   states/layers cards) shows the feature: a small specimen with freehand strokes in all six ink
   colours (`--tone-a` … `--tone-e`, `--fg`) over a card/photo mock in light and dark, the six-swatch
   palette row with the translated colour names, and the pen/palette controls in rest, active-tool
   and popover-open states. The Layers list gains an "Ink annotations" row in its correct position
   (above content, below the selection/chrome layers) marked **preview only**; the text explains that
   strokes are world-anchored, one undo step each, recolour with the theme, and are preview state
   (no data, no server, cleared on reload). The engine annotation layer is named as a follow-up.
3. **Docs and evidence.** README documents the new section and what the preview proves about ink.
   Screenshots of the section in light and dark, EN and DE; a headless-Chrome log that the new
   section renders with the expected swatch/tone colours and no overflow.

**Why:** the preview is the design system's documentation; a feature that only exists in the demo but
not in the documented states/colours/layers is invisible to reviewers and to the next tasks.

**Satisfies:** D3

  dependencies, other pages.

## Specifications

- The new section is documentation, not a new demo: static markup with the real token variables, no
  new interaction beyond what the live demo already has; links/cross-references to the demo section.
- All values from tokens; no raw colour, radius, spacing, shadow or motion value; English code and
  comments, UI text only from locale files, German `ss`.
- The layer row must match the actual preview stacking (ink above objects, below chrome) and be
  marked preview-only; do not silently change the engine's §8 order.
- Keep the existing section numbering and the page's two-column/mobile layout working.

## Pitfalls

- The icon gallery and states grid are static markup duplicated per icon; add the pen without breaking
  the `data-i18n-attr` pairing or the icon CSS.
- Light/dark: the specimen strokes must use tone variables so both themes render them correctly; do
  not hard-code an ink palette in the documentation.
- Long German labels can overflow the two-column detail cards; test 390 px width.
- `check.py` scans `node_modules/`; run `board-check` before `pnpm install`.
