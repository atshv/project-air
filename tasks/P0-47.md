# P0-47 — Preview page: connections diagram instead of roles

> Static design preview (`apps/web/preview/`). Owner note (2026-10-27): the live preview is not
> bound to the usual brief budgets.

## Goal

Owner request of 2026-10-29: "statt die rollen auf einen blick, füge die zusammenhänge hinzu". The
owner attached a diagram of how the parts of Project air connect, as the template. In section
"13 — Project areas", the card "Roles at a glance" (P0-45) is replaced by a card "How it connects".
The card holds:

1. **Diagram.** An inline SVG that is drawn only with tokens: `--surface` boxes with a 1 px
   `--border-strong` line and `--radius-sm`, names in `--fg`, technology in `--muted`, and
   connection lines in `--muted` with small arrowheads. It has thirteen nodes in four columns,
   left to right:
   - **Web app**: React 19 + Vite.
   - **Editor**, **Engine** (C++ / WASM), **SDK** (client) and **Auth**.
   - **ui-kit** (tokens + icons), **Data model** (contracts), **Sync**, **Platform API** and
     **Ory Kratos**.
   - **CRDT** (Yjs), and **PostgreSQL** and **File storage** (S3), each drawn as a cylinder.

   The edges are the ones in the template:
   - The web app uses ui-kit, editor, engine and SDK; sign-in goes to auth (dashed).
   - The engine uses ui-kit and the data model.
   - The SDK uses the CRDT, talks to sync over WebSocket and to the platform API over HTTP (both
     dashed and labelled).
   - Sync uses the CRDT and PostgreSQL.
   - Auth uses Ory Kratos.
   - The platform API uses PostgreSQL and the file storage.

   Lines never cross a box. Solid lines mean "uses in code"; dashed lines mean "talks over the
   network".
2. **Legend and words.** A two-item legend (solid = uses, dashed = over the network) and, under the
   diagram, the same connections as six short sentences, one per source. On a phone they carry the
   meaning, and screen readers read them. The SVG has a title and is labelled by it.
3. **Responsive.** On wide screens the diagram fills the card. Below 760 px it keeps a readable size
   and scrolls sideways inside its own container, as the roles table did. The page itself never
   overflows.
4. **Texts.** All names, technologies, edge labels, the legend and the sentences come from
   `en.json` / `de.json` (identical keys, du-form, `ss`). Technology names stay as they are. The
   unused `areas.roles.*` keys are removed.
5. **Page bookkeeping.** Masthead "Last change" P0-47 with the change-file time, task list, asset
   `?v=P0-47`, README (the P0-45 section and a P0-47 section) and the evidence list.

**Why:** the owner wants to see how the areas depend on each other, not only who owns them. The
area cards already name their owner role.

**Satisfies:** D3
