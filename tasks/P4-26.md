# P4-26 — Zones as containers II: platform migration and containment (L08)

## Goal

A new migration stores zones and turns the existing nullable `cards.zone_id` into a reference to a
zone of the same board, under the board's row-level security; nested zones stay impossible, the
`zoneId` mapping stays intact, and migration, api and RLS tests cover valid and invalid containment.

**Why:** ADR-0010 (Q17) makes zones containers; membership must be stored and guarded like its
board (AD-4, AD-5) before P4-27 builds engine membership on it.

**Satisfies:** D10

## Scope

- `infra/migrations/0005_zone_containers.sql` (0001–0004 stay byte-identical):
  - `app.zones` with the contract 0.2.0 zone fields: `id` PK, `board_id` (FK boards, cascade),
    `title` 1–200, `x`, `y`, `width >= 256`, `height >= 192`, `z` (format like `cards_z_format`),
    timestamps; **no parent column** (no nested zones); `UNIQUE (board_id, id)`; index
    `(board_id, z)`.
  - Composite key `cards (board_id, zone_id) -> zones (board_id, id)`, `ON DELETE SET NULL (zone_id)`
    (ADR-0010 "keep content"; "delete content" is a P4-27 operation). Unresolvable legacy
    `zone_id`s are set to `null` first.
  - `zones.board_id` immutable (trigger like `protect_board_workspace`).
  - RLS enabled and forced on `zones` with the card matrix (`is_board_member` read,
    `can_write_board` write), grants to `app_user`, trigger function not executable by `PUBLIC`.
- `services/platform/`: card create/update with a non-null `zoneId` checks through RLS that the zone
  belongs to the card's board, else `422 validation_failed` (`card.zoneId` / `changes.zoneId`); a
  `23503` on the zone key maps to the same 422, never a 500.
- Tests: migration suite (table, keys, policies, no parent column, cross-board/dangling `23503`,
  delete keeps cards, immutable board); api (allow: create in zone, PATCH out and in; deny: other
  board, foreign workspace, card id, unknown id → 422; reader 403); RLS (foreign zones invisible and
  unwritable, reader cannot write, foreign-zone card insert rejected).
- `.changes/P4-26-zone-containers.md` (area `platform`, kind `minor`).

## Out of scope

- Zone REST routes and SDK methods: contract 0.2.0 has no zone REST envelopes; `packages/sdk` stays
  unchanged (card `zoneId` is already mapped).
- Blocks: no block table exists yet; the block parent gets the same key with block storage.
- P4-27 behaviour, contract changes, `packages/engine/`, new dependencies.

## Acceptance

A1 WHEN the migrations run on an empty or a 0004 database, THEN 0005 applies once with its checksum,
creates `app.zones` with forced RLS and the card key, and a rerun is a no-op (`db-migrate`, `unit`).
A2 WHEN a card names a zone of its own board, THEN create/update succeed; WHEN it names another
board's zone, a foreign zone, a non-zone or an unknown id, THEN the API answers 422 and the database
`23503`; deleting a zone keeps its cards at board level (`api-tests`, `unit`).
A3 WHEN a second account or a reader acts on zones, THEN foreign zones are invisible and unwritable
and readers cannot write (`rls-tests`); all six gates exit 0 with records.

## Specifications

- The composite key enforces ADR-0010's referential rule for every role; RLS only adds visibility.
  Referential actions bypass RLS, so `SET NULL` works for `app_user`.
- Unknown and foreign zones give the same 422 (no probing).
- **Lead-approved inventory update:** the exact lists in `test/migrations/schema.test.mjs`
  (migrations, columns, types, keys, policies, indexes) and `APPLICATION_TABLES` in `support.mjs`
  are extended additively with the 0005 entries; nothing is removed or weakened.
- New cases go into the existing files (each file resets the slot database in `before`).
- The backfill needs an RLS-bypassing migration owner, as documented in 0003/0004.

## Pitfalls

- `SET NULL` without the column list nulls `board_id` too; PostgreSQL 17 supports `SET NULL (zone_id)`.
- RLS tests as the slot owner prove nothing; use `app_user`.
- Run `board-check` before any `pnpm` command; DB suites need this worktree's slot, never slot 0.

## Edge cases

- `zoneId: null` and absent both mean board level.
- A board deletion cascades zones and cards without a key error.
- A zone deleted before a PATCH moves a card into it: 422.
