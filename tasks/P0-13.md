# P0-13 — design-check gate

## Goal

`tools/design-check` rejects raw colours, off-grid spacing, `z-index` values outside the layer
model and missing UI evidence, and runs locally as the `design-check` gate.

**Why:** design rules must be enforced by a tool, not by memory (D3); `language-check` (P0-18) and
the CI wiring (P0-08, remote stage) build on the same pattern.

**Satisfies:** D3

## Scope

- `tools/design-check/`: a dependency-free Node.js ESM package (Node builtins only) with a CLI
  `node tools/design-check/index.mjs [root]`, unit tests and a README/ARCHITECTURE update.
- Read the allowed values from the generated design source, never duplicate them:
  `packages/ui-kit/tokens.json` (colour names, spacing/size/radius values) and
  `packages/ui-kit/layers.ts` (layer order and z-index values).
- Checks over the project sources (`apps/`, `packages/ui-kit/`, `packages/editor/`,
  `packages/engine/src/render/` when present; ignore `node_modules/`, `.git/`, `.turbo/`,
  `reference/`, `reviews/`, `docs/`, the generated `tokens.css`/`tokens.h`/`tokens.json`/
  `layers.ts` and test fixtures):
  1. **Raw colours:** hex, `rgb()`, `rgba()`, `hsl()`, `hsla()` outside the token files; only
     `var(--…)` / token references are allowed. `currentColor` is allowed.
  2. **Off-grid spacing:** numeric `margin`, `padding`, `gap`, `row-gap`, `column-gap`, `inset`,
     `top`, `right`, `bottom`, `left` values in CSS/HTML style attributes must be 0 or a multiple
     of 4 (the 4-px series); `var(--…)` is allowed. Non-px units and `calc()` are skipped but named
     in the output.
  3. **z-index:** numeric `z-index` must be one of the layer z-index values from `layers.ts`;
     `var(--…)` is allowed.
  4. **UI evidence:** when `--task <ID>` is passed, changed UI files require
     `reviews/evidence/<ID>-before-*.png` and `reviews/evidence/<ID>-after-*.png`; without
     `--task` the rule is skipped (it is for UI tasks, not the repo-wide gate).
- Output one line per finding: `file:line: rule: message`; exit 0 clean, 1 findings, 2 usage error.
- Unit tests with fixtures under `tools/design-check/test/fixtures/`: a clean fixture and one per
  rule (raw colour, off-grid spacing, bad z-index, missing evidence), plus ignore rules
  (tokens/reference/node_modules) and a clean run on the repository.
- `tools/design-check/README.md` and `ARCHITECTURE.md`: rule list, CLI flags, ignore list, commands.
- `package.json` scripts: `test` (`node --test test/*.test.mjs`) and, if the root tooling supports
  it for `.mjs`, a `lint`/`typecheck` script; no new dependencies.

## Out of scope

- CI workflow file (P0-08, remote stage), token values (P0-12), language checks (P0-18), UI code.
- Changes outside `tools/design-check/`.

## Acceptance

A1 WHEN design-check runs on this repository, THEN it exits 0; on each violation fixture it exits 1
and names file, line and rule (raw colour, off-grid spacing, z-index, missing evidence).
A2 WHEN the generated token/layer files, `reference/` or `node_modules/` contain values that would
otherwise violate, THEN design-check ignores them.
A3 WHEN the unit suite runs, THEN every rule and the clean case are covered and pass.
A4 WHEN the `design-check` and `unit` gates run through `gate.py`, THEN both exit 0 and the records
are committed; `python3 $POLIER/tools/check.py .` exits 0 (run it before `pnpm install`).

## Specifications

- **Language:** Node.js ESM (`.mjs`), Node builtins only; deterministic output; no network.
- **Colour detection:** word-boundary regex for `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`,
  `rgb(`, `rgba(`, `hsl(`, `hsla(`; ignore comments only when clearly not code (keep it simple and
  document known limits).
- **Spacing detection:** CSS declarations and `style="…"` attributes; only the properties listed
  above; allow negative multiples of 4; allow `0`.
- **Ignore list:** `node_modules/`, `.git/`, `.turbo/`, `reference/`, `reviews/`, `docs/`,
  `packages/ui-kit/tokens.css`, `tokens.h`, `tokens.json`, `layers.ts`, `tests/fixtures/` and the
  tool's own fixtures.
- **CLI:** `node tools/design-check/index.mjs [root] [--task ID] [--json]`; default root `.`.
- **Evidence rule:** check the two screenshot globs only when `--task` is given; name the exact
  missing pattern.
- **Commands:** report the exact `design-check` and `unit` commands for `docs/quality.md`.

## Pitfalls

- Do not flag SVG geometry (`viewBox`, `stroke-width`, path data) as spacing; only CSS spacing
  properties and `style` attributes.
- Do not flag `var(--…)`, `currentColor`, percentages, `rem`/`em` or `calc()` as raw values.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm install`.
- Keep findings deterministic (sorted files, ascending line numbers).

## Edge cases

- Empty project / no matching files → exit 0.
- A file with multiple findings → one line per finding.
- Missing tokens.json/layers.ts → exit 2 with a clear message (configuration, not a violation).
- A UI task without screenshots → finding only with `--task`, exit 1.

## Gates

1. `design-check`: `node tools/design-check/index.mjs .` → exit 0.
2. `unit`: `pnpm --filter ./tools/design-check test` → exit 0.
3. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0 (before `pnpm install`).

## Limits

- **Scope:** only `tools/design-check/`; gate records under reviews/evidence are always allowed.
- **Stop:** 2 rounds; when blocked, `status: blocked` + reason.
