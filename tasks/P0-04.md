# P0-04 — Workspaces, build orchestration and pinned versions

## Goal

The root workspace installs reproducibly from a lockfile, builds and tests only affected packages,
and every tool version is pinned in `docs/versions.md`.

**Why:** every package task needs working install, lint, typecheck and test commands; the CI
skeleton (P0-08), tokens (P0-12) and the i18n scaffold (P0-18) depend on them.

**Satisfies:** D1

## Scope

- Implement the owner's Q2 answer (answered 2026-10-25): **pnpm workspaces + Turborepo**. Write
  `pnpm-workspace.yaml` covering `packages/*`, `services/*`, `apps/*`, `tools/*`; root
  `package.json` with `packageManager` pinned to the installed pnpm; `turbo.json` with the
  `lint`, `typecheck`, `test` and `build` tasks and affected-only execution.
- Root `tsconfig.json` solution file (empty project is valid) plus `tsconfig.base.json`; Node
  version file; lint config; scripts for `lint`, `typecheck`, `test`, `build` that run only
  affected packages.
- Lockfile committed.
- `docs/versions.md`: one row per tool and dev dependency (exact version, source URL, date,
  approved by).
- `docs/module-map.md`: add the install/build/lint/typecheck/test commands per package kind.
- `AGENTS.md`: replace the line "defined by P0-04" with the real commands (≤ 400 words total).

## Out of scope

- Package code, tests beyond one smoke test per tool, CI workflow (P0-08), local services (P0-07).

## Acceptance

A1 WHEN the root workspace is inspected, THEN it uses pnpm workspaces and Turborepo as answered in
Q2, with `packageManager` pinned to an exact pnpm version and every tool version listed in
`docs/versions.md`.
A2 WHEN a fresh clone runs the clean-install command, THEN it exits 0 and the lockfile is unchanged.
A3 WHEN `lint`, `typecheck` and `test` run at the root on the empty workspace, THEN each exits 0.
A4 WHEN `python3 $POLIER/tools/check.py .` runs, THEN it exits 0 without a warning about a manifest
dependency missing from `docs/versions.md`.

## Pitfalls

- No new dependency without the owner's approval (Q2 answer covers pnpm and Turborepo; the dev
  dependencies needed for lint/typecheck are part of this task and must be MIT/BSD/Apache/ISC/Zlib
  and recorded in `docs/versions.md`).
- Do not add frameworks for later stages (web framework, test runners for e2e) now.
- Turborepo may report an error or a warning on an empty workspace; make `lint`, `typecheck` and
  `test` exit 0 with zero packages that define the task without adding per-package manifests
  outside the scope and without `|| true` hiding failures.
- Only one lockfile: `pnpm-lock.yaml`. Do not create `package-lock.json` or a second lockfile.

## Edge cases

- Empty workspace: test and lint scripts must succeed with zero packages that have code.
