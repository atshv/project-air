# P0-04 — Workspaces, build orchestration and pinned versions

## Goal

The root workspace installs reproducibly from a lockfile, builds and tests only affected packages,
and every tool version is pinned in `docs/versions.md`.

**Why:** every package task needs working install, lint, typecheck and test commands; the CI
skeleton (P0-08), tokens (P0-12) and the i18n scaffold (P0-18) depend on them.

**Satisfies:** D1

## Scope

- Propose to the owner, before writing files, the package manager and build orchestrator
  (open question Q2) with two options each: name, licence, current version from the official
  source with URL and date, and one sentence trade-off. Wait for the answer.
- Root manifest with workspaces covering `packages/*`, `services/*`, `apps/*`, `tools/*`; Node
  version file; shared TypeScript base config; lint config; scripts for `lint`, `typecheck`,
  `test`, `build` that run only affected packages.
- Lockfile committed.
- `docs/versions.md`: one row per tool and dev dependency (exact version, source URL, date,
  approved by).
- `docs/module-map.md`: add the install/build/lint/typecheck/test commands per package kind.
- `AGENTS.md`: replace the line "defined by P0-04" with the real commands (≤ 400 words total).

## Out of scope

- Package code, tests beyond one smoke test per tool, CI workflow (P0-08), local services (P0-07).

## Acceptance

A1 WHEN the owner has not answered Q2, THEN no manifest or lockfile is written.
A2 WHEN a fresh clone runs the clean-install command, THEN it exits 0 and the lockfile is unchanged.
A3 WHEN `lint`, `typecheck` and `test` run at the root on the empty workspace, THEN each exits 0.
A4 WHEN `python3 $POLIER/tools/check.py .` runs, THEN it exits 0 without a warning about a manifest
dependency missing from `docs/versions.md`.

## Context pack

**Read exactly:**

- `ARCHITECTURE.md`, `AGENTS.md`, `STATUS.md`, `docs/module-map.md`, `docs/quality.md`
- `docs/gates/node-ts.md`
- `docs/versions.md`

**Do not read:** other briefs, `reference/`, `docs/owner/`.

**Budget:** ≤ 25k tokens input.

## Specifications

- **Files (only those of the chosen tools):** `package.json`, one lockfile, workspace file if the
  package manager needs one, orchestrator config, `tsconfig.base.json`, `.nvmrc`, `.npmrc` if
  needed, `eslint.config.mjs`.
- **Versions:** exact (no ranges in the root manifest for tooling), from the official registry or
  release page, cited in `docs/versions.md`.
- **Licences:** MIT, BSD, Apache-2.0, ISC, Zlib only.
- **Gate commands:** write the final `install` and `unit` commands into the result; the lead copies
  them into `docs/quality.md`.

## Pitfalls

- No new dependency without the owner's approval (Q2 answer counts as approval for the chosen
  tools only).
- Do not add frameworks for later stages (web framework, test runners for e2e) now.

## Edge cases

- Empty workspace: test and lint scripts must succeed with zero packages that have code.

## Gates

1. `install`: the clean-install command chosen in this task → exit 0, lockfile unchanged.
2. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0.

## Limits

- **Scope:** only `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `turbo.json`, `nx.json`, `tsconfig.base.json`, `.nvmrc`, `.npmrc`, `eslint.config.mjs`, `docs/versions.md`, `docs/module-map.md`, `AGENTS.md`.
- **Stop:** 3 rounds; when blocked, `status: blocked` + reason.
