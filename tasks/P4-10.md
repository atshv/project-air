# P4-10 — Titles, previews and visible quality (L02)

## Goal

Card titles render single-line with an ellipsis at 15 px/600 from tokens, block and zone headers are
40 px with their content starting below the header, blocks grow instead of scrolling internally, and
delete affordances stay quiet at rest; the visible defects are evidenced before and after with
reviewed reference images.

**Why:** L02 is the engine entry for "nothing on the canvas looks cut off, doubled or random". The
text atlas and layout from P4-08/P4-09 render text; this task binds it to objects and fixes the
visual geometry of cards, blocks and zones.

**Satisfies:** D10

## Scope

- `packages/engine/` presentation binding: the caller (playground/test-kit scene) supplies a title and
  a short preview per visible object (keyed by object id); the engine draws them through the P4-09
  layout (`ellipsis` for titles, `wrap`/clip for previews) culled with the object, DPR-independently,
  using only token typography. The engine document keeps no note content; titles are presentation
  input, not board state.
- `packages/engine/` chrome geometry: a 40 px header band (token) for blocks and zones, zone content
  inset below its header (top padding 40 + 16 px), block preview clipped to its own height with no
  internal scrolling, and the layer/tone values unchanged; the text/quad geometry stays deterministic
  for identical input.
- `apps/engine-playground/`: deterministic demo objects with titles/previews (Latin-1 letters and an
  ellipsis case), a quiet DOM delete affordance (28 px hit area, 16 px icon, invisible at rest,
  visible on hover, focus-within and selection, reachable by Tab) in the overlay layer, and a
  `?text=titles` visual scene showing a normal title, a cut title, a header and a grown block.
- Tests: native tests for header geometry, zone content inset, title ellipsis placement and preview
  clipping; a deterministic scene for the visual gate.
- Visual evidence: before/after reference images of the eight L02 defects that are engine-owned
  (title cut-off/ellipsis, header height, zone content under the header, inner scrollbar, quiet delete
  button, doubled text) and a reviewed update of the affected baselines; the change is recorded in the
  Baseline history.
- `docs/engine.md`: document the title/preview binding, the header/inset geometry and the delete
  affordance split (canvas geometry vs DOM chrome).
- `.changes/P4-10-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Note content, the side panel, the editor, title editing (L09/web-app); WebGPU text; images; L03;
  snapping/selection; new dependencies; changing the atlas/layout beyond the binding (P4-08/09 own them).

## Specifications

- Typography, header height and spacing come only from tokens (no literals).
- Titles are presentation input: the engine draws them for visible objects and never stores note text
  in the document or the operation seam (AD-4).
- The delete affordance is DOM chrome (ADR-0009), not a canvas glyph; no "×", emoji or native tooltip.
- Baselines affected by text/headers update only through the reviewed `--update` path and the Baseline
  history; all other baselines stay 0-diff.
- The benchmark/perf scenes carry no titles, so the perf path is unchanged.

## Pitfalls

- Bind titles only for visible objects (culling) and keep the benchmark scene textless.
- A header added as extra instances must not break count assertions; derive it from geometry or a
  documented chrome class.
- Ellipsis at the wrong width (CSS vs device px) clips a glyph or overlaps the header.
- `check.py` scans `node_modules/`; run `board-check` before `pnpm install`.

## Edge cases

- Empty title, a title of exactly the box width, a single very wide glyph, a Latin-1 umlaut and a
  missing glyph.
- Zone with no content, block with zero preview lines, selected vs hovered delete affordance.
