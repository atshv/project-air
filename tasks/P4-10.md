# P4-10 — Titles, previews and visible quality (L02)

## Goal

Card and zone titles render single-line with an ellipsis at 15 px/600 from tokens, the text is
re-rasterised on zoom so it stays sharp when zooming in, block and zone headers are 40 px with their
content starting below the header, blocks grow instead of scrolling internally, and delete affordances
stay quiet at rest; the visible defects are evidenced before and after with reviewed reference images,
and the perf and idle measurements are re-run after the binding.

**Why:** L02 is the entry for "nothing looks cut off, doubled or random"; P4-08/P4-09 render text, this
task binds it to objects and fixes the visual geometry.

**Satisfies:** D10

## Scope

- `packages/engine/` presentation binding: the caller (playground/test-kit scene) supplies a title and
  a short preview per visible object, including zone names (keyed by object id); the engine draws them
  through the P4-09 layout (`ellipsis` for titles, `wrap`/clip for previews) culled with the object,
  using only token typography. The engine document keeps no note content; titles are presentation
  input, not board state.
- `packages/engine/` zoom sharpness: rebuild the atlas/layout on a documented zoom bucket (for example
  25 %, 50 %, 100 %, 200 %) so text stays sharp when zooming in, with a bounded number of rebuilds;
  the reference image is captured at 100 %; a 200 % capture follows once sharp.
- `packages/engine/` chrome geometry: a 40 px header band (token) for blocks and zones, zone content
  inset below its header (top padding 40 + 16 px), block preview clipped to its own height with no
  internal scrolling, and the layer/tone values unchanged; the text/quad geometry stays deterministic
  for identical input.
- `apps/engine-playground/`: demo titles/previews (Latin-1, one ellipsis case) incl. zone names, a
  quiet DOM delete affordance (28 px hit, 16 px icon, invisible at rest, visible on hover/focus/
  selection, Tab-reachable) and a `?text=titles` scene with a normal title, a cut title, a header and
  a grown block.
- Tests: native tests for header geometry, zone content inset, title ellipsis placement and preview
  clipping; a deterministic scene for the visual gate.
- Visual evidence: before/after images of the engine-owned L02 defects and a reviewed baseline update,
  recorded in the Baseline history.
- `docs/engine.md`: document the title/preview binding, the header/inset geometry and the delete
  affordance split (canvas geometry vs DOM chrome).
- `.changes/P4-10-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Note content, the side panel, the editor, title editing (L09/web-app); WebGPU text; images; L03;
  snapping/selection; new dependencies; changing the atlas/layout beyond the binding (P4-08/09 own them).

## Acceptance

A1 WHEN the titles scene renders, THEN card titles are one line at 15 px/600 from tokens, cut with an
ellipsis when they do not fit, block and zone headers are 40 px, and zone content starts below the
header; native tests and the reference image confirm it.
A2 WHEN a block shows a preview, THEN the block grows to its content height instead of gaining an
inner scrollbar, and the delete affordance is invisible at rest but visible on hover, focus and
selection and reachable by Tab, with no character used as an icon.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `cpp-unit`, `visual`, `design-check` and
`perf` exit 0 with records under `reviews/evidence/`, and the before/after reference images and the
reviewed baseline update are committed (Baseline history updated).
A4 WHEN the title binding is in place, THEN the perf gate still passes (10,000 objects, p95 <= 16.7 ms,
0 frame intervals > 16.7 ms) and the idle record still shows zero rendered frames in idle seconds,
with both records committed.

## Specifications

- Typography, header height and spacing come only from tokens (no literals).
- Titles are presentation input: never stored in the document or the operation seam (AD-4).
- The delete affordance is DOM chrome (ADR-0009), not a canvas glyph; no "×", emoji or native tooltip.
- Baseline updates only through the reviewed `--update` path and the Baseline history; all other
  baselines stay 0-diff. Re-run `perf` and the idle harness after the binding.

## Pitfalls

- Bind titles only for visible objects and keep the benchmark scene textless.
- A header added as extra instances must not break count assertions; derive it from geometry.
- Ellipsis at the wrong width (CSS vs device px) clips a glyph or overlaps the header.
- `check.py` scans `node_modules/`; run `board-check` before `pnpm install`.
