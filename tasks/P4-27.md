# P4-27 — Zones as containers II: engine membership and zone move (L08)

## Goal

Dropping an object with its centre inside a zone stores membership through exactly one operation with
inverse and highlights the zone for 1 s in `tokens::accent_line`; dragging a member out releases it;
dragging a zone moves its content with it as one group operation; the `deleteZone` content policy
(keep vs delete content) applies as one operation with inverse; zones never nest and a zone never
shrinks below its content extent + 16 px.

**Why:** L08 is the interaction half of the approved zone container decision (ADR-0010, contract
0.2.0, database in P4-26); without it zones are only decorative.

**Satisfies:** D10

## Scope

- `packages/engine/` port and document: `zoneId` on cards and blocks in the working copy,
  applied/removed by the existing `moveCard`/`moveBlock` payload (present or null); a byte-identical
  snapshot round trip proves membership survives serialisation; zones never carry a parent.
- `packages/engine/` drop policy: on release an object whose centre lies inside a live zone gets it
  as parent inside the same single move operation; nesting a zone is rejected; a member whose centre
  leaves the zone gets `zoneId: null` in its move. Membership is never a separate write or per-frame.
- `packages/engine/` zone move: dragging a zone with members commits one `drag-group` gesture whose
  group operation moves zone and members by the same delta, with one inverse restoring every
  position; no per-member operation.
- `packages/engine/` `deleteZone` policy: keep moves members to the board (`zoneId: null`) in the
  same operation, delete removes them with the zone; both carry an inverse that restores or reparents
  exactly (contract 0.2.0). The dialog belongs to the web app.
- `packages/engine/` geometry guard: minimum zone size = member extent + 16 px
  (`tokens::space_16`), as a pure helper enforced by the seam; the resize gesture is P4-17.
- `packages/engine/` zone highlight: 1 s `tokens::accent_line` outline in the chrome pass after a
  drop, presentation-only, never a command-buffer instance or document state.
- `apps/engine-playground/`: sample and `?scene=layers` demonstrate drop-in with highlight,
  drag-out, group zone move and the delete policy in memory; a capture record under
  `reviews/evidence/` proves the highlight and a moved zone with members.
- Tests: drop/out/reject, one operation per drop and release, group move with exact inverse,
  `deleteZone` both policies, snapshot round trip, minimum size and the highlight state; `cpp-unit`
  regression. `.changes/P4-27-<short-name>.md` (area `engine`, kind `minor`); `docs/engine.md`
  documents membership, drop/highlight, group zone move and the delete policy.

## Specifications

- Tokens only: `--accent-line` 1 px, 1 s highlight, 16 px inset; no raw values (design-check).
- Membership is working-copy state written only through contract operations; the highlight is
  presentation state and never enters the document.
- One gesture = one operation (AD-1): drop, drag-out, group move and delete each produce one
  operation with inverse; the group move is one `group`.
- Zones never nest in v1; a zone parent is rejected.
- `visual` is exclusive: never run it next to another browser gate.

## Pitfalls

- Writing membership before release creates intermediate states; commit only on release, in the same
  operation.
- A group inverse missing a member leaves a half-restored board; test the byte-identical snapshot
  after undo.
- Centres compared in screen px break at zoom; the drop test is world px.
- A highlight as a command-buffer instance drifts the `visual` gate; keep it in the chrome pass.
- Rebuild bridge/WASM before the capture; run `board-check` before any `pnpm` command.
