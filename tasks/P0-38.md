# P0-38 — Layer order: edges below zones

> Design law and token change. Owner decision 2026-10-28 (P0-36), confirmed with "Ja, festhalten".

## Goal

Connection lines (edges) lie behind every object on the canvas, zones included. Until now design law
§8 put zones at layer 2 and edges at layer 3, so a line ran over a zone's surface; the live demo has
deviated since P0-36 (`.demo__edge` on `--layer-canvas-background`). This task makes the new order
the law everywhere it is fixed:

1. **Design law** — `docs/design-rules.md` §8: `1 Canvas background`, `2 Edges (connections)`,
   `3 Zones`, then blocks 4 … dialogs 11 unchanged. A short note says why: a line must never cross a
   zone's surface or title.
2. **ADR-0013** — `docs/adr/ADR-0013-edges-below-zones.md` records the decision, the alternatives
   (keep §8 and accept lines over zones; draw lines only between zone edges) and the consequences.
   `board.json` lists it under `decisions`.
3. **Tokens** — `packages/ui-kit/tokens.json` swaps the two entries (`edges` order "2", z-index 2;
   `zones` order "3", z-index 3); the generated `tokens.css`, `tokens.h` and `layers.ts` are rebuilt
   with the existing codegen, never edited by hand. The ui-kit token test's expected layer table
   follows the law (owner-approved test change, recorded in the review).
4. **Engine** — no draw-order change: the engine draws only zones, blocks and note cards as
   rectangles, and zones stay the lowest of those. `Layer::zones` keeps reading
   `tokens::layer_zones` (now 3); the `doc.h` comment quotes the new §8 rows. `docs/engine.md`
   names the new numbers (zones 3, edges 2 reserved, not drawn by the engine).
5. **Design-system page** — `apps/web/preview/`: section 06 lists the layers in the new order with
   the new numbers; `.demo__edge` goes back to `var(--layer-edges)` and the P0-36 deviation comment
   is removed; the README notes that mention the deviation or the open question are updated;
   masthead P0-38, asset `?v=P0-38`.

**Why:** the owner judges the product by the live demo; a deviation that only lives in a CSS comment
is not a rule. Tokens, engine header and docs must say the same thing (AD-7, design rule §13).

**Satisfies:** D3
