# P0-21 — Match the demo connection to the design system

## Goal

The live demo's connection edge uses the same style as the design system's connection component:
stroke and endpoint dots in `--tone-d`, 1.5 px (`--border-width-strong`), and the preview keeps the
demo permanently with every future preview update.

**Why:** the owner noticed the demo edge used `--border-strong` instead of the design system's
`--tone-d` connection style; the demo must feel like the product.

**Satisfies:** D3

## Scope

- `apps/web/preview/`: change the demo edge styling (`.demo__edge-line`, `.demo__edge-dot`) to
  `var(--tone-d)` and `var(--border-width-strong)`; state the style in the demo hint/legend
  (`edge · --tone-d · 1.5 px`); no raw colours, no new tokens.
- `apps/web/preview/README.md`: state that the demo is permanent and is updated together with every
  preview or design-system change (same task, same screenshot refresh).
- Refresh `reviews/evidence/P0-21-demo.png` (1440×900) after the change; keep the P0-20 screenshot
  untouched.
- `.changes/P0-21-demo-connection.md` (area `web`, kind `patch`, one English line).

## Out of scope

- Changing the static Connection component, design tokens, engine, data, or the demo's interaction
  logic (drag/keyboard already work).
- Changes outside `apps/web/preview/` and `.changes/`.

## Acceptance

A1 WHEN the demo edge is inspected, THEN its line and endpoint dots use `--tone-d` with
`--border-width-strong` (1.5 px), matching the static Connection component; no raw colours.
A2 WHEN the preview README is read, THEN it states that the demo is permanent and must be updated
in the same task as every preview/design-system change; the refreshed screenshot shows the new
edge colour.
A3 WHEN `board-check`, `design-check` and `changelog-entry` gates run, THEN all exit 0 with records
committed; `python3 $POLIER/tools/check.py .` exits 0 (before `pnpm install`).
