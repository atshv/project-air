# P6-12 — CI passes on GitHub for the current main

## Goal

The existing CI workflow (`.github/workflows/ci.yml`) passes on a GitHub pull request against
`main`. Lint runs after the workspace packages are built, the database-backed tests run on a CI
slot against the compose stack, and the code and test-expectation defects that the first real run
exposed are fixed.

**Why:** the first GitHub CI run (PR 1, run `40910412721`) failed on code already on `main`.
Every pull request stays red until CI matches what the local gates prove. The owner pulled this
forward from the `remote` stage on 2026-10-29. Branch protection (`P0-02`), releases (`P0-15`,
`P0-17`) and dependency updates (`P0-16`) stay in `remote`.

**Satisfies:** D6

  `dist/` in a fresh clone (web and sync reach the SDK by relative path, not as a dependency).

the compose stack and `tools/dev/setup`, THEN all three exit 0.
A2 WHEN the CI workflow runs on a pull request against `main`, THEN the job

A3 WHEN the task is done, THEN the three approved test-file changes are data/portability only,

## Specifications

- The CI slot comes from `slot.py acquire` inside a git worktree, never a hand-written
  `.polier-slot` and never slot 0.
- Secrets: the `app_user` password is generated by `tools/dev/setup` into the gitignored
  `infra/compose/.env` and is never printed.
- Lint fixes keep behaviour: a promise in an event handler gets `void` plus the existing error
  handling, and a non-promise is not awaited.

## Pitfalls

- `turbo` lint without `^build` passes locally only when `dist/` is left over from an earlier build.
- `tools/dev/setup` refuses slot 0; the main checkout on the runner is slot 0.
- `parity.test.mjs` prefers `clang++`; `g++` hides the incomplete-type error.
