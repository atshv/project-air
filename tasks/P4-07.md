# P4-07 — Canvas feel: fit, dot grid and idle drawing (L19)

## Goal

"Alles anzeigen" fits the board at most to 100 % and keeps the L02 padding free at the top, the dot
grid hides below zoom 0.5 and the playground renders only on change, so an idle canvas produces no
frames.

**Why:** L19 is the calm-canvas entry; the fit rule, the grid threshold and on-demand drawing also
keep the perf gate honest and the canvas quiet.

**Satisfies:** D10

## Scope

- `packages/engine/` camera: a fit helper that takes the board's world bounds and the viewport and
  returns pan/zoom with the zoom clamped to at most 1.0 and never below the existing minimum; it
  keeps at least 64 px (bar 48 px + 16 px) free above the fitted content (L02 target). Invalid or
  empty bounds are handled explicitly (a single card still fits at 100 % at most).
- `packages/engine/` renderer: the dot grid as the bottom chrome layer — dots in the token colour
  (`tokens::faint`) on the token canvas colour (`tokens::canvas`), 16 px world spacing from
  `tokens::canvas_grid`, aligned with the camera; the grid is hidden below zoom 0.5 and needs no
  per-dot instance upload.
- `apps/engine-playground/`: a "fit" action (button or key, labels existing style), on-demand
  rendering — `renderFrame` only after a camera, document or resize change; the benchmark mode keeps
  its continuous loop unchanged for the perf gate. A small counter/ready hook exposes rendered
  frames so idle behaviour is measurable.
- Tests: native tests for the fit helper (one card, wide board, empty document, padding, zoom clamp)
  and for the grid visibility threshold; a browser record that idle for one second renders zero
  frames; a `visual` reference image for the fitted view with the grid.
- `docs/engine.md`: document fit, grid threshold and the on-demand rule.
- `.changes/P4-07-<short-name>.md` (area `engine`, kind `minor`).

## Out of scope

- Toolbar chrome (L00), selection/snap guides, trackpad gesture defaults (L15), zoom limit changes
  beyond fit, WebGPU, images.
- Persistent viewport storage (L17, `P4-22`), minimap or board cleanup (not in v1).
- New dependencies; changed or deleted tests.

## Acceptance

A1 WHEN the board is fitted with one card or a wide board, THEN the zoom is at most 100 %, the
content is fully visible and at least 64 px stay free above it; native tests cover the helper.
A2 WHEN the view is zoomed below 0.5, THEN the dot grid disappears, and at or above 0.5 it is visible
in `tokens::faint` on `tokens::canvas` with 16 px world spacing; a visual reference image shows it.
A3 WHEN the playground is idle for one second after a change, THEN it renders zero frames; native or
browser-backed evidence records the count, and the pan/zoom perf budget still passes (`perf`).

## Specifications

- Fit is a pure function of world bounds and viewport size: pan centres the content, zoom is
  `min(viewport/world, 1.0)` and never below the camera minimum; no special case per board type.
- The grid is chrome, not board content: it draws below everything, is not part of the command-buffer
  instance list and does not affect hit testing.
- On-demand rendering must not break the perf harness: keep `?bench=…` on the continuous rAF loop and
  record that difference in `docs/engine.md`.
- The visual baseline for this scene is reviewed like every other baseline; do not overwrite an
  existing baseline to make the gate pass.

## Pitfalls

- A grid drawn as one instance per dot defeats the perf target; use a shader pattern or a screen-space
  quad with the camera transform.
- Fitting to the viewport including the HUD can violate the 64 px rule; fit against the canvas
  viewport and assert the padding in a test.
- Stopping rAF without a way to schedule the next frame after a camera change hangs the canvas;
  centralise the "request one frame" path.
- `check.py` scans `node_modules/`; run `board-check` before any `pnpm` command.

## Edge cases

- Empty document: fit shows the origin at zoom 1.0 without a division by zero or NaN pan.
- A single card: fit lands at exactly 100 %, not above.
- Zoom exactly 0.5: define whether the grid is visible and test it.
- Device-pixel-ratio change: grid spacing stays 16 world px and stays crisp.
