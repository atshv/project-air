# P0-42 — Live demo: light theme with sun/moon icons under DE/EN

> Static design preview (`apps/web/preview/`). Owner note (2026-10-27): the live preview is not
> bound to the usual brief budgets.

## Goal

Owner request of 2026-10-28: "die helle Seite mit Sonne-/Mond-Icons unter DE/EN".

1. **Light theme.** The preview page gets a light variant: a `data-theme="light"` block overrides
   the colour tokens for the page and the demo board — background, surface, canvas, cards, checklists,
   zones, blocks, toolbar, frames, chips — with no dark remnant and no raw colour outside the block.
   Text keeps >= 4.5:1 contrast, icons/lines >= 3:1; the accent and tone colours get darker variants of
   the same hue; shadows become soft light-mode shadows, `color-scheme` is `light`. Dark stays default.
2. **Sun/moon toggle under DE/EN.** Below the language switch sits a theme group with two icon-only
   buttons (sun = light, moon = dark) as inline SVG line icons in ui-kit style (24 grid, 1.6 stroke,
   `currentColor`, round caps) — no character icons, no emoji, no external assets. The active button has
   `aria-pressed="true"`, the group a translated name, both buttons translated labels and a visible
   focus ring; Tab/Enter/Space work. The choice persists in `localStorage` (`preview-theme`), is read
   before first paint and is independent of the language choice.
3. **Both languages, both themes.** Every new label comes from `en.json`/`de.json` with identical
   keys, du-form, `ss` where German needs it; `DE`/`EN` keeps working as before. The P0-41 contents
   list, rounded frames and darker done entries behave the same in both themes (the done-entry value
   from design law §6 stays darker than open entries in the light palette too).

**Why:** the owner wants to judge the design in the bright variant, not only on the dark canvas, and
the theme switch belongs next to the existing language switch.

**Satisfies:** D3

## Specifications

- The dark design stays default; the light palette is preview-scoped in `preview.css` with a
  commented palette table and a note that promoting it into `packages/ui-kit/tokens.json` needs an
  owner decision.
- No raw colour, radius, spacing, shadow or motion value outside the theme block; everything else uses
  the token variables.
- The toggle is DOM chrome in the masthead following the locale-switch pattern: same markup shape,
  `aria-pressed`, one listener, one storage key, no framework.
- German uses `ss`, never `ß`; both locale files keep identical key sets.

## Pitfalls

- A stored theme applied after first paint flashes dark; set `data-theme` before the stylesheet
  paints (inline script in `<head>` or `preview.js` loaded early enough) and test a reload.
- Light-mode accent contrast: the dark `--accent` on white is too bright; use the darker accent and
  check every tone (a/b/c/d/e), danger and the teammate colours.
- The board's inline styles and the JS-set `--frame-radius` must follow the theme variables; grep
  for hex/rgba in `preview.js`/`index.html` before finishing.
- The P0-41 contents list uses `<details>`; the theme toggle must not steal its keyboard behaviour.
- `check.py` scans `node_modules/`; run `board-check` before `pnpm install`.
