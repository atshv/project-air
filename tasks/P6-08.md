# P6-08 — Contract 0.4.0 operation support in crdt and sync

## Goal

`packages/crdt` applies the 0.4.0 `updateNoteBody` operation (note body + plainText on the note, inverse
restores the previous body) in the document store and the Yjs adapter, snapshots/convergence include
note bodies and stay byte-identical under inverses, and `services/sync` accepts, persists, broadcasts
and replays `updateNoteBody` like any other operation with a live-socket test; the editor save path
(P6-07) then persists and reloads note bodies end to end.

**Why:** P6-06 added the operation and P6-07 emits it, but `packages/crdt`/`services/sync` predate
0.4.0 and reject it — the save path would silently lose note bodies (P6-07 A2 reload half).

**Satisfies:** D12

## Scope

- `packages/crdt/` document store + Yjs adapter: handle `updateNoteBody` — store the structured body
  and its derived `plainText` on the note entity (AD-4: notes exist once, cards reference them),
  reject unknown block/mark shapes consistently with the contract, and make the inverse restore the
  byte-identical previous note (body + plainText + `updatedAt` as the contract defines). Snapshots
  round-trip bodies; `encodeState`/`applyUpdate` and the conformance suite include body operations;
  unknown/future operation types keep failing closed.
- `packages/crdt/` tests: apply/inverse byte-identical state for `updateNoteBody` (a body with
  links/lists), two-replica convergence with body operations, snapshot round-trip with bodies, and
  the second fake adapter still passing the same suite (ADR-0011). Keep the 10k-round suite runtime
  reasonable with focused body scenarios instead of a larger loop.
- `services/sync/`: the operations log/replay/broadcast/catch-up paths must accept `updateNoteBody`
  (the log stores operations JSON and replays through `BoardDoc.apply` — remove any allow-list or
  validation that rejects it) and a fresh join's snapshot must contain body + plainText. Extend the
  live-socket integration test: one client sends an `updateNoteBody` batch, gets the ack/`serverSeq`,
  another receives the broadcast, a fresh join gets a snapshot with body + plainText, and catch-up
  replays it; the restart harness may take one body operation (keep it small).
- `.changes/P6-08-<short-name>.md` (area `sync` or `engine`, minor); one line in `docs/realtime.md`
  that contract 0.4.0 note-body operations are supported by log/replay.

## Out of scope

- Editor/panel UI (P6-07), platform REST note persistence (bodies live in the board document),
  search indexing (value), images/attachments, engine rendering of note bodies.

## Acceptance

A1 WHEN a `BoardDoc` applies `updateNoteBody`, THEN the note gets body + plainText, `snapshot()`

body operations (fake adapter included).

persisted, broadcast to other clients, replayed for catch-up, included in a fresh join's snapshot,
and survives the restart harness.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit` and `typecheck` exit 0 with
records (crdt + sync suites with the new tests), the editor save path can replay a body end to end,

## Specifications

- The contract is the model: apply exactly the 0.4.0 body shape, store `plainText` as given (the
  editor derives it, the CRDT preserves it), reject unknown fields like other operations.
- AD-4: the operation targets `noteId` in the board-content notes; a missing note is a rejected
  operation, not a silent create.
- Snapshots include `body`/`plainText` for notes that have them; notes without a body stay valid.
- The inverse is the previous body/plainText; applying it must yield byte-identical encoded
  state/snapshot (same assertion style as the existing suite).
- Sync: no second operation path; the generic log applies through the same `BoardDoc`; the live test
  proves ack → persist → broadcast → catch-up → snapshot.
- Keep the existing 10k-round suite green; never weaken assertions; add focused body tests.
- No new dependency; imports per `may_import` (crdt only contracts; sync contracts+crdt).

## Pitfalls

- Storing the body as a string instead of the structured JSON breaks the contract and the editor.
- Forgetting `plainText` makes reload/search inconsistent.
- The Yjs adapter may need a separate map for bodies; keep snapshots canonical so inverse checks
  are byte-identical.
- A sync allow-list may reject the new operation; use the generic path and never accept unknown
  future types silently.
- The restart harness expects baseline 1 / first batch 2 — a body batch must not change bootstrap.
- Bodies are small; no outbound-form limit concern, but keep the test realistic.
