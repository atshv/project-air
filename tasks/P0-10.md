# P0-10 — Adapt design rules to this project

## Goal

`docs/design-rules.md` exists, is derived from `reference/docs/design-rules.md`, applies to the
web app **and** the engine, and takes every value from `packages/ui-kit/tokens.json`.

**Why:** every UI and engine task cites these rules; P0-11 (acceptance catalogue), P0-12 (tokens)
and P0-13 (`design-check`) build on them.

**Satisfies:** D3

## Scope

- Copy the rules from `reference/docs/design-rules.md` and keep every value, rule and section
  that is not tied to the earlier prototype (principles, colours, spacing, radii, typography,
  icons, states, motion, layers, chrome, texts, acceptance).
- Adapt only what this project changes, each listed in a short "Changes from the reference"
  section at the end:
  - token source is `packages/ui-kit/tokens.json` (CSS custom properties and C++ header are
    generated), not a global CSS file;
  - icon source is `packages/ui-kit/icons/` (SVG), used by the web app and the engine atlas;
  - states (§6) and layers (§8) apply to objects drawn by the engine as well;
  - working rules point to Polier (worktree, slot, `gate.py`) and to `docs/canvas-acceptance.md`;
  - texts come from translation files (German always `ss`);
  - new short sections: realtime cursors and selection, engine (no design numbers outside the
    generated header), layout for translation (+40 % text, logical CSS directions).
- English throughout.

## Out of scope

- Creating `tokens.json` or icons (P0-12), the acceptance catalogue (P0-11), the check tool
  (P0-13).
- Any change to `reference/`.

## Acceptance

A1 WHEN `docs/design-rules.md` is compared with `reference/docs/design-rules.md`, THEN every
numeric value (spacing scale, radii, sizes, durations, font sizes, layer order) is the same, and
every deviation is listed in "Changes from the reference".
A2 WHEN the file is searched for names of the earlier prototype, its files or vendors, THEN there
are none.
A3 WHEN `python3 $POLIER/tools/check.py .` runs, THEN it exits 0.
