# P0-18 — i18n scaffold and language-check gate

## Goal

German and English message files with English keys exist in a framework-neutral ICU MessageFormat,
`docs/i18n/` holds the glossary and German style, and `tools/language-check` rejects German in code,
`ß` in German text and drifting message keys.

**Why:** AD-8 — the site stays translatable without code changes; the owner chose ICU files now and
an established library when the web framework is chosen (Q12).

**Satisfies:** D4

## Scope

- `apps/web/messages/`: `de.json` (German, complete starter set), `en.json` (same English keys),
  `en-XA.json` (pseudo-locale derived deterministically from `de.json` for layout tests) and
  `README.md` (key rules, how to add a language).
- `docs/i18n/glossary.md` (one term per thing, German/English) and `docs/i18n/style-de.md`
  (Du-Form, short labels, no exclamation marks, always `ss`, never `ß`, locale `de-DE`).
- `tools/language-check/`: dependency-free Node.js ESM package (Node builtins only) with CLI
  `node tools/language-check/index.mjs [root]`, unit tests and README/ARCHITECTURE update.
- Message content: derive the starter German values from `reference/src/ui/strings.de.ts`
  (canvas toolbar, save status, empty note, errors, panel labels) and write English keys and English
  values yourself; convert every `ß` to `ss`; no earlier-prototype names or file paths.
- Checks (documented and unit-tested):
  1. `de.json`, `en.json`, `en-XA.json` have exactly the same key set; keys are English
     (`lowerCamelCase` path segments) and contain no umlauts.
  2. ICU MessageFormat is valid: balanced braces, placeholders in every locale match the key's
     placeholders, plural/select forms have the required branches; report the key on error.
  3. `en-XA.json` is the deterministic pseudo-locale of `de.json` (same keys, pseudo values with a
     stable transformation); `--write-pseudo` regenerates it.
  4. No German in code: `.ts/.tsx/.js/.jsx/.mjs/.html/.css` under `apps/`, `packages/editor/`,
     `packages/ui-kit/` and `tools/` (outside `apps/web/messages/`) must not contain `ß` and must
     not contain German words/umlauts in user-facing strings; a small documented word list plus
     umlauts is enough for this stage. Report file and line.
  5. The translation files themselves use `ss`, never `ß` (also in `docs/i18n/`).
- Output `file:line: rule: message`; exit 0 clean, 1 findings, 2 usage/configuration error.
- `tools/language-check/package.json` scripts: `test` (`node --test test/*.test.mjs`) and, if
  supported, `lint`; generated pseudo file is committed.
- Unit tests with fixtures under `tools/language-check/test/fixtures/`: clean case, key drift,
  broken ICU, `ß` in code, German word in code, pseudo drift.

## Out of scope

- The i18n library, framework integration, server rendering, routing or UI (web-app stage).
- CI workflow file (P0-08, remote stage); changes outside the three scopes above.

## Acceptance

A1 WHEN the three message files are compared, THEN they have identical English keys and valid ICU
syntax; `en-XA.json` matches the deterministic pseudo transformation of `de.json`.
A2 WHEN a fixture has key drift, broken ICU, `ß` or German in code, THEN language-check exits 1 and
names file, line and rule; the real repository exits 0.
A3 WHEN `docs/i18n/` is read, THEN glossary and German style exist and state `ss`/`de-DE` and the
Du-Form.
A4 WHEN the `language-check` and `unit` gates run through `gate.py`, THEN both exit 0 and records
are committed; `python3 $POLIER/tools/check.py .` exits 0 (run it before `pnpm install`).

## Specifications

- **Format:** JSON objects, nested by area (`canvas`, `panel`, `errors`, …), values ICU strings,
  e.g. `"count": "{count, plural, one {# Element ausgewählt} other {# Elemente ausgewählt}}"`.
- **Keys:** English, lower camelCase, path by place and purpose, never the German text.
- **German:** `ss` never `ß`; Du-Form; short labels; no exclamation marks; no technical terms.
- **Pseudo-locale:** deterministic (e.g. wrap and expand letters), marked as pseudo, same keys as
  `de.json`; never shipped as a real language.
- **Language checker:** Node builtins only; deterministic findings; ignores `node_modules/`,
  `.git/`, `.turbo/`, `reference/`, `reviews/`, `docs/` (except the `ß` rule for `docs/i18n/`) and
  its own fixtures.
- **Comments/strings:** a documented, intentionally small German word list; false positives go into
  `open_questions`, do not weaken the rule silently.
- **Commands:** report the exact `language-check` and `unit` commands for `docs/quality.md`.

## Pitfalls

- `check.py` scans `node_modules/`; run `board-check` before any `pnpm install`.
- Do not copy prototype names, comments or file paths into the new message files.
- Do not invent a library; this task is files + checker only (Q12: library later).
- JSON must stay deterministic (sorted keys in the generator, stable indentation) so `--write-pseudo`
  produces no diff on a second run.
- Do not add `en-XA` to shipped locales; it exists only for layout tests.

## Edge cases

- A key present in `de.json` but missing in `en.json` → finding naming the key.
- A placeholder renamed in one locale → finding.
- A German word in a comment-only context: keep the rule on string literals; document the limit.
- `ß` in a German word that should use `ss` → finding, even inside a translation value.

## Gates

1. `language-check`: `node tools/language-check/index.mjs .` → exit 0.
2. `unit`: `pnpm --filter ./tools/language-check test` → exit 0.
3. `board-check`: `python3 $POLIER/tools/check.py .` → exit 0 (before `pnpm install`).

## Limits

- **Scope:** only `tools/language-check/`, `apps/web/messages/`, `docs/i18n/`; gate records under
  reviews/evidence are always allowed.
- **Stop:** 2 rounds; when blocked, `status: blocked` + reason.
