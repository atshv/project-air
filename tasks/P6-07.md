# P6-07 — Panel and editor: overlay, own editor, note placeholder and title (L04, L06, L09)

## Goal

`packages/editor` gets the own contenteditable editor (contract 0.4.0 structured JSON, inline
marks/links, plain-text extraction, selection preservation, IME-safe; no rich-text library) and
`apps/web` the 400 px right panel overlay (L04, 12 px gap, 180 ms, Esc, no canvas width change,
camera pan when the selected card is hidden), the empty-note focus/placeholder (L06) and the title
field (L09); content is saved as one contract operation with inverse through the SDK autosave path.

**Why:** the panel/editor is the content-editing surface of the product; ADR-0013 keeps the editor
our own code and P6-06 defines its document.

**Satisfies:** D12

## Scope

- `packages/editor/` (new code, framework-agnostic — no React import): a DOM editor controller with
  mount/unmount, document model per contract 0.4.0 (blocks: paragraph, heading, bullet/numbered
  list; inline marks: bold, italic, code, link), serialise/deserialise, deterministic `plainText`
  derivation exactly as the contract specifies, selection preservation across focus/save, IME
  composition safety, Enter/Tab list behaviour, paste as **plain text** (no HTML injection), link
  creation from a selection with href validation, accessible `role="textbox"`/`aria-multiline` and
  labels; the package's README/ARCHITECTURE commands and tests are filled in.
- `apps/web/` panel overlay (L04): 400 px right panel, 12 px gap, 180 ms translateX(16px)+opacity,
  Esc closes, the canvas width never changes, and when the selected card would be hidden the camera
  pans 300 ms so the card sits 24 px left of the panel; opens on card selection/open, keeps focus
  logic (panel shortcuts must not leak to the board keyboard layer).
- `apps/web/` empty note (L06) and title (L09): opening an empty note focuses the editor, shows the
  muted 15 px placeholder "Start writing …" which disappears on the first character and is never
  saved; the title field (serif 24 px, underline on hover/focus) validates like other titles
  (trim, length from the contract), Enter moves focus into the editor, errors come from messages.
- `apps/web/` saving: content changes go through the SDK autosave path (P5-04) as **one
  `updateNoteBody` operation per save** with its inverse; title edits are one `updateNote` operation;
  the panel never writes a second save path and never persists content itself (the L05 status UI is
  P6-08).
- `apps/web/` note/card wiring: the selected card resolves its note (AD-4: note exists once); editing
  reads/writes the board document through the SDK client so remote updates appear (P6-08 shows
  presence/save status), and a missing note/body falls back to the contract's empty body.
- Tests: editor model round-trip/serialise/parse/plainText, mark/link validation, paste sanitiser,
  placeholder/focus helper, title validation, panel state helper with `node --test`; DOM/engine
  behaviour is P6-09 e2e. `.changes/P6-07-<short-name>.md`.

## Out of scope

- The L05 save-status UI and presence (P6-08), e2e (P6-09), `[[Link]]` suggestion lists and search
  (value stage), image/attachment blocks (hardening), collaborative carets inside the editor text
  (defer; presence covers the board surface), rich-text library (ADR-0013).

## Specifications

- The contract is the content model: no second JSON shape, no HTML strings; serialise exactly the
  0.4.0 body and derive `plainText` with the contract's rules; validate size limits before save.
- One save = one `updateNoteBody` operation with inverse; use the SDK autosave debounce/flush, do not
  start a parallel timer or a second persistence path.
- contenteditable correctness: preserve selection when the panel/state re-renders, never re-create
  the DOM node on each keystroke, handle `compositionstart/end`, and restore focus after save.
- Paste/drop: plain text only (sanitise), never trust HTML; link hrefs validated with the contract
  allow-list; no `javascript:`/data URLs.
- Panel keyboard: Esc closes, board shortcuts are suppressed while the panel/editor owns focus, and
  the editor keeps its own native text undo (board undo applies to structural operations).
- AD-4: the panel edits the note referenced by the card; it never duplicates notes on open.
- The camera pan must animate without changing the stored view unexpectedly (it is a transient pan;
  the persisted view is updated only by user camera input, L17).
- Design: panel 400 px/12 px gap, serif 24 px title, muted 15 px placeholder, tokens only, layers
  from `layers.ts`.

## Pitfalls

- Re-rendering the editor node on every change moves the caret; use the controller's internal model
  and update only when external content differs.
- Placeholder text leaking into the saved body is a defect; assert it in the round-trip test.
- An IME composition interrupted by a save loses characters; flush on `compositionend`.
- Two autosave paths (panel + board) double-write; the SDK autosave is the only one.
- The camera pan during panel open must not fight the user's own pan; cancel on user input.
- A card whose note was deleted remotely must close the panel or show the missing state, not crash.
- Contract limits (bytes/blocks) must be enforced before sending; a rejected operation must show an
  error, not drop the text.
