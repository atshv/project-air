# P6-07 — Panel and editor: overlay, own editor, note placeholder and title (L04, L06, L09)

## Goal

`packages/editor` gets the own contenteditable editor (contract 0.4.0 structured JSON, inline
marks/links, plain-text extraction, selection preservation, IME-safe; no rich-text library) and
`apps/web` the 400 px right panel overlay (L04, 12 px gap, 180 ms, Esc, no canvas width change,
camera pan when the selected card is hidden), the empty-note focus/placeholder (L06) and the title
field (L09); content is saved as one contract operation with inverse through the SDK autosave path.

**Why:** the panel/editor is the content-editing surface of the product; ADR-0013 keeps the editor
our own code and P6-06 defines its document.

**Satisfies:** D12

## Scope

- `packages/editor/` (framework-agnostic, no React import): DOM editor controller (mount/unmount),
  contract 0.4.0 document model (paragraph/heading/list blocks; bold/italic/code/link marks),
  serialise/deserialise, deterministic `plainText`, selection preservation, IME safety, list
  Enter/Tab, plain-text paste (no HTML), link creation with href validation, accessible textbox
  roles; README/ARCHITECTURE commands and tests.
- `apps/web/` panel overlay (L04): 400 px right panel, 12 px gap, 180 ms motion, Esc closes, canvas
  width never changes, 300 ms camera pan to 24 px left of the panel when the selected card would be
  hidden; opens on selection; panel focus never leaks to board shortcuts.
- `apps/web/` empty note (L06) and title (L09): empty note focuses the editor with the muted 15 px
  placeholder that disappears on the first character and is never saved; title field (serif 24 px)
  validates per contract, Enter focuses the editor, errors from messages.
- `apps/web/` saving: text goes through the SDK autosave as **one `updateNoteBody` operation per
  save** with inverse; title edits are one `updateNote`; no second save path (L05 UI is P6-08).
- `apps/web/` wiring: the selected card resolves its note (AD-4), edits read/write the board
  document through the SDK, a missing note/body falls back to the contract's empty body.
- Tests: editor model round-trip/serialise/parse/plainText, mark/link validation, paste sanitiser,
  placeholder/focus helper, title validation, panel state helper with `node --test`; DOM/engine
  behaviour is P6-09 e2e. `.changes/P6-07-<short-name>.md`.

## Out of scope

- The L05 save-status UI and presence (P6-08), e2e (P6-09), `[[Link]]` suggestion lists and search
  (value stage), image/attachment blocks (hardening), collaborative carets inside the editor text
  (defer; presence covers the board surface), rich-text library (ADR-0013).

## Acceptance

A1 WHEN a card is opened, THEN the panel overlays at 400 px with the 180 ms motion, Esc closes it,
the canvas width never changes, and a card that would be under the panel gets the 300 ms camera pan
to 24 px left of it.
A2 WHEN an empty note opens, THEN the editor is focused with the placeholder that disappears on the
first character and is never saved; typing serialises to the contract 0.4.0 document with a
deterministic plain text, paste stays plain text, and each save produces exactly one
`updateNoteBody` operation with its inverse through the SDK autosave path; the title field validates,
Enter moves to the editor, and edits survive a reload.
A3 WHEN the task is done, THEN `board-check`, `boundaries`, `unit`, `typecheck`, `design-check` and
`language-check` exit 0 with records, the editor package commands/tests are green, and the change
entry exists.

## Specifications

- Contract is the model: one JSON shape, no HTML strings, contract `plainText` rules, size limits
  before save.
- One save = one operation with inverse via the SDK autosave; no parallel timer/path.
- Preservation: never recreate the editor node per keystroke, handle composition events, restore
  focus after save.
- Paste/drop sanitises to plain text; link hrefs use the contract allow-list.
- Panel Esc/shortcut isolation; native text undo stays inside the editor, board undo is structural.
- AD-4: edit the referenced note, never duplicate it.
- Camera pan is transient; the stored view changes only from user camera input (L17).
- Tokens/layers only (panel 400/12 px, serif title, muted placeholder).

## Pitfalls

- Re-rendering the node moves the caret; use the internal model, update only on external change.
- Placeholder must never enter the saved body (round-trip test).
- IME composition interrupted by save loses characters; flush on `compositionend`.
- Two autosave paths double-write; SDK autosave only.
- Camera pan must not fight user input; cancel on it.
- A remotely deleted note closes the panel or shows the missing state.
- Enforce contract limits before sending; a rejected operation shows an error, never drops text.
