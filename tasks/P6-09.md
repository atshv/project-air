# P6-09 — Realtime UI: live changes, presence and save status (L05)

## Goal

The board page shows live remote changes and presence cursors/selections (colour/name from the
server), the L05 save status (Saving … → Saved 2 s → Not saved – retry, clickable), an offline notice
that never loses input, reconnect/resync, and uses the authenticated session clientId — with the
browser-to-sync session handshake wired through the services.

**Why:** L05 is the remaining realtime web order; the stage exit e2e edits with two users and
reloads, and the current board page still uses a placeholder token (P6-04 limit).

**Satisfies:** D12

## Scope

- `services/sync/` + `services/auth/` browser session handshake: the same-origin session cookie
  travels with the WebSocket upgrade; sync validates it through the auth service (forwarded
  `Cookie`, no token in JS), maps it to the user and joins as before. Keep the tokenRef path for
  tests/non-browser clients and the test-mode flag; add a real-socket cookie integration test
  (allowed/denied).
- `apps/web/` sync wiring: SDK `BoardSyncClient` with the session client id and same-origin sync
  URL; hello/welcome/snapshot/catch-up and reconnect via the SDK; connection state
  (connecting/joined/offline/error); remote operations project to the engine.
- `apps/web/` L05 save status from the SDK autosave events: "Saving …", "Saved" for 2 s after the
  server confirmation, "Not saved – retry" (clickable) on failure; offline queue/notice, flush on
  reconnect and on close/navigate (installFlushTriggers), focus never lost, text from messages.
- `apps/web/` presence UI: remote cursors/selection outlines (`remote-cursors` layer), server-derived
  name/colour, throttled SDK presence updates, cleared on leave/reconnect/board switch.
- Edge cases: session expiry shows the L05 retry (no reconnect loop), offline→online resync applies
  exactly the missed updates, board switch closes the old session.
- Tests: sync/auth integration for the cookie handshake; web pure helpers for status mapping,
  presence colour/label mapping, offline/retry state and reconnect state with `node --test`; the
  browser two-user flow is P6-09 e2e. `.changes/P6-08-<short-name>.md`; README/docs/realtime.md
  updates for the handshake and status semantics.

- `services/sync/` production entry fix: the real `node dist/index.js` start must resolve the built crdt module (the dynamic import path does not match the package's build output; tests inject the source adapter) — fix the import so the e2e-started service uses the built CRDT.

## Out of scope

cookie (no token in JS), the client joins and receives live remote operations; a foreign/expired

Saving/Saved or the offline notice honestly, queued edits survive reload/navigation and flush after

names/colours and disappear on leave/reconnect.

## Specifications

- Cookie: HttpOnly, same-origin (Vite proxy in dev); sync validates via auth, logs no cookie;
  authorization stays the platform check; tokenRef is the test/non-browser fallback.
- Status: only the server ack counts as "Saved"; failures keep the value with retry; no focus loss.
- Offline: SDK queue, flush on reconnect/triggers, no duplicate sends after resync.
- Presence: server identity only, clipped cursors, no persistence, cleared on leave/switch.
- Reconnect: bounded backoff, resync from last serverSeq; expiry is terminal with retry.
- No token in browser storage; no direct fetch in `apps/web` outside the SDK.
- Tokens only (status region 40 px, muted/error tones, cursor labels).

## Pitfalls

- Cookie forwarding must only reach the auth service, never arbitrary hosts; log no cookie.
- "Saved" before the ack is a data-loss illusion; drive it from the SDK.
- One client/flush path per board; no parallel dedupe after reconnect.
- Ignore presence from the old board after a switch.
- Missing cursor colour falls back to a token tone, not an invalid value.
- Expiry closes the socket with retry; no auto-retry drain.
