# P6-03 — Boards start page: workspaces, board list and creation over the SDK

## Goal

The start page lists workspaces and their boards through the SDK, creates a first workspace/board
when none exists, creates/renames/deletes boards with confirmation and opens `/boards/:id`; loading,
empty and error states use message files and the SDK is the only data path.

**Why:** the e2e flow login → board list → board needs this page, and it proves the SDK platform
client in the product.

**Satisfies:** D12

## Scope

- `apps/web/` start/boards page: on load, `session.get()` (P6-02) then `workspaces.list()`; pick the
  first workspace (persist a `workspaceId` selection seen by the header), `boards.list(workspaceId)`
  with cursor/limit from the SDK types; a board grid/list with title, visibility and `updatedAt`
  (formatted via `Intl.DateTimeFormat` from the active language), one primary action "New board"
  and per-board actions (open, rename, delete).
- `apps/web/` first-run flow: when the signed-in account has no workspace, show an empty state with
  one action that creates a workspace (`workspaces.create({ name, ownerId })`) and then a board
  (`boards.create(workspaceId, { title, visibility })`); the names come from messages and are
  editable.
- `apps/web/` dialogs: create/rename board (title validation: 1…120 characters, trim, message keys
  for errors), delete confirmation (destructive button, board title shown), all built on the P6-01
  `Dialog`/`Menu`/`Button` components with focus trap, Escape, and `aria-*` from messages.
- `apps/web/` states and navigation: skeleton/loading, empty ("no boards yet"), error with retry
  (typed `ApiError` codes mapped to message keys), disabled actions while a request is in flight;
  opening a board navigates to `/boards/:id` (the page shell from P6-01 until P6-04); the board page
  guard returns to `/boards` when the board is missing/forbidden.
- Helpers/tests: board title validation, sort order (updatedAt descending), date formatting and the
  workspace-selection persistence as pure functions with `node --test`; the SDK calls themselves are
  covered by the SDK's own tests and P6-08's e2e. `.changes/P6-03-<short-name>.md` (area `web`,
  kind `minor`); new message keys in `apps/web/messages/{en,de}.json`.

## Out of scope

- The board canvas/engine (P6-04+), panel/editor (P6-06), realtime UI (P6-07), e2e (P6-08),
  templates/library/search (value stage), sharing/member management (backend stage), board
  thumbnails/images (hardening).

## Specifications

- Data path: `createClient()` from `@project-air/sdk` with the account's credentials and the
  configured base URL; `apps/web` has no service imports and no direct HTTP.
- Error mapping: `ApiError` codes (`unauthorized`, `forbidden`, `not_found`, `validation`,
  `rate_limited`, `unavailable`) to message keys; a 401 sends the user back to `/login`.
- Empty/loading/error states are components with messages, not ad-hoc text; keep focus visible and
  restore it after dialogs close.
- Board titles: trim, non-empty, <= 120 characters; the SDK/contract validates again on the server.
- Dates: `Intl.DateTimeFormat(language, ...)`; no date library.
- Design: token-only styling, layers for overlays, 32/36 px control heights, destructive tone from
  tokens; no new raw values.
- Tests: pure helpers only (`node --test`); no extra DOM test dependency.
- Keep the workspace/boards state in one hook/module (no duplicated fetch on navigation); a simple
  in-memory cache with explicit refresh is enough.

## Pitfalls

- Creating a board in the wrong workspace (no workspace selected) fails with a server 404; resolve
  the workspace before showing the primary action.
- Cursor pagination: `list()` returns `{ items, nextCursor }`; the first page is enough for this
  stage, but do not drop `nextCursor` from the type contract.
- A failed create must not leave the dialog in a stuck "saving" state; always settle status.
- Deleting the last board must show the empty state again, not an error.
- `language-check` rejects German literals in code; all UI strings go to messages.
- Avoid a full page reload after mutations; update local state from the SDK response.
