# P0-19 — Design preview page

## Goal

A runnable design preview page shows tokens, typography, icons, component states and a sample board
at desktop and mobile width, with committed screenshots.

**Why:** the owner wants to see the look and feel after larger milestones instead of waiting for the
end; this is the first visible demo of the design system.

**Satisfies:** D3

## Scope

- `apps/web/preview/` with a static, dependency-free page (`index.html`, `preview.css`, optionally a
  tiny `preview.js`), served locally with `python3 -m http.server` from the repository root.
- The page shows, using only the generated tokens:
  - colour swatches with token names (bg, canvas, surface, card, fg, muted, faint, border,
    border-strong, accent, accent-soft, accent-line, danger, tone-a…e);
  - the typography scale (serif/sans, sizes 28/24/22/15/13/11/12, weights, line height);
  - spacing (4/8/12/16/24/32/48), radii (10/14/20/pill/6 tooltip), shadows and border widths;
  - the ten toolbar icons as a grid (from `packages/ui-kit/icons/`);
  - component states: rest, hover, focus (visible outline), pressed, selected, disabled; one
    example note card, block, zone, connection, side-panel header and toolbar arrangement;
  - a simple sample board composition (zones, note cards, blocks, connections) that shows the
    intended look, clearly labelled as a static preview (no engine, no data).
- Responsive: desktop 1440×900 and mobile 390×844, no horizontal overflow, 4-px spacing only.
- Link the generated stylesheet from `packages/ui-kit/tokens.css` (relative path that works when
  served from the repository root); use only `var(--…)` values, no raw colours, no new tokens.
- Screenshots: serve the page on the slot's `web` port (`.polier-slot`; never a hard-coded port),
  capture `reviews/evidence/P0-19-desktop.png` (1440×900) and
  `reviews/evidence/P0-19-mobile.png` (390×844) with the cached headless Chromium
  (`~/Library/Caches/ms-playwright/chromium_headless_shell-1248/chrome-headless-shell-mac-arm64/chrome-headless-shell`),
  and mention the exact command in the manual log.
- `apps/web/preview/README.md`: how to serve the page locally, what it shows, and that it is a
  static design preview, not the product.

## Out of scope

- Engine, data, routing, framework, build step or dependencies; `apps/web` product code.
- Changes outside `apps/web/preview/` (the screenshots under `reviews/evidence/` are always allowed).
- CI wiring (P0-08, remote stage) and design-check enforcement (P0-13).

## Acceptance

A1 WHEN the preview is opened, THEN it shows the colour, type, spacing, icon and state sections and
a sample board, and uses only `var(--…)` tokens (no hex/rgb/hsl values in the preview files).
A2 WHEN the page is served on the slot web port, THEN HTTP 200 for `/apps/web/preview/`, the layout
has no horizontal overflow at 1440×900 and 390×844, and both screenshots are committed under
`reviews/evidence/`.
A3 WHEN `python3 $POLIER/tools/check.py .` runs, THEN it exits 0; no board, STATUS, tasks or
`reference/` files were changed, and the manual log names the serve/screenshot commands.

## Specifications

- **Files:** `apps/web/preview/index.html`, `apps/web/preview/preview.css`, optionally
  `apps/web/preview/preview.js`, `apps/web/preview/README.md`.
- **Language:** English page text; German example strings stay out of the page for now (no
  translation layer yet); if a German word is shown, use `ss`, never `ß`.
- **Styling:** only CSS custom properties from `packages/ui-kit/tokens.css`; layout in logical
  properties where it matters; no framework, no build, no external fonts or CDNs (offline).
- **Server:** read the port from the worktree's `.polier-slot` (`python3 $POLIER/tools/slot.py show`,
  key `web`); start `python3 -m http.server <port>` in the repository root, verify with
  `curl -s -o /dev/null -w '%{http_code}'`, then stop the server (a process you started).
- **Screenshots:** headless Chromium as named above; put the exact commands in
  `reviews/evidence/P0-19-preview.log`.
- **Commit:** one commit `P0-19: Design preview page` including the page, README, screenshots and
  the log.
- **Gate:** `board-check` only (run it before any `pnpm install`; this task needs none).

## Pitfalls

- Do not invent tokens or colours; a missing value → keep it out and record an `open_question`.
- The preview must not look like a product feature claim: label it "static design preview".
- No external network: no Google Fonts, no CDN, no images; icons come from the repository.
- The screenshot must show the real page, not a mock.
- Keep the page lightweight: a single HTML/CSS pair and no build step.

## Edge cases

- Headless Chromium not found → report the exact attempted path and fall back to another installed
  Chromium/Chrome; do not install a browser.
- The mobiles viewport (>390 px content) must wrap, not scroll horizontally; test both sizes.
- The preview may later be replaced by the web-app stage; keep it isolated in `apps/web/preview/`.
