# P6-15 — Depth-ordered titles and previews in the engine

## Goal

Bound titles, previews and header chrome draw in document depth order, so a front object always
covers the text of an object behind it, on WebGL2 and WebGPU, without breaking the performance
proof.

**Why:** the P4-10 review (finding 1) left bound text in one glyph pass after all objects, so on an
overlapping board a back card's title paints over a front card. The web app will show real titles
from P6-16 on, and the live demo never shows that defect (owner decision 2026-10-29: close the
stage-7 gaps first).

**Satisfies:** D12

## Scope

- `packages/engine/` render order: interleave the text/chrome pass with the object pass by depth
  bands (or per object where the band is small), so text of object N is drawn before objects above
  N; same rule in the WebGL2 and WebGPU backends.
- Native test for the band ordering; a reviewed visual baseline `overlapping-titles` at 1440×900 and
  390×844 for both backends; all older baselines stay 0-diff.
- Performance: `perf` on the engine-core scenario stays within the P4-03 basis + 10 %; record the
  number of extra draw calls per frame for the 10,000-object and 500 cards + 50 zones scenes.
- `docs/engine.md` titles section: remove the depth-order limitation, describe the band rule.
- `.changes/P6-15-<short-name>.md` (area `engine`, kind `patch`).

## Out of scope

- Any other engine behaviour, contract changes (P6-14), `apps/web`.

## Specifications

- Bands follow the document draw order; objects in the same band without overlap keep one batch.
- Header chrome occlusion (P4-10) keeps working.

## Pitfalls

- Per-object switching between the object and glyph programs can explode the draw calls on a full
  board; measure before choosing the band size.
- WebGPU render-pass ordering differs from WebGL2; test both, not one.
