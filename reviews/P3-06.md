## Open question judged

Legacy non-v7 profiles keep a v4 `account_id` after the backfill. **Acceptable for this stage:** none exist (the stage DB was empty before and after the task's tests), the brief explicitly out-of-scopes migrating historical data and asks for a non-destructive backfill only when `account_id` is the identity id, and a remap would have to update `workspaces.owner_account_id`, `workspace_members.account_id` and `boards.owner_account_id` transactionally. The backfill does not create v4 ids or duplicate a mapping; for rows written by the pre-P3-06 code (`ensureProfile` stored `user.accountId`, which was the Kratos identity id) the mapping is truthful. The residual is that such users would still produce v4 `ownerId` values, so it must be documented and remapped before any historical data is imported; it is not a defect for this stage.
