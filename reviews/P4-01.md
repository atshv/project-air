- **A3: fail on the C ABI loader path; pass for the `Document` mutations** — The document side is covered: ids start at 1, are monotonic and never reused after removal or `clear()`; a removed id no longer resolves and another object keeps its id, geometry and relative draw order; a non-finite/overflowing geometry, an unknown/removed id and a full 50,000-object document are rejected without changing version, size or id; the last object can be removed and its slot reused (`engine_core_test.cpp:605-751`); `addBoardContent` rejects 50,001 cards and a NaN card atomically (`:384-421`). ### Round-1 findings

- **Major — failed-load atomicity and the stale-index patch — fixed.** `Document::loadPackedRectangles` (`packages/engine/src/doc.cpp:199-248`) validates the count/null pointer, every rectangle's geometry and both ordinals of the whole packed array before it calls `clear()` at `:236`; a rejected load returns before any mutation, so the document, version (no `++version_`), slot handles and the spatial index are unchanged. `Renderer::loadRectangles` delegates to it (`render_gl.cpp:198-211`) and rebuilds the grid only on success (`:209`). All four incremental ABI mutations call `ensureSpatialCurrent()` before touching the document (`render_gl.cpp:218,248,270,289`; helper `:390-397`; `SpatialIndex::ensureCurrent` `spatial.cpp:126-130`), so `updateSlot`/`removeSlot`/`syncVersion` never stamp a version the grid did not follow. The regression `packedLoadAndSpatialGuard` (`engine_core_test.cpp:1063-1165`) loads 3 valid records, rejects 3-valid+NaN, asserts size/version unchanged, the index still current and the command buffer byte-identical, then adds an object, builds a 4-instance frame and hits all three objects; a second block leaves the index stale by a direct document mutation, calls `ensureCurrent`, checks both candidates come back, then patches a further add and sees 3 candidates. Slot reuse (remove → erase → reuse → insert), capacity (a failed `addObject` does not mutate), and tone/layer clamps (no cell change) were checked and do not leave a stale or half-loaded grid.
- **Minor 1 — handle-lifetime docs — fixed.** `render_gl.h:12-16,37-44` and `engine.ts:44-56` state that `loadRectangles` invalidates every slot handle (even when the new content reuses the same slots) and that a removed slot may be reused. The `Engine.loadRectangles` comment matches the ABI: `#requireOk` throws on 0 and the C path leaves the document and handles unchanged on rejection (`engine.ts:234-243,355-363`).
- **Minor 2 — `doc.h`/`clear()` consistency — fixed.** `clear()` no longer resets `nextInsertionOrder_` (`doc.cpp:104-115`) and `doc.h:62-67` now states that the id and the insertion order are never reset, so both stay unique for the document lifetime; the `clear()` comment (`doc.h:103-106`) agrees. A search for insertion-order statements found no test or doc claiming a reset.
- **Minor 3 — tooling change named — fixed.** `.changes/P4-01-engine-document-with-stable-object-ids-incremental-mutations.md:4` names the `build-wasm.sh` change (`EM_CACHE` default and real path).
