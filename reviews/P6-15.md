## Verdict

Bound titles, previews and header chrome now follow the document draw order. `CommandBuffer` splits
the visible objects into **depth bands** (P6-15), and both backends draw each band's objects and then
that band's header chrome and bound glyphs, so a front object always covers the text of an object
behind it. A frame without bound text keeps the exact P4-03 draw, so the perf proof is untouched.
The reviewed `overlapping-titles` baseline proves the occlusion on WebGL2 and WebGPU at both
viewports, the six gates pass with records and every older reference image stayed 0-diff.

## What was built

- **Band plan (`render.cpp`, `render.h`).** `CommandBuffer::build(..., interleave)` forms maximal
  runs of consecutive draw-order objects in which no later object covers an earlier object's bound
  text boxes (title/preview for cards, header band/rule/title for zones, band/rule/title/preview for
  blocks — the same `objectTextBoxes` the binding draws). The plan is cached per document
  instance/version, formed in document space (camera-independent) and reported through `bands()`
  as instance range plus visible rank range. A board without covered text is one band; an invalid or
  stale index fails closed.
- **WebGL2 (`render_gl.cpp`, `text_gl.cpp`).** The renderer draws each band's instance range with
  the object program, then calls the band's chrome/glyph pass, then continues; the object program,
  VAO and instance buffer are restored per band because the glyph pass switches GL state. The bound
  runs and header chrome are stable-ordered by band inside the text pass and sliced from one glyph
  buffer / one chrome list. Page-owned runs and the chrome above every object (guides, selection,
  drop highlight) draw in the tail.
- **WebGPU (`render_webgpu.cpp`, `render_webgpu.h`).** `FrameText` carries one glyph/chrome slice per
  band plus the global chrome. The frame draws a band's objects, then the band's text/chrome pass
  (load-op `load` after the first), then the next band; queue submission order keeps the interleave
  on the same canvas texture. The two-backend tolerance still holds.
- **Native test (`test/engine_depth_order_test.cpp`).** A covering card starts a new band; uncovered
  cards, zone members, and a full 10,000-object container board keep one band; a card over a zone
  header splits; the split is camera-independent and deterministic; the legacy build is one band with
  byte-identical instances; a document change rebuilds the plan; a stale index fails closed.
- **Visual scene (`apps/engine-playground/main.js`, `run-visual.mjs`).** Page-owned
  `?text=overlapping` gallery (four titled cards, world 1024x576, world (504, 280) at zoom 1) whose
  front card fully covers the title and preview boxes of the card behind it while its own text stays
  on top; two outer cards are the readable control. The scene is additive: no existing scene,
  baseline, tolerance or expectation changed.
- **Docs.** `docs/engine.md` gains the "Depth-ordered text (P6-15)" section and loses the P4-10
  depth-order limitation; `docs/gates/visual-diff.md` lists the new scene and its four reviewed
  baselines in the Baseline history.
