## Findings

| # | Severity | Finding | Evidence | Fix |
| --- | --- | --- | --- | --- |
| 1 | minor | Bound titles/previews are drawn in one glyph pass **after** the object pass, so they are not depth-ordered against higher-layer objects: on an overlapping board a back card's title would overpaint a front card. The titles gallery is deliberately non-overlapping, so the references cannot show it. | `packages/engine/src/text_gl.cpp` (`drawChrome`/`drawGlyphBuffers` after the object pass); `docs/engine.md` "What the spike does not prove yet" discloses the limitation | Depth-sort bound runs by the document draw order (or emit per object in the object pass) in a follow-up task |
| 2 | minor | The delete affordance is invisible at rest (`opacity: 0`) but still `pointer-events: auto`, so a first click/tap in its 28 px corner hits the button and deletes the object while the control is invisible; on touch there is no hover to reveal it first (the `hover: none` rule only changes opacity). | `apps/engine-playground/playground.css` `.object-action`; `main.js` click → `remove()`; no capture covers a touch tap on the corner | `pointer-events: none` unless hovered/selected/visible (or enable pointer events only for `@media (hover: hover)`) |
| 3 | minor | The delete icon is an inline SVG in `main.js` rather than an entry in `packages/ui-kit/icons/` (design rule §5 says icons MUST come from there). `ui-kit` has no delete icon and is outside the P4-10 write scope; the deviation is documented. | `apps/engine-playground/main.js` `DELETE_ICON`; `docs/engine.md` titles-scene chrome bullet | Add a delete icon to `packages/ui-kit/icons/` with its icon test when L09/web-app owns the affordance |

Acceptable for the demo (no message catalogue in the playground) but must move. | `apps/engine-playground/main.js:503-504`; capture record `activeElement.label: "Delete"` | Move the label to the translation files when the affordance enters `apps/web` |
