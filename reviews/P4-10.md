## Verdict

The implementation itself meets A1 and A2: the binding, header geometry, block growth, quiet delete
affordance and zoom-bucket re-rasterisation are correct and genuinely tested, and the visible
reference images demonstrate them. The merged tree also contains the author's follow-up fixes for
the pointer-events hit target, the `P4-10` idle record and the "before build" wording, and those are
verified below.

Two required evidence points are not met:

1. the `perf` (and `visual`) gate records were produced **without the exclusive lock** — both show
   `"exclusive": []`, while the brief requires the perf gate to be exclusive;
2. the two newest gate records (`design-check`, `visual`) were made on commit `bb52df9`, which is
   **not in the merged history** (the task commit was amended), and the committed `board-check`
   predates them, so the final evidence set is not "one current set"; a fresh `check.py` on `main`
   reports both P4-10 records as made on a commit outside `HEAD`'s history.

Both are cheap to fix with a re-run on the final head. The code findings are minors and one
documented follow-up (text depth order).

## Acceptance

- **A1 — titles, geometry, sharp zoom: ✓.** Card titles and zone names are one `ellipsis` run at
  the token title role (`text_15`, `weight_semibold`); zones/blocks carry the 40 px
  `tokens::header_height` band plus a `tokens::border_width` rule, and their content starts at
  `header_height + space_16`; the title box reserves `button_card + space_8` for the quiet control.
  Text is bound only for visible, live, non-tiny objects, in document order, with a 2,048-run budget,
  and never enters the document (`TextBindings` is keyed by `ObjectId`; the document is only read).
  Zoom buckets are 25/50/100/200/400 %, the raster scale is `min(DPR × bucket, 4)` and the atlas is
  rebuilt only in `setCamera`/`resize` when that scale changes (unit test 4/4; capture
  `rasterScale` 1 at 100 %, 2 at 200 %). The reference set contains `text-titles` (100 %) and
  `text-titles-zoom-200` (200 %) on both viewports; the 200 % image is visibly crisp (inspected).
  `engine_binding_tests` genuinely covers the band/rule/inset/title-centring, the ellipsis cut and
  box overflow, the preview clip and the grown block, culling, DPR independence and determinism
  (4/4 native suites pass; `engine_binding_tests` also passes in an independent rebuild).
- **A2 — visual quality: ✓.** Blocks grow via `engine_text_required_height` + `updateGeometry`
  (`grownBlocks: 2` in the capture; the native test shows the grown box shows every wrapped line
  and no inner scroll exists). The delete affordance is DOM chrome in `#overlay`: 28 px `--button-card`
  hit area, 16 px inline stroke SVG from `--icon-card`, invisible at rest with `pointer-events: none`
  (the merged fix; capture `visibleControls: 0`, `invisibleHitTests: 0`, `invisiblePassThrough: true`),
  visible on hover/selection and Tab focus (`activeElement {tag: "button", label: "Delete"}`), no
  character/emoji/native tooltip (`iconCharacters: []`, no `title` attribute). Before/after PNGs are
  committed (desktop; one mobile after), and the pointer-events/hover fixes are evidenced.
- **A3 — gates/evidence: partial / ✗ on "one current set".** `board-check`, `boundaries`, `cpp-unit`,
  `visual`, `design-check` and `perf` all exit 0 with records; the log SHA-256 values match the logs;
  `visual` has 20 captures, every pre-existing baseline is 0 differing pixels and the four new
  `text-titles*` baselines match exactly (0 pixels, 0 channel delta); the Baseline history in
  `docs/gates/visual-diff.md` documents the reviewed addition; before/after PNGs are committed.
  However, the final `visual`/`design-check` records are on the orphaned `bb52df9`, and the
  committed `board-check` predates them (finding 2), so the current set is not clean.
- **A4 — perf/idle: partial / ✗ on "exclusive".** The perf numbers pass: 10,000 objects, p95 0.2 ms
  ≤ 16.7 ms, 0 intervals > 16.7 ms, 2,000 samples, one document load, real Apple M2 GPU (ANGLE
  Metal), and the enforced p50/p95/p99/mean are within basis + 10 % (the 2.5 ms max is the
  documented observation metric, bounded by the 50 ms L01 target, not a regression signal). The
  idle record is now `P4-10-idle-20261027T214827Z.json` (`task: P4-10`), result `pass`, 0 rendered
  frames in all idle windows while the fit/resize render one frame and the benchmark control keeps
  rendering; the harness now takes `--task`. **But** the perf record's `exclusive` list is empty
  (finding 1).
