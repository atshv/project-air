## Acceptance

### A1 — pass

- **Rasterised in the browser from tokens.** `rasterizeTextAtlas`
  (`packages/engine/src/bridge/text-atlas.ts`) composes the CSS font from `engine_text_style` /
  `engine_text_font_family`, which return `tokens::font_sans`, `text_15`/`weight_semibold` (title)
  and `text_13`/`weight_regular` (body) with `line_height` (`packages/engine/src/text.cpp`
  `textStyle`). The bridge holds no typography value; the only literal is the `"white"` coverage-mask
  fill, which the shader replaces with `tokens::fg`.
- **One upload, validated in C++.** `buildTextAtlas` (`src/bridge/engine.ts`) mallocs pixels and
  packed metrics once and calls `engine_text_load_atlas`; `GlyphAtlas::load` validates sides, the
  texture limit, raster scale, byte length, all nine metric fields, ranges, duplicates and one
  placeholder per role before replacing anything; `TextPass::loadAtlas` (`src/text_gl.cpp`) then
  issues one `glTexImage2D`. `engine_text_tests` covers the accepted upload (pixels copied byte for
  byte) and 14 rejections with the previous atlas and generation unchanged.
- **No font file.** The diff adds no binary except the evidence screenshot
  `reviews/evidence/P4-08-text-demo.jpg`; the glyph set comes from the system font stack.
- **Browser check.** `?text=1&view=200,64,2` on the slot-1 playground (Chrome, DPR 2, real WebGL2)
  shows both runs with Latin-1 letters and the placeholder box for U+4E2D;
  `getState().textAtlas` = 1024×1024, raster scale 2, 384 glyphs, `MAX_TEXTURE_SIZE` 16384. The
  first browser run found a real defect — the glyph program failed to link because `u_glyph` had
  `mediump` in the fragment stage and `highp` in the vertex stage; fixed (`uniform highp vec4`) and
  the link log is now part of the error. The gates were re-run after the fix.

### A2 — pass

- **DPR-correct metrics.** Metrics are stored in CSS px (raster px / raster scale);
  `testCssMetricsIndependentOfDpr` compares advances at DPR 1/2/3, and the glyph-buffer test shows
  identical pen steps for a DPR 1 and a DPR 2 atlas. `resize` rebuilds a built atlas when the ratio
  changes (bridge; not exercised in the browser because the pane cannot change its DPR).
- **Texture-limit fallback.** `planAtlas` halves from the DPR down to 1 (not below; a ratio below 1
  is not halved) and fails with a `Status` when the last scale does not fit; tested 3 → 1 at 512 px,
  4 → 2 at 1024 px, failure at 64 px and below one cell, plus invalid input. `wasm-smoke` repeats
  the fallback and the failure in the WebAssembly build.
- **Missing glyphs.** `GlyphAtlas::resolve` falls back to the role's placeholder (tested for CJK,
  emoji, U+FFFD and a Latin-1 letter missing from an ASCII atlas); the bridge draws it as an outlined
  box, never a character (design rule §5). A lone surrogate stays a code unit and draws the box.

## Findings

- **minor (accepted):** the renderer-bound text calls are stubs natively, so the GL upload and draw
  are only covered by the browser check and `wasm-smoke`'s pre-create failure paths; the `visual`
  gate (P4-09) is the first reference-image proof of text.
- **minor (accepted):** the brief's pitfall suggested premultiplied upload and `ONE,
  ONE_MINUS_SRC_ALPHA`; the implementation samples only alpha coverage and blends `SRC_ALPHA,
  ONE_MINUS_SRC_ALPHA` like the grid pass, which makes premultiplication irrelevant. Documented in
  `docs/engine.md`.
- **note:** runs draw above every object (one glyph pass after the object pass); binding text to
  card layers and ellipsis is P4-09/P4-10, as is zoom-bucket re-rasterisation. Text is off unless
  `?text=1`, so the `visual` baselines and perf documents are unchanged.
- **note:** ADR-0009's "Confirmed in P4-02" paragraph still says no glyph atlas exists; `docs/adr/`
  is outside this task's scope, so a later docs task should add a P4-08 confirmation line.
