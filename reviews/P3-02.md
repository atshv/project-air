## Known follow-ups (judged)

- **(a) SECURITY DEFINER owner role.** The migration header (0003:8-12) documents that the helpers are owned by the Compose superuser locally and that production needs a dedicated owner with BYPASSRLS. That is adequate for this stage and not a blocker, but the gate catalogue does not repeat it, and the migration owner is a superuser locally, so `FORCE ROW LEVEL SECURITY` is not exercised by the owner. The hardening stage must introduce a non-superuser table owner and a separate BYPASSRLS helper owner; the helpers return booleans only, so the data-leak surface is limited.
- **(b) `cards.zone_id` has no FK.** Documented at 0002:73-74 and accepted until a zones task; that task must add the FK and decide the delete rule.
- **(c) `docs/gates/postgres.md` not updated.** Recorded as F7; a lead edit because `docs/` is outside the task's `scope_write`.
