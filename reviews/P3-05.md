## Known follow-ups (judged)

- **(a) Stage exit "account via the SDK" (wording gap, not a blocker).** D9 says "a typed SDK script creates account, workspace, board and note"; `packages/sdk/scripts/acceptance.mjs:41-56,80-83` mints account A/B with a raw `fetch` to auth's `POST /test/session`, because the SDK has no account resource. The profile rows are created lazily by the first SDK call (`ensureProfile`), and the script proves the substantive exit criteria: A's resources exist and B's lists are empty / gets are `NOT_FOUND`. The brief itself scopes the account step as "create account A (test session)". I judge the stage exit **evidenced**; document the account step explicitly or add a session-mint helper in a later task if the lead reads D9 literally.
- **(b) Worker note: SDK flow split into `packages/sdk/scripts` — acceptable.** `tools/dev` has `may_import: []` and the orchestrator imports only Node builtins and spawns `packages/sdk/scripts/acceptance.mjs` by path; the SDK-side script lives with the SDK and imports only its own `src`/builtins. This respects the boundaries contract; the `boundaries` gate is exit 0 with 40 pre-existing warnings. No finding.
- **(c) Worker note: `dist/sdk/src/index.js` — F1 minor**, as requested; functional now, fix before `apps/web` imports the package.
- **(d) `api-tests` evidence.** P3-04's `api-tests` record (exit 0, base `adefe92`, hash `f5ea484a…`) is on the base and still covers the stage; P3-05 changes no platform code, so no P3-05 re-run is needed. `rls-tests` is the new P3-05 record. P3-06 (v4/v7 mapping) remains a separate follow-up, as ADR-0008 states.
- **(e) RLS assertion strength.** Removing RLS would make the A/B selects return both rows, cross-workspace updates return rowCount 1 and the no-account counts non-zero, so the suite genuinely guards the second line, not just the `current_account_id()` null path.
- **(f) board-check warnings** (P3-05 context pack ~65k tokens, STATUS length) are pre-existing board/brief issues, not code defects.
