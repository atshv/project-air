## Open questions

- **Release 18–28 px outside settles detached though progress < 1:** accepted. 18 px is the
  midpoint of the 8/28 hysteresis band, so a release is the nearest state of that band; at 20 px
  the visual jump is progress 0.80 → 1.00, and a release at 17 px still docks. No fix requested.
- **Detached items grid-snap on release while cards do not:** accepted as brief-sanctioned — the
  brief's specifications ask for "the same 16 px grid snap as the cards"; the only effect is a
  ≤ 8 px nudge on release. If the owner meant "free" literally, drop the `snap()` in
  `settleZoneItem`; the pointer-following drag is unaffected.
- **Pointer-only zone items:** accepted for this task — the scope asks for pointer drag, and the
  cards' keyboard path is unchanged. The zone items are not focusable, so keyboard/screen-reader
  users cannot detach them; a follow-up could add a keyboard affordance.
- **First drag reparents items into the zone container with equal dock slots / no-JS rendering:**
  accepted. With scripting disabled the items remain in `.demo-zone__card` (not floating, no
  slots): zone card 274 × 274.6 at (583, 687.4), notepad 240 × 88.6 and window 240 × 140 at
  x = 600, window border present, no horizontal overflow, `<noscript>` shown — the static render is
  the P0-27 layout. With JS the first `pointerdown` replaces them with equally sized slots, so no
  layout jump; the dock position is measured from the slot (0.2 px sub-pixel difference on
  re-dock, invisible).
- **150 % zoom, "stay visible":** at 150 % the clamp is to the world, not the visible surface: a
  detached item dragged to the top-left ends at screen x = −134…233 against a surface starting at
  x = 152 (≈ 81 px visible of 367 px). This follows the existing zoom model — card A dragged the
  same way ends at x = −130…134, i.e. fully off-surface. Thresholds are screen pixels
  (preview.log:109-111); no P0-28 regression, but the brief's "stay visible" is not literal.
- **Empty zone:** accepted — the card keeps its measured slot height, which avoids any layout jump;
  it reads as an empty container rather than shrinking, and the brief leaves the empty zone open.
- **Reduced motion / border fade:** the scale and shadow are removed and the settle is immediate,
  but `::before` opacity still follows `--detach-progress` (`0.5` at 50 % in my run). That is a
  direct-manipulation fade, not a time animation, and matches the brief's "no scale/shadow"
  wording; the log's "::before opacity 0 (no border animation)" at preview.log:120 was measured at
  progress 1, so it does not show the border is suppressed.

## Merge concerns

- The only owner-visible defect is F1: after the first drag the photo window loses its 1 px border
  **also when docked/redocked**, and while dragging it lifts without the shadow that the notepad
  gets. The interaction itself (detach, free, redock, edge-less) is correct, so this does not block
  the merge by itself, but it is a visible regression against P0-27 and the photo's animation is
  reduced to the 1.02 scale. The fix is local to preview.css.
- Everything else checked green: edge count/path, cards/zoom/toolbar/switch, gates and hashes,
  scope, masthead/date, locale parity, no overflow at 1440/390 and reduced-motion behaviour.
