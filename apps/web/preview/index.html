01 — Interactive demo

Live connection demo

Two note cards and one connection, plus a preview-only toolbar and a zone whose notepad and photo can be pulled out and docked back. Drag a card with mouse, pen or finger — the whole card is the handle — or focus a card and use the arrow keys (16 px per step, Home resets both). interactive demo — not the engine; no data, no server.

A click without movement (under 4 px) selects the card; the four side-midpoint anchors are invisible geometry and the edge snaps to the nearest pair. Drag the notepad or the photo out of the zone: after about 28 px it detaches and stays free on the canvas, and dragging it back docks it into its slot again. Toolbar, zone and zoom pill are preview-only: a tool click only selects it and changes nothing on the canvas.

02 — Contract

Contract 0.1.0 — the shared language

Everything the engine, the backend and the web exchange is versioned JSON Schema in packages/contracts: board content, its operations with exactly one inverse each, the WebSocket sync protocol and the REST API resources and errors, with valid and invalid fixtures and generated TypeScript and C++. Version 0.1.0 is logical in this stage: the contracts@0.1.0 tag is created by the owner or CI in the remote phase (ADR-0002, ADR-0003). The $id base https://project-air.dev/contracts/0.1.0/ is a placeholder until the domain is decided (Q1).

Schema families and files

  • Board content schemas/*.schema.json The codegen input schemas and the root board-content.schema.json; corpus fixtures/.
  • Sync protocol schemas/sync/sync.schema.json One closed oneOf envelope for the WebSocket messages; corpus fixtures-sync/.
  • REST API schemas/api/*.schema.json Closed envelopes for the four resources (workspace, board, note, card) and one error envelope; corpus fixtures-api/.
  • Gate specimens fixtures-gate/ Two direct Polier specimens copy the canonical board-content fixtures, because the Polier contracts gate only reads valid/*.json and invalid/*.json; a unit test enforces the copies.

A durable ack covers every operation id of its batch (AD-2); presence is ephemeral and carries no operations.

Error codes and message keys

The wire code stays language-neutral; the required messageKey is errors.<camelCase>, so the user text comes from the translation files (AD-8).

  • AUTH_REQUIRED errors.authRequired
  • FORBIDDEN errors.forbidden
  • NOT_FOUND errors.notFound
  • VALIDATION errors.validation
  • CONFLICT errors.conflict
  • RATE_LIMITED errors.rateLimited
  • INTERNAL errors.internal

Fixture proof and codegen

Every fixture in the parity corpus is reduced to one canonical line by test/parity/canonical.ts; test/cpp/parity.cpp reads the same wrappers with generated/contract.h, and the unit suite asserts that the TypeScript and C++ line sets are identical — a tampered line is detected.

codegen.mjs deterministically generated the committed generated/types.ts and generated/contract.h; hand edits fail the codegen gate on a diff, so the types cannot drift from the schemas.

Demo cadence: this overview is kept current in the same task as every contract or preview change, and the live two-note demo above stays permanently (docs/quality.md).

Read the full contract in docs/contracts.md and the decision in ADR-0005 — Contract and versions.

07 — States

Component states

Every interactive element has rest, hover, pressed, keyboard focus and disabled; cards and blocks also have selected. The samples below show each state side by side; the buttons are real buttons, so native hover, press and focus work too.

Focus is a 2 px --accent outline with 2 px offset; pressed adds scale(0.97); disabled is opacity 0.4 without hover.
