01 — Interactive demo

Live connection demo

Two note cards and one connection, plus a preview-only toolbar and a zone whose notepad and photo can be pulled out and docked back. The zone lays its two items side by side or stacked depending on where you drop them, a drag follows the pointer one to one, and a docked item can be reordered inside the zone. When both items are out the empty zone disappears, and dragging the two items together forms a new zone around them. Drag a card with mouse, pen or finger — the whole card is the handle — or focus a card and use the arrow keys (16 px per step, Home resets both). interactive demo — not the engine; no data, no server.

A click without movement (under 4 px) selects the card; the four side-midpoint anchors are invisible geometry and the edge snaps to the nearest pair. Drag the notepad or the photo: it follows the pointer one to one and the zone shows what a release would do — a dashed slot where the item lands, the other item making room, the frame shrinking around the remaining item when you pull one out. Release over the other free item to group both into a new zone (above/below stacks, left/right places side by side); release away from the zone to keep the item free. Nothing is committed before the release, and every settle uses the same calm ease-out. Click the zone name in its header to rename it: Enter keeps the new name, Escape restores the old one, an empty name returns to the default; a zone formed by grouping starts as “New zone”. Drag a zone by its frame or header to move it together with its items. Click any object to select it and drag an edge or a corner of its frame to resize it; Lena and Jonas work on the same board as simulated teammates, each with a cursor, a name and a selection in their colour; a photo dropped into a zone takes the size of the other item. Dragged objects snap to their neighbours (Shift moves freely); Shift-drag on the empty canvas selects several objects; right-click opens the menu, Delete removes, Cmd/Ctrl+Z undoes. When both items are out the empty zone fades away; toolbar, zone and zoom pill are preview-only: a tool click only selects it and changes nothing on the canvas.

02 — Contract

Contract 0.3.0 — the shared language

Everything the engine, the backend and the web exchange is versioned JSON Schema in packages/contracts: board content, its operations with exactly one inverse each, the WebSocket sync protocol and the REST API resources and errors, with valid and invalid fixtures and generated TypeScript and C++. Version 0.3.0 is logical in this stage: the contracts@0.3.0 tag is created by the owner or CI in the remote phase (ADR-0002, ADR-0003). The $id base https://project-air.dev/contracts/0.3.0/ is a placeholder until the domain is decided (Q1).

Schema families and files

  • Board content schemas/*.schema.json The codegen input schemas and the root board-content.schema.json; corpus fixtures/.
  • Sync protocol schemas/sync/sync.schema.json One closed oneOf envelope for the WebSocket messages; corpus fixtures-sync/.
  • REST API schemas/api/*.schema.json Closed envelopes for the four resources (workspace, board, note, card) and one error envelope; corpus fixtures-api/.
  • Containment rule fixtures/containment/ Since 0.2.0 a card or block may name a zone of the same board as its parent (nullable zoneId, no nested zones); the fixtures and test/containment.test.mjs hold the rule, the platform database enforces it.
  • Gate specimens fixtures-gate/ Two direct Polier specimens copy the canonical board-content fixtures, because the Polier contracts gate only reads valid/*.json and invalid/*.json; a unit test enforces the copies.

Operation types

AD-1: every change to board content is one operation with exactly one inverse, and group is ordered and never nested.

New in 0.2.0: reorder moves one card, block or zone to a new fractional z; its inverse carries the previous key (L13, the front of a layer).

Since 0.3.0 the contract version is negotiated once per connection (hello first, welcome answers), a fresh board starts at serverSeq 1 with an empty catch-up from 0, and snapshotRef is <boardId>:<serverSeq>.

A durable ack covers every operation id of its batch (AD-2); presence is ephemeral and carries no operations.

Error codes and message keys

The wire code stays language-neutral; the required messageKey is errors.<camelCase>, so the user text comes from the translation files (AD-8).

  • AUTH_REQUIRED errors.authRequired
  • FORBIDDEN errors.forbidden
  • NOT_FOUND errors.notFound
  • VALIDATION errors.validation
  • CONFLICT errors.conflict
  • RATE_LIMITED errors.rateLimited
  • INTERNAL errors.internal

Version history

  1. 0.1.0 Initial contract: board content, 19 operations with inverses, sync protocol and REST API envelopes.
  2. 0.2.0 Zone parent reference with containment fixtures (no nested zones) and the reorder operation; additive only.
  3. 0.3.0 Pre-realtime sync rules: version negotiated once per connection, fresh-board sequence numbers and the snapshot reference; content unchanged.

Fixture proof and codegen

Every fixture in the parity corpus is reduced to one canonical line by test/parity/canonical.ts; test/cpp/parity.cpp reads the same wrappers with generated/contract.h, and the unit suite asserts that the TypeScript and C++ line sets are identical — a tampered line is detected.

codegen.mjs deterministically generated the committed generated/types.ts and generated/contract.h; hand edits fail the codegen gate on a diff, so the types cannot drift from the schemas.

Demo cadence: this overview is kept current in the same task as every contract or preview change, and the live two-note demo above stays permanently (docs/quality.md).

Read the full contract in docs/contracts.md and the decision in ADR-0005 — Contract and versions.

06 — Motion, interaction and layers

Motion, interaction and layers

Durations, thresholds and the stacking order the canvas and its chrome share. Things move with transform and opacity only, never with springs; under reduced motion every transition is 0 ms (design law §7). Point at a duration to play it.

Durations

  • --motion-hover 120 ms hover and colour, ease
  • --motion-fade 150 ms show and hide: tooltip, menu
  • --motion-panel 180 ms panels, ease-out; transform and opacity only
  • --motion-tooltip 300 ms tooltip delay; instant on keyboard focus
  • --motion-saved 2000 ms how long “Saved” stays

Interaction

  • --drag-threshold 4 px a press that moves less is a click
  • --snap-tolerance 6 px screen distance to a snap line (L07)
  • --click-target 32 px click target with a mouse
  • --click-target-coarse 44 px touch target (pointer: coarse)
  • --header-height 40 px zone and block header (L02)
  • --outline-width / -offset 2 px / 2 px keyboard focus ring
Focus

12 — Design rules

The design law, rule by rule

Every rule of docs/design-rules.md, §0 to §14, in short. MUST means must, NEVER means never; each card names where this page shows the rule at work.

§0 Guiding idea

  • Content first, tool quiet. The person's notes are the brightest thing on the screen; bars, frames and buttons recede.
  • Calm instead of colourful. Dark green-grey, one accent (--accent, sage), otherwise greys.
  • Nothing jumps. No element changes its position, size or text unless the person triggered it.
  • When in doubt: fewer elements, less colour, less motion. Whoever wants to deviate asks first and does not build.

Shown in: the whole page

§1 Working rules

  • MUST read AGENTS.md, ARCHITECTURE.md, the design law, the own catalogue entry and its listed files before the first line of code.
  • MUST implement exactly one catalogue entry per task — nothing improved on the side.
  • MUST tick every acceptance checkbox individually (✓ / ✗ + one sentence).
  • MUST store before/after screenshots at 1440×900 and 390×844 under reviews/evidence/.
  • MUST work in the task's worktree, take ports and names only from .polier-slot, run every gate through gate.py and commit its records.
  • MUST keep lint, typecheck and unit checks green and run the named e2e specs.
  • NEVER a new dependency, NEVER change or delete existing tests, NEVER touch files outside the entry's list — ask instead.
  • NEVER guess: unclear goes to open_questions. NEVER deliver TODOs, placeholders or commented-out code.

Shown in: the task board

§2 Colours

  • MUST use only tokens from packages/ui-kit/tokens.json — CSS custom properties on the web, the generated header in the engine.
  • NEVER new hex, rgb or rgba values in components; a missing tone is a question, new tokens need approval.
  • Each purpose has one token: --bg, --canvas, --surface, --card, --fg, --muted, --border, --border-strong, --faint, --accent…, --danger.
  • --tone-a … --tone-e only for zones, palettes, edges and person colours.
  • Accent sparingly: at most one filled accent button per screen; otherwise accent only for selection, focus and snap lines.

Shown in: 03 — Colour

§3 Spacing, sizes, radii

  • 4 px grid: spacing only 4, 8, 12, 16, 24, 32, 48 px — NEVER 5, 7, 10, 13 …
  • Canvas grid 16 px for snapping, sizes and positions.
  • Click targets at least 32 × 32 px with a mouse, 44 × 44 px on coarse pointers.
  • Note card --radius-md (14), block and zone --radius-lg (20), icon button and field --radius-sm (10), text button outside the canvas --radius-pill.
  • NEVER pill buttons inside cards or blocks — there an icon button or a --muted text link.
  • NEVER shadows other than --card-shadow and --shadow.

Shown in: 05 — Space

§4 Type

  • Board, panel and empty-state titles in --font-serif 28 / 24 / 22 px; card and block titles 15 px semibold; body 13 px at 1.4.
  • Type label 11 px uppercase +0.1em in --accent; status and hints 12 px --muted; tooltip 12 px medium.
  • NEVER text below 11 px. NEVER more than two weights in one card.
  • Long titles: one line with an ellipsis, the full title in the tooltip — NEVER clipped text without an ellipsis.

Shown in: 04 — Typography

§5 Icons

  • MUST come from packages/ui-kit/icons/: own SVGs, 24 grid, stroke 1.6, currentColor, round caps — the same files for web and engine.
  • 20 px icon in a 36 px bar button, 16 px icon in a 28 px card button.
  • NEVER emoji, Unicode characters as icons (×, ✓, →) or icon libraries.
  • Icon buttons MUST have aria-label from the translation files and data-label for the tooltip — NEVER the native title.

Shown in: 07 — Icons

§6 States

  • Every interactive element — engine objects included — has rest, hover, pressed, focus, selected, dragged, disabled, saving, saved and error.
  • Focus: 2 px --accent outline, 2 px offset — NEVER removed. Pressed: hover plus scale(0.97).
  • Selected card or block: 1.5 px --accent border with a 3 px --accent-soft ring. Being dragged: --shadow, opacity 1 — NEVER semi-transparent.
  • Disabled: opacity 0.4, no hover. Saving / saved: 12 px --muted in a fixed-height status slot, “saved” fades after 2 s; errors stay in --danger and keep the input.
  • Done checklist entry: text --muted, tick in --accent — NEVER struck through.
  • Controls inside cards and blocks are invisible at rest and appear on hover, focus within or selection; they stay reachable by keyboard and show on touch when selected.

Shown in: 08 — States

§7 Motion

  • Hover and colour 120 ms ease; show and hide 150 ms; panel 180 ms ease-out, only transform and opacity.
  • Tooltips after 300 ms of dwell, immediately on keyboard focus.
  • NEVER bounce, springs, wobble, confetti or animated numbers.
  • NEVER animate layout properties (width, height, top, left, margin).
  • Under prefers-reduced-motion: reduce every transition is 0 ms.

Shown in: 06 — Motion

§8 Layers

  • From the bottom up — 1 canvas background, 2 edges, 3 zones, 4 blocks, 5 note cards, 6 dragged or selected, 7 snap guides and selection frame, 7a remote cursors, 8 canvas chrome, 9 side panel, 10 context menu and tooltip, 11 dialogs and toasts.
  • The same order is the engine's render order and the DOM's z-order.
  • Edges lie below every object, zones included: a line never crosses a zone's surface or title (ADR-0013).
  • NEVER a z-index above 10 without an entry in packages/ui-kit/layers.ts.

Shown in: 06 — Layers

§9 Canvas chrome

  • Toolbar top centre, zoom control bottom left, save and error hint bottom centre — all floating, 12 px from the edge.
  • Side panel on the right, overlapping the canvas, 400 px wide, 12 px from the edge.
  • NEVER more floating elements; NEVER rows of buttons above the canvas.
  • “Show all” keeps at least 64 px free at the top; the zoom control is always fully visible.

Shown in: 10 — Canvas chrome

§10 Texts

  • MUST come from translation files with English keys, German first, in the informal address.
  • Short: a button ≤ 2 words, a tooltip ≤ 3 words, an error ≤ 1 sentence plus what the person can do.
  • NEVER exclamation marks, “Ups” or technical terms (node, block ID, payload).
  • Terms as in the German glossary, NEVER two words for the same thing; German always uses “ss”.

Shown in: the DE/EN switch

§11 Acceptance of every UI entry

  • No colour value outside the tokens — the design-check gate rejects raw hex, rgb, rgba and hsl values.
  • All spacing from the 4 px series; every §6 state present and reachable by keyboard.
  • No text clipped without an ellipsis and none below 11 px; nothing jumps on hover, save, open or close.
  • At 390 px width nothing overflows and everything is operable; before/after screenshots are in reviews/evidence/.

Shown in: the gates

§12 Realtime cursors and selection

  • Other people's cursors: a 16 px cursor with a 12 px name label on a surface in the person's colour (--tone-a … --tone-e).
  • After 5 s without movement a remote cursor fades to opacity 0.4.
  • Another person's selection is a 1.5 px frame in their colour without a ring; the own selection follows §6.

Shown in: 01 — Interactive demo (Lena, Jonas)

§13 Engine

  • No design numbers in C++ outside the generated tokens.h: radii, borders, shadows and the 4 px drag, 6 px snap, 16 px grid and 40 px header thresholds are tokens.
  • The engine reads every design value from tokens.json through the header and never keeps its own copy.

Shown in: 02 — Contract

§14 Layout for translation

  • The layout tolerates +40 % text length.
  • Only logical CSS directions (margin-inline-start, inset-inline-start, …).
  • The engine shows no text of its own; object content is the only text it draws.

Shown in: the DE/EN switch
